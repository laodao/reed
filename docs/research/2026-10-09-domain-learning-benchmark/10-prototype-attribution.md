# 原型元素出处标注：哪些来自 Gauth / NotebookLM

> 日期：2026-10-10
> 用户问题：*"哪些是从 gauth 和 notebooklm 借鉴的"*
> 用途：把 v2 原型里的每一处设计**追溯到具体来源**，并诚实标出**哪些是自研、哪些不是外部借鉴**。避免"看起来像借鉴"的模糊表述。

---

## 〇、先厘清一个关键前提：这两家的哲学是对立的

不理解这一点，就会把借鉴说混：

| | **NotebookLM** | **Gauth** |
| --- | --- | --- |
| 知识组织单位 | 笔记本 = **源集合** | 一道题 / 一个知识点 |
| 是否预规划结构 | **从不**（Mind Map 是导入后的即时衍生品） | 不涉及（单点解决） |
| 有掌握度吗 | ❌ 无 | ✅ 有（错题/报告） |
| 有 SRS 吗 | ❌ 无（**学习闭环到"出题"为止**） | ✅ 有（推送复习） |
| 防御靠什么 | 引用锚点 + 离源拒绝 | 题库规模 + 品牌 |
| 一句话 | **以源为中心** | **以单体为中心，追求零摩擦** |

**我们的模块是以"图"为中心的**——两者都不是我们的直接模板。所以借鉴必然是**拆件的**（拿机制，不拿哲学）。

这也解释了为什么 02 号档明确警示：

> "它最不能学的是'图不可编辑'（被用户骂两年）和'测完即弃'（无掌握度/SRS）——**后者正是我们的差异化护城河，别被它的一键出题带偏成工具化**。"

## 二、来自 Gauth 的（3 项，其中 2 项是核心）

### G-1：答不上要显性承认 + 给动作 ★核心

**Gauth 原做法**：AI 解不出或学生怀疑答案时，一键转**真人导师**（7×24，带语音+共享白板）。它的本质是——**承认 AI 有边界，而不是假装没有**。

**我们原型**：虚线卡片 "我暂时答不上——「72 法则」在当前讲义里没有对应内容" + 两按钮「就此补研究」「我来补充」。

**诚实说明**：我们**没有照搬**"转真人"（07 号档明确列为"不建议做"：字节级体量才养得起）。借鉴的是**态度**——把失败显性化并转成任务。

### G-2：测量自动回流（复习闭环） ★核心

**Gauth 原做法**：每次解题自动生成错题记录与学习报告，按答题类型推送相关知识点复习。**搜题从"即时行为"变成"学习数据入口"**。

**我们原型**：底部复习条 + "答对才算完成"。

**诚实说明**：这条 07 号档自己也标注了——"**与其说是借鉴 Gauth，不如说是 Gauth 印证了 T0 优先级**"。真实情况是：我们早就有 `mastery_log`、`self_test` 声明，只是没接线。Gauth 的价值是**证明这不是锦上添花，而是 $11.99/月产品的标配**。

### G-3：对话嵌入 + 多解法（部分借鉴）

**Gauth 原做法**：答案界面内嵌对话框，可问"为什么这一步这样算"；几何题同时给代数法与图形法。

**我们原型**：讲义内嵌交互 + 引证回跳。

**诚实说明**：**这部分借鉴得最不纯**。Gauth 是**开放式追问**（想到什么问什么），我们做的是**结构化动手**（预测/探索/排序）。真正的"区级就这段追问"（07 号档借鉴 3 的第 1 条）**原型里没做**——那是右栏追问的定位，不是讲义内嵌。

## 三、来自 NotebookLM 的（3 项已做 + 2 项未做）

### N-1：引用锚点 → 原文高亮（做得最纯的一处）

**NotebookLM 原做法**：所有回答/产出物约束在用户给的源上，**回答带可点击原文引用锚点**。

**我们原型**：引证行 "📎 引证：本讲义「原理」区 · 回看原文" → 点击平滑滚动 + 高亮闪烁。

**为什么做**：02 号档原话——"对抗幻觉批评、建立信任的**最便宜手段**"。成本极低（锚点跳转），信任收益高。

### N-2：知识点 = 提问坐标系

**NotebookLM 原做法**：Mind Map 是**导航器 + 提问入口**，点节点即在该子图内接地提问；"图不是要维护的文档，而是提问的坐标系"。

**我们原型**：点左栏节点 → 切换中栏讲义 + 滚到顶部。

**诚实说明**：**只做了一半**。NotebookLM 的精髓是"点节点 = 在该节点+前置闭包内提问"，原型里点击只是切换视图。完整实现需要把 tutor 会话上下文自动限定到该子图。

### N-3：以源为中心 + 以图为中心的结合（理念借鉴）

**NotebookLM**：以源为中心（用户喂料优先）。
**我们**：以图为中心（概念图是骨架）。

**07 号档的判断**（原话）：

> "Gauth 的 Study Converter 是全局的；我们可以做得更准——因为讲义本身是挂在概念上的，**素材天然有落点**。这是'以源为中心'（NotebookLM）与'以图为中心'（我们）**真正的结合点**。"

**原型状态**：❌ **未做**。这只是理念层面的记录，喂料四入口在原型里没有体现。

### N-4 / N-5：未做的两项

| 项 | NotebookLM 做法 | 原型状态 |
| --- | --- | --- |
| 一键多文体 | Reports 5 模板 + 自定义格式沉淀 | ❌ 未做（对应 08 号档"讲义多文体"，属 T1） |
| 精选模板库 | Featured notebooks / OpenStax 策展源 | ❌ 未做（对应 07 号档 G6） |

## 四、既不是 Gauth 也不是 NotebookLM 的（避免张冠李戴）

| 元素 | 真实出处 |
| --- | --- |
| **三种交互（预测/探索/排序）的组织方式** | **自研**（09 号档方案）。预测-验证源自认知心理学"信息缺口理论"；参数探索对标 **Brilliant**（05 号档 A4："每课都是可视化交互问题"）；排序属通用题型 |
| **streak / 连续学习** | **Duolingo**（05 号档 C11）。且我们遵循其"**宽恕优先**"原则（freeze 组 21 天留存是未用组 4.5 倍） |
| **掌握度四态** | **我们本就有**（`untouched\|learning\|mastered\|review`，`domain-learning.types.ts:57`）。方向上参考 **Khan Academy**（可降级掌握度），但原型未升级为数值 rating |
| **"剩余时间"进度语义** | **自研**（08 号档思路 3） |
| **底部复习条的常驻形态** | **自研**（借鉴的动力是行业数据："45% 用户只用最低级功能，新能力必须做进默认路径"，`06:142`） |
| **三栏 + 暗色体系** | **自研**（对齐现有 `DomainLearningSpace.vue`） |

## 五、一句话总结

> **核心交互变化里，Gauth 给了 2 条（答不上要承认、测量要回流），NotebookLM 给了 1 条（引证回跳）——但都不是照搬，而是"拿态度、换实现"。**
>
> - **Gauth**：拿"承认边界"和"数据回流"的态度；**不拿**真人导师（养不起）、不拿付费墙
> - **NotebookLM**：拿"引用锚点"和"图即导航器"的机制；**不拿**它的哲学（我们不放弃掌握度与 SRS——那是我们的护城河）
> - **其余大部分是自研**：三种交互的组织、streak 落地、进度语义、视觉体系

**最该记住的一条**：02 号档的警告——**别被 NotebookLM 的"一键出题"带偏成工具化**。它测完即弃、无掌握度，这恰恰是我们相对它最大的差异化。所以对 NotebookLM 是**拆件借鉴**，不是路径跟随。
