## 原文摘录（保留原文不翻译）

> **Abstract (节选)**: Voyager consists of three key components: 1) an automatic curriculum that maximizes exploration, 2) an ever-growing skill library of executable code for storing and retrieving complex behaviors, and 3) a new iterative prompting mechanism that incorporates environment feedback, execution errors, and self-verification for program improvement.

技能即代码：

> Inspired by the generality, interpretability, and universality of programs, we represent each skill with executable code that scaffolds temporally extended actions for completing a specific task proposed by the automatic curriculum.

入库与索引（描述嵌入作 key，程序作 value）：

> Each time GPT-4 generates and verifies a new skill, we add it to the skill library, represented by a vector database. The key is the embedding vector of the program description (generated by GPT-3.5), while the value is the program itself.

> We iteratively refine the program through a novel iterative prompting mechanism, incorporate it into the skill library as a new skill, and index it by the embedding of its description. For skill retrieval, we query the skill library with the embedding of self-generated task plans and environment feedback. By continuously expanding and refining the skill library, Voyager can learn, adapt, and excel in a wide spectrum of tasks, consistently pushing the boundaries of its capabilities in the open world.

验证后才入库 + 复合技能：

> ...(3) repeats the process until a self-verification module confirms the task completion, at which point we commit the program to the skill library (e.g., craftStoneShovel() and combatZombieWithSword()) and query the automatic curriculum for the next milestone.

> Complex skills can be synthesized by composing simpler programs, which compounds Voyager's capabilities rapidly over time and alleviates catastrophic forgetting in other continual learning methods.

生成技能时的关键提示词约束：

> The input prompt to GPT-4 consists of the following components: (1) Guidelines for code generation, such as "Your function will be reused for building more complex functions. Therefore, you should make it generic and reusable."...

效果：

> It obtains 3.3x more unique items, travels 2.3x longer distances, and unlocks key tech tree milestones up to 15.3x faster than prior SOTA. Voyager is able to utilize the learned skill library in a new Minecraft world to solve novel tasks from scratch, while other techniques struggle to generalize.

## 核心机制拆解（中文）

- **数据模型**: 向量数据库——key = 技能描述（自然语言）的嵌入，value = 可执行程序（代码）。技能是自足函数（craftStoneShovel()），天然可组合成复合技能。
- **流程**: 自动课程出题 → GPT-4 生成代码（提示中带"要通用可复用"的约束 + 相关旧技能做 fewshot）→ 执行拿环境反馈/报错 → 迭代精修 → 自验证通过才入库 → 下一次出题。
- **触发时机**: 技能入库 = 任务完成的瞬间（验证通过是硬门槛）；检索 = 每个新任务规划时（用任务计划+环境反馈的嵌入查询 top-5）。
- **成本**: 一次技能 = 多轮生成-执行-修错循环；但技能一旦入库即可零成本复用，复合技能的边际成本递减。

## 证据与局限

- Minecraft 三个量化指标大幅超 AutoGPT 类基线；新世界零样本迁移证明技能的泛化性。
- 局限：① 依赖可执行验证（代码跑得对不对很明确），无验证器的领域（写作）不能直接搬；② 技能库无淘汰/合并机制，只增不减；③ 自验证模块本身也是 LLM，可能误判。
- 但其"procedural memory = 代码资产"的思想直接启发了 2025 年的 Agent Skills（Anthropic 官方博客将 Skills 定义为"instructions, scripts, and resources"的文件夹，见另条目）与 CoALA 框架中"updating agent code"的学习类别。

## 对我们的适用性

1. **"描述嵌入作 key、制品作 value"是我们技能资产的正确索引结构**: 无论沉淀的是 prompt 模板、写作工作流还是工具宏，检索入口永远是"用任务/计划的嵌入查技能描述"——技能本体只在命中后才加载。这比把技能全文塞进知识库做 RAG 干净得多。
2. **验证门槛决定入库资格**: Voyager 只在 self-verification 通过后入库。我们没有客观验证器，等价物是"用户采纳/审批通过"——即技能资产只能从被验证过的成功轨迹中沉淀，不能从任意轨迹自动生成。这给"何时提炼"一个清晰答案：验证信号出现时。
3. **"要写成通用可复用的"这句提示词约束是免费的杠杆**: 我们从轨迹沉淀工作流/方法论文本时，同样应在提炼 prompt 里显式要求"去情境化、参数化、可复用"，否则条目会绑定在具体章节上无法迁移。
4. **复合技能 = 能力复利**: 简单技能组合出复杂技能是"知识库变大脑"的最直接证据——我们的写作技能（如"人物出场三板斧"）应支持引用/组合已有技能，形成技能间依赖图，而不是扁平列表。
