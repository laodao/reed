# FActScore：原子事实分解 + 逐条核验的事实性评测范式（claim verification 奠基）

- 链接：https://arxiv.org/abs/2305.14251（2023-05-23，Sewon Min, Kalpesh Krishna, Xinxi Lyu, Mike Lewis, Wen-tau Yih — UW/Meta；EMNLP 2023 杰出论文）
- 时间：2023-05
- 来源：arXiv API 原文抓取

## 原文摘录

**论文摘要：**

> Evaluating the factuality of long-form text generated by large language models (LMs) is non-trivial because (1) generations often contain a mixture of supported and unsupported pieces of information, making binary judgments of quality inadequate, and (2) human evaluation is time-consuming and costly. In this paper, we introduce FACTSCORE, a new evaluation that breaks a generation into a series of atomic facts and computes the percentage of atomic facts supported by a reliable knowledge source. We conduct an extensive human evaluation to obtain FACTSCOREs of people biographies generated by several state-of-the-art commercial LMs ... and report new analysis demonstrating the need for such a fine-grained score (e.g., ChatGPT only achieves 58%). Since human evaluation is costly, we also introduce an automated model that estimates FACTSCORE using retrieval and a strong language model, with less than a 2% error rate.

## 核心机制拆解（中文）

**两步范式（已成行业标配）：**
1. **分解**：长文本 → 原子事实列表（in-context few-shot 分解，要求每条 atomic、自包含）；
2. **核验**：每条原子事实独立做"检索 + 相关片段判断"（非二元整文判断），得分 = 被支持原子事实的百分比。

**为什么重要：** 它把"这段话准不准"变成"这 N 条事实各对不对"——细粒度支持混合判断（一半对一半错可量化）；自动化版本与人评误差 <2%，证明 **原子事实+检索+LLM 判定** 的核验管线生产可用。

**对知识库的意义：** 这正是"事实库"的运行时形态——入库时反向使用（从文档抽原子事实），生成时正向使用（把 AI 产出分解为原子事实、逐条对照库内事实打分）。

## 证据与局限

- 证据：EMNLP 2023 杰出论文；`pip install factscore`；自动化与人评 <2% 误差；被后续（包括 RAGAS、SAFE/LongFact 等 2024-25 事实性评测）普遍继承。
- 局限：核验依赖"可靠知识源"（其用 Wikipedia），对私有/创作类语料需自建源；分解与判定仍用 LLM（成本与一致性敏感）；原子事实粒度无客观标准（论文靠 few-shot 锚定）。

## 对我们的适用性

1. **FActScore 管线可整体反向用于我们的"入库提炼"**：文档 → 原子事实（同 Dense X 命题粒度）→ 每条挂来源与支持状态——一步得到"事实库"的填充流程，且分解 prompt（few-shot 原子化）可以直接借鉴其开源实现。
2. **正向用途即创作质检**：AI 生成草稿的"设定一致性检查"= 把草稿原子化、逐条查我们的时序图谱（按章节有效区间过滤）→ 输出"第 X 章后此事实已变更"的精确报告——这是我们"矛盾扫描"资产的产品化出口，FActScore 证明了该形态的用户价值（事实性评分）。
3. <2% 误差说明自动核验可信到能进产品回路（不是只做离线评测）。
4. 局限应对：创作场景"可靠源"就是用户自己的图谱（以书内一致性为真值），比开放域更可控——反而更适合我们。
