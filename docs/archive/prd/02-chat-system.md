# 对话系统

## 1. 功能概述

对话系统是产品的核心功能，用户可以与 AI 进行多轮对话交流。

## 2. 功能需求

### 2.1 对话管理

#### FR-CHAT-001 创建新对话

**需求描述**：用户可以创建新的对话

**前置条件**：
- 至少配置了一个可用的 AI 提供商

**操作流程**：
1. 点击侧边栏的"新建对话"按钮
2. 系统创建新对话，自动选择默认提供商和模型
3. 如果当前选中了某个助手角色，新对话关联该角色
4. 进入对话界面，光标聚焦到输入框

**界面要求**：
- 新对话默认标题为"新对话"
- 发送第一条消息后，自动以消息内容前 20 字符作为标题

---

#### FR-CHAT-002 删除对话

**需求描述**：用户可以删除不再需要的对话

**操作流程**：
1. 在话题列表中，点击对话右侧的删除按钮
2. 弹出确认对话框："确定要删除这个对话吗？此操作不可恢复。"
3. 用户点击"删除"确认
4. 系统删除对话及其所有消息

**界面要求**：
- 删除按钮在鼠标悬停时显示
- 确认对话框使用警告样式

---

#### FR-CHAT-003 重命名对话

**需求描述**：用户可以修改对话标题

**操作流程**：
1. 在话题列表中，双击对话标题
2. 标题变为可编辑状态
3. 用户输入新标题，按 Enter 确认
4. 系统保存新标题

**界面要求**：
- 编辑状态下显示输入框
- 支持 Esc 取消编辑

---

#### FR-CHAT-004 按角色筛选对话

**需求描述**：用户可以按助手类型筛选对话列表

**操作流程**：
1. 在侧边栏选择一个助手
2. 话题列表自动切换，只显示该助手相关的对话
3. 选择"默认助手"时，显示未关联角色的对话

**界面要求**：
- 侧边栏分两个 Tab：助手 / 话题
- 选择助手后自动切换到话题 Tab

---

### 2.2 消息交互

#### FR-CHAT-005 发送消息

**需求描述**：用户可以发送文本消息给 AI

**操作流程**：
1. 在输入框输入文本内容
2. 点击发送按钮或按 Enter 键
3. 用户消息显示在对话区域
4. AI 开始流式回复，内容实时显示

**界面要求**：
- 输入框支持多行，Shift+Enter 换行
- 发送后清空输入框
- AI 回复时显示加载动画
- 支持 Markdown 格式渲染

**业务规则**：
- 空消息不允许发送
- 发送时如果没有可用模型，提示用户配置提供商
- 正在生成时禁止发送新消息

---

#### FR-CHAT-006 流式显示回复

**需求描述**：AI 回复以流式方式实时显示

**操作流程**：
1. 用户发送消息
2. AI 回复区域出现，显示加载状态
3. 回复内容逐字显示，实时更新
4. 回复完成后，显示完整内容

**界面要求**：
- 流式输出时显示打字动画
- 代码块实时渲染，带语法高亮
- 内容区域自动滚动到底部（用户未手动滚动时）

---

#### FR-CHAT-007 停止生成

**需求描述**：用户可以中断 AI 的回复生成

**操作流程**：
1. AI 正在生成回复时，发送按钮变为"停止"按钮
2. 用户点击停止按钮
3. AI 停止生成，保留已生成的内容

**界面要求**：
- 停止按钮使用醒目颜色
- 停止后显示"已停止"标记

---

#### FR-CHAT-008 编辑消息

**需求描述**：用户可以编辑已发送的消息

**操作流程**：
1. 鼠标悬停在用户消息上，显示操作按钮
2. 点击"编辑"按钮
3. 消息内容变为可编辑状态
4. 用户修改内容，点击"保存"
5. 系统更新消息内容

**界面要求**：
- 编辑状态下显示输入框和保存/取消按钮
- 保存后消息显示"已编辑"标记

---

#### FR-CHAT-009 删除消息

**需求描述**：用户可以删除单条消息

**操作流程**：
1. 鼠标悬停在消息上，显示操作按钮
2. 点击"删除"按钮
3. 弹出确认对话框
4. 用户确认后删除消息

**界面要求**：
- 删除用户消息时，对应的 AI 回复也一并删除
- 删除后消息序号重新排列

---

#### FR-CHAT-010 重新生成

**需求描述**：用户可以让 AI 重新生成回复

**操作流程**：
1. 鼠标悬停在 AI 消息上，显示操作按钮
2. 点击"重新生成"按钮
3. 系统以相同的上下文重新请求 AI
4. 新的回复替换原回复

**界面要求**：
- 重新生成时显示加载状态
- 支持选择不同的模型重新生成

---

#### FR-CHAT-011 换模型重答

**需求描述**：用户可以选择其他模型重新回答

**操作流程**：
1. 点击 AI 消息的"重新生成"按钮
2. 在弹出菜单中选择"换模型重答"
3. 显示模型选择下拉框
4. 用户选择新模型
5. 使用新模型重新生成回复

**界面要求**：
- 下拉框显示所有可用的对话模型
- 按提供商分组显示
- 显示模型能力标签（如支持联网、支持深度思考）

---

### 2.3 高级功能

#### FR-CHAT-012 添加附件

**需求描述**：用户可以在消息中添加图片附件

**操作流程**：
1. 点击输入框旁的附件按钮
2. 选择本地图片文件
3. 图片预览显示在输入框上方
4. 发送消息时，图片一同发送

**界面要求**：
- 支持拖拽上传
- 显示图片缩略图和文件名
- 支持删除已添加的附件

**业务规则**：
- 仅支持图片格式（jpg, png, gif, webp）
- 单个文件不超过 10MB
- 当前模型不支持图片时提示用户

---

#### FR-CHAT-013 联网搜索

**需求描述**：支持联网搜索的模型可以搜索网络信息

**操作流程**：
1. 在输入区域开启"联网搜索"开关
2. 选择搜索引擎（百度 / Bing / Google）
3. 发送消息
4. AI 在回答前先搜索相关内容
5. 搜索结果和回答一同显示

**界面要求**：
- 开关仅在模型支持时可用
- 显示搜索来源链接

---

#### FR-CHAT-014 深度思考

**需求描述**：支持思维链的模型可以展示思考过程

**操作流程**：
1. 在输入区域开启"深度思考"开关
2. 发送消息
3. AI 先展示思考过程
4. 思考完成后再给出正式回答

**界面要求**：
- 思考过程可折叠显示
- 使用不同的视觉样式区分思考和回答
- 开关仅在模型支持时可用

---

#### FR-CHAT-015 清空对话

**需求描述**：用户可以清空当前对话的所有消息

**操作流程**：
1. 点击对话标题栏的"清空消息"按钮
2. 弹出确认对话框
3. 用户确认后清空所有消息

**界面要求**：
- 确认对话框使用警告样式
- 清空后对话保留，消息数为 0

---

#### FR-CHAT-016 切换模型

**需求描述**：用户可以在对话中切换使用的模型

**操作流程**：
1. 点击对话标题栏的模型选择器
2. 显示所有可用模型的下拉列表
3. 选择新模型
4. 后续消息使用新模型

**界面要求**：
- 显示当前使用的模型名称
- 下拉列表按提供商分组
- 显示模型能力标签

---

### 2.4 上下文管理

#### FR-CHAT-017 上下文窗口配置

**需求描述**：用户可以配置对话的上下文窗口大小

**操作流程**：
1. 在对话设置中配置上下文窗口
2. 设置最大 Token 数
3. 选择截断策略（从旧到新 / 智能摘要）

**界面要求**：
- 提供预设选项：4K / 8K / 16K / 32K
- 显示当前对话的 Token 使用情况

---

## 4. 交互规范

### 4.1 消息操作

| 操作 | 触发方式 | 说明 |
|------|----------|------|
| 编辑 | 悬停显示按钮 | 仅用户消息可编辑 |
| 删除 | 悬停显示按钮 | 弹出确认框 |
| 复制 | 悬停显示按钮 | 复制纯文本 |
| 重新生成 | 悬停显示按钮 | 仅 AI 消息可用 |
| 换模型重答 | 重新生成下拉菜单 | 显示模型列表 |

### 4.2 快捷键

| 快捷键 | 功能 |
|--------|------|
| Enter | 发送消息 |
| Shift + Enter | 输入框换行 |
| Esc | 取消编辑 / 关闭对话框 |

### 4.3 状态反馈

| 状态 | 反馈方式 |
|------|----------|
| 发送中 | 发送按钮变为加载动画 |
| 生成中 | 打字动画 + 流式输出 |
| 生成完成 | 滚动到底部 + Token 统计 |
| 生成失败 | 错误提示 + 重试按钮 |
| 网络错误 | 红色错误提示 |

## 5. 边界情况

### 5.1 无可用提供商

**场景**：用户首次使用，未配置任何提供商

**处理**：
- 显示引导页面，提示用户添加提供商
- 提供"添加提供商"按钮

### 5.2 消息过长

**场景**：消息内容超过模型输入限制

**处理**：
- 显示警告："消息内容过长，部分历史消息将被截断"
- 自动按配置的截断策略处理

### 5.3 网络断开

**场景**：发送消息时网络断开

**处理**：
- 显示错误提示："网络连接失败，请检查网络"
- 提供"重试"按钮

### 5.4 API 限流

**场景**：API 请求频率超限

**处理**：
- 显示错误提示："请求过于频繁，请稍后再试"
- 自动等待后重试（如支持）
