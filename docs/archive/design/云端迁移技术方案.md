# The Bot 云端迁移技术方案

## 一、项目背景与目标

### 1.1 当前状态

The Bot 是一个基于 Electron + Vue3 + TypeScript 的 AI 工具箱桌面应用，提供以下核心功能：

| 功能模块 | 描述 | 核心数据 |
|----------|------|----------|
| AI 对话 | 流式对话、联网搜索、知识库增强 | roles, dialogs, messages |
| 人像设计 | 人物角色管理、多角度生成、换衣换背景 | portrait_projects, characters, variants |
| 长文写作 | 故事创作、角色/地点/势力系统、大纲章节 | lw_projects（70+关联表） |
| 剧集制作 | 剧本生成、分镜设计、视频合成 | video_projects（20+关联表） |
| 知识库 | 文档管理、向量检索、RAG 增强 | knowledge_bases, documents, vectors |
| 其他 | 翻译、语音、日记、图像生成等 | 各模块独立数据表 |

### 1.2 迁移目标

1. **双版本共存**：保留 PC 本地版本，新增云端在线版本
2. **代码统一**：最大化代码复用，降低维护成本
3. **功能完整**：在线版本功能与 PC 版本保持一致
4. **扩展能力**：在线版本提供系统提示词管理、用户管理、后台管理等增值功能

## 二、云端版后端技术栈选型

### 2.1 后端框架选型

**推荐方案：NestJS**

| 对比项 | NestJS | Express | Fastify |
|--------|--------|---------|---------|
| TypeScript 支持 | 原生支持，装饰器语法 | 需手动配置 | 原生支持 |
| 模块化架构 | 内置模块系统 | 需手动组织 | 需手动组织 |
| 依赖注入 | 内置 DI 容器 | 无 | 无 |
| 中间件系统 | 完整的中间件/守卫/拦截器 | 简单中间件 | 简单中间件 |
| WebSocket 支持 | @nestjs/platform-socket.io | socket.io | @fastify/websocket |
| 文档生成 | @nestjs/swagger 自动生成 | swagger-jsdoc | @fastify/swagger |
| 测试支持 | 内置测试工具 | 需配置 Jest | 需配置 Jest |
| 学习曲线 | 较高（Angular 风格） | 低 | 低 |
| 性能 | 中等 | 中等 | 高 |
| 企业级应用 | ✅ 非常适合 | 一般 | 一般 |

**选型理由**：
1. **与前端架构一致**：NestJS 采用 Angular 风格的模块化架构，与 Vue3 的 Composition API 思想相近
2. **TypeScript 原生支持**：本项目全程使用 TypeScript，NestJS 提供最佳 TS 体验
3. **模块化设计**：便于将现有 Services 直接迁移为 NestJS Modules
4. **依赖注入**：统一管理 Provider 实例、数据库连接等
5. **自动 API 文档**：Swagger 集成便于 API 管理
6. **WebSocket 支持**：流式通信需求可使用 @nestjs/platform-socket.io

### 2.2 完整技术栈

| 层级 | PC 版本 | 云端版本 |
|------|---------|----------|
| **前端框架** | Vue 3 + Vite | Vue 3 + Vite（相同） |

| **缓存** | 无 | **Redis**（Session、Rate Limit） |

| **API 文档** | 无 | **Swagger** |
| **监控** | 无 | **Prometheus + Grafana** |

### 2.3 向量数据库选型

**推荐方案：Milvus**

| 对比项 | Milvus | Pinecone | Qdrant | LanceDB |
|--------|--------|----------|--------|---------|
| 部署方式 | 云托管/自托管 | 仅云托管 | 云托管/自托管 | 嵌入式 |
| 性能 | 高（分布式） | 高 | 高 | 中 |
| 开源 | ✅ 完全开源 | ❌ 商业产品 | ✅ 开源 | ✅ 开源 |
| 成本 | 低（可自托管） | 高 | 低 | 低 |
| 国内可用 | ✅ Zilliz Cloud（阿里云） | ❌ 仅海外 | ✅ | ✅ |
| 知识库支持 | ✅ 专为向量检索设计 | ✅ | ✅ | ✅ |
| 实时更新 | ✅ | ✅ | ✅ | ✅ |
| 混合检索 | ✅（向量+标量过滤） | ✅ | ✅ | ✅ |

**选型理由**：
1. **国内云服务可用**：Zilliz Cloud（Milvus 云托管版）已在阿里云上线，合规且稳定
2. **开源可控**：完全开源，可自托管避免供应商绑定
3. **高性能**：支持十亿级向量检索，适合大规模知识库
4. **混合检索**：支持向量检索 + BM25 标量过滤，满足 RAG 需求
5. **与现有架构兼容**：PC 版使用 LanceDB，云端版使用 Milvus，接口可统一抽象

## 四、用户认证与安全设计

### 4.1 认证方案对比分析

**JWT 安全性评估**：

| 安全风险 | JWT 传统方案 | 改进方案 |
|----------|-------------|----------|
| Token 泄露 | Access Token 有效期长，泄露后风险高 | **短有效期 + Refresh Token** |
| Token 无法撤销 | JWT 无法主动失效 | **Refresh Token 入库，可撤销** |
| 重放攻击 | Token 被截获后可重放 | **添加 jti（JWT ID）+ 时间戳验证** |
| XSS 攻击 | Token 存 localStorage，XSS 可获取 | **存 HttpOnly Cookie** |
| CSRF 攻击 | Cookie 方式受 CSRF 影响 | **使用 SameSite + CSRF Token** |
| 信息泄露 | Payload 可解码查看 | **敏感信息不放 Payload** |

**推荐方案：HttpOnly Cookie + CSRF Token**

```typescript
// server/modules/auth/auth.service.ts

@Injectable()
export class AuthService {
  constructor(
    private readonly jwtService: JwtService,
    private readonly configService: ConfigService,
    private readonly redisService: RedisService,
  ) {}

  async login(user: User, res: Response) {
    const payload = {
      sub: user.id,
      role: user.role,
      // 不放敏感信息
    }

    // Access Token：短有效期（15分钟）
    const accessToken = this.jwtService.sign(payload, {
      secret: this.configService.get('JWT_ACCESS_SECRET'),
      expiresIn: '15m',
      // 添加唯一标识防止重放
      jwtid: uuidv4(),
    })

    // Refresh Token：长有效期（7天），入库管理
    const refreshToken = uuidv4()
    const refreshTokenHash = await bcrypt.hash(refreshToken, 10)

    await this.redisService.set(
      `refresh_token:${user.id}`,
      refreshTokenHash,
      'EX',
      7 * 24 * 60 * 60,
    )

    // HttpOnly Cookie 存储（防止 XSS）
    res.cookie('access_token', accessToken, {
      httpOnly: true,
      secure: true,  // HTTPS only
      sameSite: 'strict',
      maxAge: 15 * 60 * 1000,
    })

    res.cookie('refresh_token', refreshToken, {
      httpOnly: true,
      secure: true,
      sameSite: 'strict',
      maxAge: 7 * 24 * 60 * 60 * 1000,
      path: '/api/auth/refresh',  // 仅刷新接口可用
    })

    // CSRF Token（防止 CSRF）
    const csrfToken = uuidv4()
    await this.redisService.set(`csrf:${user.id}`, csrfToken, 'EX', 15 * 60)

    return {
      message: '登录成功',
      csrfToken,  // 返回给前端存 localStorage（XSS 无法读取 HttpOnly Cookie）
      user: {
        id: user.id,
        username: user.username,
        role: user.role,
      },
    }
  }

  async refresh(userId: number, refreshToken: string, res: Response) {
    // 验证 Refresh Token
    const storedHash = await this.redisService.get(`refresh_token:${userId}`)
    if (!storedHash || !await bcrypt.compare(refreshToken, storedHash)) {
      throw new UnauthorizedException('Refresh Token 无效')
    }

    // 获取用户信息
    const user = await this.prisma.user.findUnique({ where: { id: userId } })
    if (!user || user.status !== Status.ACTIVE) {
      throw new UnauthorizedException('用户不存在或已禁用')
    }

    // 生成新的 Access Token
    return this.login(user, res)
  }

  async logout(userId: number, res: Response) {
    // 删除 Refresh Token
    await this.redisService.del(`refresh_token:${userId}`)
    await this.redisService.del(`csrf:${userId}`)

    // 清除 Cookie
    res.clearCookie('access_token')
    res.clearCookie('refresh_token')
  }
}
```

// server/modules/admin/storage-management.service.ts

@Injectable()
export class StorageManagementService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly ossService: OSSService,
    private readonly redisService: RedisService,
  ) {}

  // 获取系统存储统计
  async getSystemStorageStats(): Promise<SystemStorageStats> {
    const totalUsed = await this.prisma.storageRecord.aggregate({
      _sum: { fileSize: true },
      where: { deletedAt: null },
    })

    const byType = await this.prisma.storageRecord.groupBy({
      by: ['fileType'],
      _sum: { fileSize: true },
      _count: { id: true },
      where: { deletedAt: null },
    })

    return {
      totalUsed: totalUsed._sum.fileSize || 0,
      byType: byType.map(item => ({
        type: item.fileType,
        size: item._sum.fileSize || 0,
        count: item._count.id,
      })),
      ossQuota: this.configService.get('OSS_TOTAL_QUOTA'),
    }
  }

  // 获取用户存储详情
  async getUserStorageDetail(userId: number): Promise<UserStorageDetail> {
    const user = await this.prisma.user.findUnique({
      where: { id: userId },
      select: { storageQuota: true, storageUsed: true },
    })

    const records = await this.prisma.storageRecord.findMany({
      where: { userId, deletedAt: null },
      orderBy: { fileSize: 'desc' },
      take: 100,
    })

    return {
      quota: user.storageQuota,
      used: user.storageUsed,
      usagePercent: (user.storageUsed / user.storageQuota) * 100,
      topFiles: records,
    }
  }

  // 设置用户配额
  async setUserQuota(userId: number, quotaBytes: number): Promise<void> {
    await this.prisma.user.update({
      where: { id: userId },
      data: { storageQuota: quotaBytes },
    })
  }

  // 批量清理过期/未引用文件
  async cleanupOrphanFiles(): Promise<CleanupResult> {
    // 查找超过 30 天无项目引用的文件
    const orphanFiles = await this.prisma.storageRecord.findMany({
      where: {
        projectId: null,
        createdAt: { lt: new Date(Date.now() - 30 * 24 * 60 * 60 * 1000) },
        deletedAt: null,
      },
    })

    // 从 OSS 删除
    for (const file of orphanFiles) {
      await this.ossService.delete(file.objectKey)
      await this.prisma.storageRecord.update({
        where: { id: file.id },
        data: { deletedAt: new Date() },
      })
    }

    return {
      deletedCount: orphanFiles.length,
      freedSize: orphanFiles.reduce((sum, f) => sum + f.fileSize, 0),
    }
  }
}

interface SystemStorageStats {
  totalUsed: number        // 总使用量（字节）
  byType: TypeStat[]       // 按类型统计
  ossQuota: number         // OSS 总配额
}

interface UserStorageDetail {
  quota: number            // 用户配额
  used: number             // 已使用
  usagePercent: number     // 使用百分比
  topFiles: StorageRecord[] // 最大文件列表
}

## 十一、总结

本方案采用 **「共享核心 + 条件编译」** 架构，实现了：

1. **代码复用最大化**：核心业务逻辑完全共享，维护成本大幅降低
2. **版本管理简单化**：单一仓库，条件编译，无需多分支同步
3. **安全合规完善**：HttpOnly Cookie、CSRF、OAuth、数据隔离
4. **管理功能完整**：用户管理、提示词管理、存储管理、提供商管理
5. **实施路径清晰**：18周分阶段实施，风险可控

**技术选型亮点**：
- NestJS：企业级后端框架，模块化、依赖注入、TypeScript 原生支持
- Milvus：国产向量数据库，性能高、合规、可自托管
- HttpOnly Cookie + CSRF Token：比纯 JWT 更安全的认证方案
