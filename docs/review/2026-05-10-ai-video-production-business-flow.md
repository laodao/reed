# AI 视频制作 · 业务流程与要素全景

> 日期：2026-05-10
> 视角：**业务**（不引用当前代码 / 不引用现有产品形态）
> 目的：从「我要做一段 AI 视频」的零起点出发，梳理标准流程的环节、每环节所需要素、跨环节一致性要求，作为后续产品设计的业务对照表

## 1. 八个环节

### 环节 1 · 创意立项

**做什么**：把一个模糊的想法变成可执行的项目定义。

**输入**：用户脑子里的灵感 / 一句话 / 一张参考图 / 一段参考视频。

**输出**：项目元信息（不进生成 prompt，但决定后续每个环节的方向）。

**业务要素**：

| 要素 | 含义 | 影响后续 |
|---|---|---|
| 题材类型 | 短剧 / 广告 / 解说 / 教程 / MV / 纪录 / Vlog | 决定剧本结构、镜头节奏、配音风格 |
| 目标平台 | 抖音 / 视频号 / B 站 / YouTube / 朋友圈 / 院线 | 决定时长、画幅、字幕样式 |
| 目标受众 | 年龄段 / 性别 / 兴趣群体 | 决定语言风格、画面美术、节奏 |
| 整体时长 | 15s / 60s / 3min / 长视频 | 决定剧本字数、分镜数量 |
| 画幅 | 9:16 / 16:9 / 1:1 / 21:9 | 决定生成图视频的宽高比 |
| 美术风格 | 写实 / 动漫 / 国风 / 赛博朋克 / 复古胶片 / 卡通 | 后续每个生成环节都要带上的"风格锚点" |
| 故事世界 | 年代（古代/现代/未来）/ 地域（中式/西式/架空）/ 整体调性 | 限定场景、服装、道具的合理范围 |
| 参考素材 | 参考视频 / 参考画风图 / 参考剧本 | 起步加速器（从 0 创作太难，从参考改最快） |

**决策点**：
- 是 AI 全自动一键生成，还是逐环节手工掌控？
- 是否有现成参考？（有参考 → 反向拆解；无参考 → 正向构思）

---

### 环节 2 · 故事 / 剧本

**做什么**：把创意展开成完整叙事 — 谁、在什么地方、做什么事、说什么话、发生了什么。

**输入**：环节 1 的元信息 + 一句话/几段创意描述 + （可选）长文/小说/解说稿。

**输出**：结构化剧本 — 由场景列表组成，每场景含人物、地点、时间、对白、动作、旁白。

**业务要素**：

| 层级 | 要素 | 含义 |
|---|---|---|
| 整体 | 主题 / 卖点 | 一句话能说清楚的内核 |
| 整体 | 故事大纲 | 起承转合 / 三幕结构 / 钩子-冲突-高潮-反转 |
| 整体 | 人物关系图 | 谁是谁、关系、动机 |
| 整体 | 时间线 | 故事内的时间推进（一天 / 一年 / 多线） |
| 场景 | 地点 | 故事发生的物理空间 |
| 场景 | 时间 / 天气 / 氛围 | 黄昏雨天 / 深夜雪夜 / 晨曦初露 |
| 场景 | 出场人物 | 该场景哪些角色出现 + 各自状态（情绪/服装） |
| 场景 | 旁白 | 全知视角的解说文本（可选） |
| 场景 | 对白 | 角色之间的对话（含情感、语速、停顿） |
| 场景 | 关键动作 | 推动情节的动作（递剑、推门、转身） |
| 场景 | 关键道具 | 影响剧情的物品（玉佩、信件、凶器） |

**决策点**：
- 剧本由 AI 生成还是用户提供？
- 长内容（小说/解说）需要 AI 拆成场景结构
- 对白由 AI 写还是用户写？

**一致性要求开始介入**：
- 同一角色在不同场景的称谓、性格、说话方式要一致
- 地点名称、世界观设定要一致

---

### 环节 3 · 角色 / 场景 / 物品（资产建立）

**做什么**：把剧本里出现的"人 / 地 / 物"转成可视化的资产 — 这些资产将在后续每个镜头里反复出现，**一致性是核心要求**。

**输入**：剧本中出现的角色名 / 地点名 / 物品名列表 + 每项的描述。

**输出**：每个资产的完整设定 + 一组视觉锚定图。

#### 3.1 角色资产

**业务要素**：

| 类别 | 要素 | 是否进画面生成 prompt | 是否进调度（剧本/配音） |
|---|---|---|---|
| 身份 | 姓名 / 别名 / 角色定位（主角/反派/配角） | ✗ | ✓ |
| 身份 | 性别 / 年龄 / 人种 | ✓ | △ |
| 视觉 | 体型 / 身高 / 肤色 / 发型 / 五官 | ✓ | ✗ |
| 视觉 | 服装（基础造型 + 多套） | ✓ | ✗ |
| 视觉 | 标志性特征（疤痕 / 纹身 / 道具配饰） | ✓ | ✗ |
| 表演 | 性格 / 情感倾向 / 招牌动作 | △ 强表现时进 | ✓ 影响演技 |
| 配音 | 音色 / 语速 / 语调 / 情感色彩 | ✗ | ✓ |
| 一致性 | **角色形象库**：多角度图（正/侧/背 三视图）+ 不同表情图 + 不同服装图 | ✓ 作为参考图喂给生成模型 | ✗ |

**关键概念**：「角色形象库」= **跨整部剧 / 整个项目共用的稳定参考图集合**。每个镜头生成画面时，这一组图作为"身份锚定"喂给 AI，保证不同镜头里同一个角色"长得一样"。

#### 3.2 场景 / 地点资产

**业务要素**：

| 类别 | 要素 | 是否进画面生成 prompt |
|---|---|---|
| 标识 | 地点名称（茶馆 / 卧室 / 山顶） | ✓ |
| 视觉 | 整体描述（材质 / 光感 / 风格） | ✓ |
| 视觉 | 室内布局 / 关键家具 / 空间感 | ✓ |
| 一致性 | **地点形象库**：不同时间的同一地点（晨/昼/昏/夜）、不同天气（晴/雨/雪）、不同视角（远/中/近） | ✓ 作为参考图 |

**关键**：同一地点在剧情不同时刻可能呈现不同状态（白天 vs 夜晚），但**结构 / 风格 / 主要陈设要一致**。

#### 3.3 物品资产

**业务要素**：

| 要素 | 是否进画面生成 prompt |
|---|---|
| 物品名 | ✓ |
| 形状 / 材质 / 颜色 / 大小 | ✓ |
| 标志性特征（雕花 / 铭文） | ✓ |
| 物品参考图 | ✓ |
| 在场景中出现的常见上下文（手持 / 桌上 / 包内）| △ |

**何时需要建物品资产**：仅当物品**多次出现**且**剧情关键**（玉佩、信件、武器）。一次性出现的道具（路边花瓶）不需要单独建。

#### 3.4 风格资产（项目级）

**业务要素**：
- 美术风格锚定图（参考画风的代表图）
- 调色板 / 主色调
- 镜头美学风格（电影感 / 数码感 / 胶片感 / VHS / 漫画）

风格资产**贯穿整个项目**，每个镜头生成都自动套用。

#### 3.5 一致性的技术路径（业务视角）

| 路径 | 对用户的体现 | 适用 |
|---|---|---|
| 多张参考图喂给生成模型 | 用户管理"角色形象库" | 主流方案，无训练成本 |
| 训练专属模型（LoRA / DreamBooth） | 用户为某角色"训练" | 长内容 / IP 矩阵 / 高质量 |
| 模型原生主体能力（subject library / Omni Reference） | 用户上传一次，整个项目自动用 | 部分新模型支持 |

**业务决策**：用户不需要懂技术细节，但需要知道"我管理这一组图就能让角色稳定"。

### 环节 4 · 分镜设计

**做什么**：把剧本的每个场景切分成若干镜头，规划每个镜头要拍什么。

**输入**：环节 2 的剧本 + 环节 3 的资产。

**输出**：分镜列表 — 每分镜含画面内容、镜头语言、出场角色配置、时长、转场。

**业务要素**：

#### 4.1 分镜切分原则（业务）

| 切分依据 | 含义 |
|---|---|
| 按对白 | 一句对白一个镜头（最常见，对话戏） |
| 按动作 | 一个完整动作一个镜头（动作戏） |
| 按情绪转折 | 情绪发生变化时切镜（特写脸部） |
| 按节奏 | 快节奏短镜头（2-3s）/ 慢节奏长镜头（5-8s） |
| 按视角 | 全景建立 → 中景互动 → 近景反应 → 特写情感（标准电影语法） |

#### 4.2 单分镜 · 业务要素

| 类别 | 要素 | 含义 / 例 |
|---|---|---|
| **画面内容**（核心） | 画面描述 | 这个镜头看到的画面是什么 — 谁在什么位置做什么、环境氛围、光影 |
| 画面内容 | 主体 | 画面焦点是谁/什么 |
| 画面内容 | 构图 | 三分构图 / 中心构图 / 对称 / 黄金分割 |
| **镜头语言** | 景别 | 远景 / 全景 / 中景 / 近景 / 特写 / 大特写 |
| 镜头语言 | 角度 | 平视 / 俯拍 / 仰拍 / 鸟瞰 / 蚁视 / 斜角 |
| 镜头语言 | 运镜 | 静止 / 推 / 拉 / 摇 / 移 / 跟 / 升降 / 环绕 / 希区柯克变焦 |
| 镜头语言 | 摄影参数（高级） | 焦距（广角/标准/长焦）/ 光圈（景深）/ 相机风格（电影/数码/胶片） |
| **光照 / 氛围** | 打光风格 | 三点光 / 伦勃朗光 / 蝴蝶光 / 黑色电影 / 赛博霓虹 / 自然光 |
| 光照 / 氛围 | 时间 | 晨 / 昼 / 昏 / 夜 |
| 光照 / 氛围 | 天气 | 晴 / 阴 / 雨 / 雪 / 雾 |
| **角色配置** | 出场角色 | 本分镜哪些角色出现（从场景出场角色子集中选） |
| 角色配置 | 角色位置 | 画面中的位置（左/中/右 + 前/后 + 大/小） |
| 角色配置 | 角色表情 | 本镜头的表情（焦虑 / 平静 / 愤怒，可比角色基础设定更具体） |
| 角色配置 | 角色动作 | 本镜头在做什么（推门 / 喝茶 / 转身） |
| 角色配置 | 角色朝向 | 正面 / 侧面 / 背面 / 三分之四 |
| **物品引用** | 出场物品 | 本镜头出现哪些关键道具 |
| **音频引用** | 旁白片段 | 本分镜对应的旁白文本（来自剧本） |
| 音频引用 | 对白片段 | 本分镜包含的对白（剧本中的哪几句） |
| 音频引用 | 音效提示 | 本分镜的环境音 / 特殊音效（开门声 / 雷声） |
| **时序** | 时长 | 本分镜的视频时长 |
| 时序 | 转场到下一镜 | 硬切 / 淡入淡出 / 叠化 / 滑动 / 圈入圈出 / 甩镜 |
| 时序 | 转场参数 | 转场时长 / 方向 / 缓动曲线 / 颜色 |

#### 4.3 分镜决策点

- 切多少镜（一个场景拆 3 镜还是 13 镜）？
- 镜头语法选择（是否套用经典模式：建立 → 中近 → 反应）
- 由 AI 自动拆还是人工逐镜设计？
- 是否参考已有视频的镜头节奏？

#### 4.4 输出粒度

每个分镜本质是一份"拍摄说明书"：拍什么 + 怎么拍 + 包含什么 + 持续多久。

### 环节 5 · 画面生成

**做什么**：根据分镜的描述，生成该镜头的视觉画面（一张或多张静态图）。

**输入**：环节 4 的单个分镜定义 + 环节 3 的资产参考图集。

**输出**：每分镜的画面图（单张 OR 关键帧序列）。

**业务要素**：

#### 5.1 画面生成的两种业务模式

| 模式 | 适用 | 输出 |
|---|---|---|
| **单帧模式** | 静态画面 / 文生视频路径下的单图先看 | 1 张图 |
| **关键帧序列** | 需要明确"开始 → 结束"动作的镜头 | 2-N 张图（首/末/中间） |

**业务区别**：
- 单帧 → 后续走"图生视频"或"文生视频"，模型自动想象运动
- 关键帧序列 → 后续走"关键帧视频"，模型在指定的几张图之间做插值，**运动可控性最强**

#### 5.2 画面生成的输入要素

| 要素 | 来源 |
|---|---|
| 文本 prompt | 分镜画面描述 + 角色当前状态 + 镜头语言 + 光照 + 风格 |
| 参考图 | 角色形象库 + 地点参考 + 物品参考 + 上一帧（关键帧链路） |
| 风格锚定 | 项目级美术风格 |
| 反向 prompt | 排除不希望出现的元素（水印 / 多余角色 / 错误结构） |
| 画幅 / 分辨率 | 项目级配置 |
| 模型选择 | 写实 / 动漫 / 国风等专长模型 |

#### 5.3 画面生成的关键决策

| 决策 | 业务含义 |
|---|---|
| 走单帧还是关键帧 | 看需要多少运动控制 |
| 用几张参考图 | 一致性 vs 创造性的平衡 |
| 风格锚定多强 | 强（贴风格）vs 弱（多变化） |
| 是否锁定构图 | 锁了构图模型自由度低，但可控性高 |

#### 5.4 用户介入点

- 不满意时**调整哪一项**最直接：
  - 风格不对 → 改风格锚定图
  - 角色不对 → 改角色参考图选择
  - 构图不对 → 改画面描述
  - 表情不对 → 改角色配置
- 这个"哪不对就改哪"的对应关系**应该清晰可见**

### 环节 6 · 运动生成（视频片段）

**做什么**：把环节 5 的静态画面变成有运动的视频片段。

**输入**：环节 5 的画面（1 张或 N 张）+ 运动描述 + 时长。

**输出**：每分镜对应的一段视频文件（无音频或仅环境音）。

**业务要素**：

#### 6.1 三种运动生成模式

| 模式 | 输入 | 模型自由度 | 适用 |
|---|---|---|---|
| **文生视频** | 仅文本（运动描述）| 高 | 简单运动 / 不强调一致性 |
| **图生视频** | 1 张图 + 运动描述 | 中 | 起始画面定，模型想象后续运动 |
| **关键帧视频** | 2-N 张图 + 运动描述 | 低（最可控）| 需要精确运动轨迹 |

#### 6.2 运动生成的输入要素

| 要素 | 含义 |
|---|---|
| 运动描述（动作 prompt） | 描述这段视频里发生的运动（不是画面是什么）— 例：「角色缓慢转身，目光由茶杯抬至窗外」 |
| 起始 / 结束帧 | 关键帧模式必需 |
| 时长 | 这段视频多长 |
| 运动强度 | 微动 / 普通 / 剧烈 |
| 镜头运动 | 镜头本身是否动（推/拉/摇/移）— 与角色运动叠加 |

#### 6.3 运动生成的"未参与项"

| 不进运动生成的字段 | 原因 |
|---|---|
| 角色身份描述 | 已经"画"在关键帧上了，不需要再说一遍 |
| 地点 / 物品描述 | 同上 |
| 镜头语言（景别/角度） | 已体现在画面构图上 |
| 光影 / 风格 | 已在画面上 |
| 对白 / 旁白文本 | 视频本身不带音频，对白是另一条管道 |
| 转场 | 转场是相邻分镜之间的事，不是单分镜内部 |

**业务核心认知**：运动生成只负责「让画面动起来」，**画面长什么样**已经在环节 5 决定。这是常被混淆的点 — 用户以为运动生成时还能改"角色长相"是错觉。

---

### 环节 7 · 声音

**做什么**：为视频生成所有声音元素 — 旁白、对白、背景音乐、音效。

**输入**：剧本中的旁白 / 对白 / 角色音色配置 + 项目级 BGM 风格。

**输出**：每个声音元素的音频文件（含时长，用于环节 8 对齐）。

**业务要素**：

#### 7.1 旁白

| 要素 | 含义 |
|---|---|
| 文本 | 旁白说什么（来自剧本） |
| 旁白人音色 | 选哪个声音 |
| 语速 / 语调 / 情感 | 平淡叙述 / 紧张急促 / 深沉低语 |
| 切分 | 整段旁白对应哪几个分镜（决定每段音频长度） |

#### 7.2 对白

| 要素 | 含义 |
|---|---|
| 文本 | 角色说什么 |
| 角色音色 | 该角色的固定音色（一致性要求） |
| 当前情感 | 本句的情绪（与剧本里的标注一致） |
| 语速 / 停顿 / 重音 | 表演细节 |
| 时长 | 这段对白持续多久（决定对应分镜的时长基线） |
| **口型对齐** | 对白音频要与画面角色口型同步（高级要求） |

#### 7.3 背景音乐 / 音效

| 要素 | 含义 |
|---|---|
| BGM 风格 | 与项目调性匹配 |
| BGM 段落规划 | 哪段视频用哪段音乐（前奏 / 主歌 / 高潮 / 尾声） |
| 音效列表 | 关键音效（雷声 / 开门 / 兵器碰撞 / 心跳） |
| 音效绑定 | 哪个分镜用哪个音效，何时触发 |

#### 7.4 一致性要求（声音域）

- 同一角色全剧音色统一
- 旁白人全剧统一
- BGM 风格全剧统一（除非剧情需要切换）

#### 7.5 业务时序对齐

声音的时长往往**反向决定**画面时长：
- 一句对白 3.5 秒 → 该分镜视频至少 3.5 秒
- 整段旁白决定全剧节奏

---

### 环节 8 · 合成 / 剪辑

**做什么**：把所有分镜视频片段 + 所有音频元素 + 转场 + 字幕，拼接成成片。

**输入**：环节 6 的视频片段列表 + 环节 7 的音频列表 + 项目级合成配置。

**输出**：最终成片（一个视频文件）。

**业务要素**：

#### 8.1 时间线

| 要素 | 含义 |
|---|---|
| 视频轨道 | 各分镜按顺序排列 |
| 音频轨道 | 旁白 / 对白 / BGM / 音效 各自一轨或同轨混合 |
| 字幕轨道 | 对白字幕 / 翻译字幕 / 标题字幕 |
| 时间标尺 | 整片时长 |

#### 8.2 转场处理

| 要素 | 含义 |
|---|---|
| 相邻分镜的转场类型 | 硬切 / 淡入淡出 / 叠化 / 滑动 / 圈入圈出 / 甩镜 |
| 转场时长 | 0.3 / 0.5 / 1.0 秒 |
| 转场曲线 | 线性 / 缓入 / 缓出 / 缓入缓出 |
| 转场颜色（淡入淡出用） | 白 / 黑 / 自定义 |

#### 8.3 字幕

| 要素 | 含义 |
|---|---|
| 字幕样式 | 字体 / 字号 / 颜色 / 描边 / 位置 |
| 字幕同步 | 与对白音频精确同步 |
| 多语言 | 主字幕 + 翻译字幕（可选） |
| 标题 / 字幕卡 | 开场标题 / 章节标题 / 片尾字幕 |

#### 8.4 调色 / 后期

| 要素 | 含义 |
|---|---|
| 整体色调 | 暖 / 冷 / 高对比 / 低饱和 |
| LUT 调色 | 风格化滤镜 |
| 局部修复 | 修复 AI 生成的瑕疵（如有） |

#### 8.5 导出

| 要素 | 含义 |
|---|---|
| 分辨率 | 1080p / 4K / 720p |
| 帧率 | 24 / 30 / 60 fps |
| 编码 | H.264 / H.265 / ProRes |
| 文件格式 | MP4 / MOV |
| 平台预设 | 抖音 / B 站 / YouTube 各自的最佳参数 |

## 2. 跨环节一致性矩阵

```
              环节 3        环节 4        环节 5        环节 6        环节 7        环节 8
              资产建立      分镜          画面生成      运动生成      声音          合成
角色身份      ★ 定义        ✓ 引用        ★ 强参与     ⚪ 不直接     ⚪ 不直接     ⚪
角色音色      ★ 定义        ⚪            ⚪            ⚪            ★ 强参与      ⚪
风格调性      ★ 定义        ✓ 引用        ★ 强参与     ✓ 间接       ⚪            ✓ 调色对齐
世界观        ★ 定义        ✓ 引用        ★ 强参与     ⚪            ✓ 配音风格    ⚪
节奏          ⚪            ★ 决定        ⚪            ✓ 时长        ★ 时长决定   ★ 转场决定
口型 / 音画同步 ⚪          ⚪            ⚪            △ 起始口型   ★ 决定时长    ★ 对齐
```

**贯穿全程的一致性要求**：
1. **角色身份** — 资产建立时锚定，画面生成时引用，整片不变
2. **风格调性** — 资产层定义，每个生成环节套用
3. **世界观** — 影响所有视觉决策（古/今、东/西、写实/奇幻）
4. **音色** — 整片角色音色不变

**跨环节时序对齐**：
1. 声音时长 → 反向决定画面时长
2. 画面运动节奏 → 与音乐节拍呼应
3. 转场时长 → 占用前后视频片段的尾/首

## 3. 用户分层 · 不同需求

### 3.1 自媒体大众用户

特征：要快、要简单、要"能用就行"。

**典型流程**：
```
1. 输入一句话 / 一段解说稿
2. 选风格（5-10 个预设）
3. 选时长
4. 一键生成 → 等待 → 看成片 → 觉得不行重新生成
```

**核心需求**：
- 自动化程度极高
- 介入点少（最多在最终成片上做小修改）
- 用预设而非参数

**对设计的影响**：
- 资产建立可以**全自动**（AI 从剧本提取，用户不管）
- 分镜可以**全自动**（AI 默认选镜头语法）
- 声音用默认音色
- 合成走平台预设

### 3.2 专业用户（短剧团队 / 工作室）

特征：要质量、要可控、要批量。

**典型流程**：
```
1. 上传成熟剧本 / 拍摄计划
2. 精细管理角色资产（每个角色多套服装、表情、形象库）
3. 逐分镜配置镜头语言
4. 多次重生成 + 挑图
5. 精修每段视频
6. 配音 + 字幕精对
7. 导出多平台版本
```

**核心需求**：
- 每个环节都能介入
- 每项配置都能精细控制
- 批量操作（10 集一起做）
- 跨项目复用资产

**对设计的影响**：
- 资产管理需要**完整 CRUD + 形象库 + 跨项目库**
- 分镜需要**所有镜头语言字段开放**
- 画面生成需要**多次重生成 + 帧级挑图覆盖**
- 合成需要**精细时间线**

### 3.3 创意 / 艺术家用户

特征：要新、要试验、要差异化。

**典型流程**：
```
1. 想法不固定，边做边改
2. 大量 A/B 测试不同风格
3. 跳跃式修改（先做后面，再补前面）
4. 寻找意外效果
```

**核心需求**：
- 高度灵活
- 透明 — 看到 AI 在做什么、为什么这样
- 易实验 — 改一个参数立即看效果

**对设计的影响**：
- 透明度面板（看 prompt / 参考图链 / 模型）
- 局部重生成（不必整体重做）
- 历史版本对比
- 子画布式连线（看清楚每个决定的影响范围）

## 4. 业务决策的"三层模型"

每个环节用户面临的决策可分三层：

### 第一层：宏观决策（项目级）
- 题材 / 风格 / 时长 / 平台
- 选哪些核心角色 / 哪些场景
- 整体调性
- 一旦定下，影响整个项目

### 第二层：场景级决策
- 这一段戏怎么演
- 切多少镜
- 节奏快慢
- 在场景边界生效

### 第三层：镜头级决策
- 这一帧画面长什么样
- 镜头语言细节
- 角色这一刻的状态
- 仅本镜头生效

**界面设计含义**：
- 第一层应在项目设置 / 一开始就决定
- 第二层在剧本 / 分镜阶段
- 第三层在分镜内部 + 制作阶段微调

混淆三层是典型 UI 反模式（让用户在镜头级面板里反复改项目级配置，或反之）。

## 5. 业务流程的"自由度坍缩"

```
环节 1 创意       自由度 ████████████████████ 100%
环节 2 剧本       自由度 ██████████████░░░░░░ 80%（受创意约束）
环节 3 资产       自由度 ████████░░░░░░░░░░░░ 60%（受剧本约束）
环节 4 分镜       自由度 █████░░░░░░░░░░░░░░░ 40%（受资产约束）
环节 5 画面       自由度 ███░░░░░░░░░░░░░░░░░ 25%（受分镜约束）
环节 6 运动       自由度 ██░░░░░░░░░░░░░░░░░░ 15%（受画面约束）
环节 7 声音       自由度 ███░░░░░░░░░░░░░░░░░ 25%（受剧本约束）
环节 8 合成       自由度 ██░░░░░░░░░░░░░░░░░░ 10%（受素材约束）
```

**关键意义**：
- **越早的决策影响越大** — 创意和剧本一旦定，后面的环节都被约束
- **重做成本前低后高** — 改剧本影响所有后续，改单个镜头只影响自己
- **错误回滚** — 如果用户在合成阶段才发现"风格不对"，要回到环节 3 重做整个项目

**对设计的影响**：
- 早期环节要让用户**慎重决策**（比一键过更重要）
- 提供"项目模板"让用户少在第一层踩坑
- 后期环节支持**局部修改**而不必全做（改单镜头不影响整片）

| 剧本视图 | 完整故事结构 + 所有对白 |

## 8. 业务环节 → 用户介入策略

每个环节用户的"介入深度"应可调：

| 环节 | 全自动 | 监督式 | 精细控制 |
|---|---|---|---|
| 创意 | AI 选模板 | 用户填一句话 + AI 推荐 | 用户完整定义 |
| 剧本 | AI 生成 | 用户改 AI 草稿 | 用户写 |
| 资产 | AI 从剧本提取 | 用户审核字段 | 用户精修每个 |
| 分镜 | AI 拆 + 配镜头 | 用户审核 | 用户逐镜配置 |
| 画面 | AI 选参考图 | 用户挑参考图 | 用户改 prompt + 改图 |
| 视频 | AI 选模式 | 用户选模式 | 用户调运动参数 |
| 声音 | AI 选音色 | 用户选音色 | 用户精调情感 |
| 合成 | AI 选转场 | 用户挑转场 | 用户自定义时间线 |

**默认策略**：
- 自媒体用户：全部走全自动
- 专业用户：默认监督式，关键环节切精细控制

## 9. 业务流程的"标准时长成本"

参考行业实际：

| 环节 | 自动时长 | 监督时长 | 精细时长 |
|---|---|---|---|
| 创意 | 1 分钟 | 5 分钟 | 30 分钟 |
| 剧本 | 30 秒 | 5 分钟 | 30 分钟 - 数小时 |
| 资产 | 1-3 分钟（含 AI 生图）| 5-10 分钟 | 30 分钟 - 1 小时 |
| 分镜 | 30 秒 - 1 分钟 | 5 分钟 | 30 分钟 |
| 画面 | 每镜 30s-1min（含 AI 生成）| 同左 + 挑图 | 同左 + 多次重生 |
| 视频 | 每段 30-60s | 同左 | 同左 + 调参 |
| 声音 | 1 分钟 | 5 分钟 | 30 分钟 |
| 合成 | 30 秒 | 1 分钟 | 5 分钟 |

**总成本**：
- 自动模式：5-15 分钟出 60s 视频（一杯咖啡）
- 监督模式：30 分钟 - 1 小时
- 精细模式：数小时 - 数天

## 10. 业务流程的"反模式" / 常见错误

| 反模式 | 表现 | 后果 |
|---|---|---|
| 跳过资产建立直接生成 | 每个镜头单独生成不复用 | 角色长相每镜不同，无一致性 |
| 把叙事元数据塞进画面 prompt | 把"姓名 / 别名 / 角色定位"塞进文生图 | 模型注意力被干扰，画质下降 |
| 让用户填一堆字段才能开始 | 11 个角色字段必填 | 用户放弃 |
| 同个面板混三层决策 | 在镜头级面板改项目级风格 | 用户迷茫，反复改不到点 |
| 把"显示"和"作用"混淆 | UI 显示 7 段提示词文本但只有 1 段进生成 | 用户被误导，调错地方 |
| 把转场放在分镜阶段而非合成阶段 | 转场是分镜间事 | 用户在错误的地方决策 |
| 只做"全自动"或只做"精细" | 一种用户类型 | 失去另一类用户 |

## 11. 给后续设计的核心问题

把这份业务流程当对照表，回头审视任何 AI 视频产品都能问：

1. **环节是否齐全**？8 个环节是否都有，没有的环节用户怎么补？
2. **每环节要素是否齐全**？业务上需要的字段是否都能填？
3. **每环节要素是否冗余**？UI 上的字段是否都真的影响后续？
4. **跨环节一致性是否保证**？角色身份 / 风格 / 音色是否贯穿？
5. **跨环节时序是否对齐**？声音时长是否反向决定画面时长？
6. **三层决策是否分明**？项目 / 场景 / 镜头各自该决策的事是否在对的地方？
7. **用户介入策略是否分层**？全自动 / 监督 / 精细三种用户都能用吗？
8. **可视化是否到位**？每个环节用户能看到自己做了什么、AI 做了什么吗？
9. **错误回滚是否友好**？后期发现前期错误时能局部修而非全做吗？
10. **业务术语是否准确**？UI 用词是否与行业标准一致？
