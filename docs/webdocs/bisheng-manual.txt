工作流功能用户手册
1. Workflow工作流
workflow、助手、技能三种创建应用的方式有什么区别？
Workflow 是BISHENG自研的低代码编排体系，底层引擎基于 Langgraph，相比市面上同类产品的特点是独立完备、支持 Human in the loop、支持成环（详见 3.5 节）
助手类似 OpenAI 的 GPTs 产品，主要通过自然语言的 prompt 来定义执行逻辑，以及搭配知识库等工具，面向不了解技术的业务人员。
技能是BISHENG早期搭建应用的方式，基于 Langchain、Langflow，在 Langflow 原生组件的基础上开发了一些新组件，特点是暴露的可调节参数多，但编排逻辑不直观（长期计划用户 workflow 取代 技能）。
1.1 创建 workflow
按照以下操作，创建工作流：
step1：基于模板或从零创建工作流。在左侧导航栏选择【构建】菜单，点击【新建应用】，点击【自定义工作流】或基于模板创建工作流。
step2：工作流编排及调试。从左侧边栏选择所需的节点，每个节点右侧触点与下一个节点的左侧触点连接，按照业务逻辑进行编排。点击【运行】按钮，可在右侧弹窗中进行调试运行。支持导出工作流为本地，以及从本地文件导入工作流。
step3：工作流上线。上线后可在会话菜单中展示及使用。

1.2 创建应用模板
按照以下操作，将已有工作流存为模板：
step1：找到目标工作流。在【应用】页面找到希望保存为模板的工作流。
step2：进入创建模板入口。在工作流卡片右下角，点击齿轮形状的【设置】按钮，在弹出的菜单中选择【创建模板】。
step3：填写模板信息。在弹出的【创建模板】对话框中，工作流名称默认为源工作流名称，可按需修改；描述建议填写模板的用途、适用场景等说明，便于后续检索与使用。
step4：完成创建。点击对话框右下角的【创建】按钮，即可将当前工作流保存为模板。创建成功后可在页面右上角的【管理应用模板】中进行查看、拖拽排序、删除操作。
1.3 节点及变量概念介绍
节点：在工作流中，每个节点承担独立的功能任务，可通过编排节点之间的执行步骤，来实现特定的业务逻辑。目前 BISHENG workflow 中的节点分为两类：
基础节点：开始、输入、输出、大模型、助手、QA 知识库检索、文档知识库问答、报告、代码、条件分支、结束。
工具节点：包括BISHENG内置工具以及用户创建的自定义工具。
变量：存储工作流运行过程中产生的数据（例如用户输入的信息、预置的文本、节点运行的结果），通过在不同节点之间引用变量，实现数据的传递。在节点中，通过点击（x）按钮，可在弹出的变量列表中选择可用的全局变量。
例如在条件分支节点中，可通过引用并判断变量的值，来决定后续的执行逻辑。

1.6 节点功能说明
1.6.1 开始节点
功能说明
工作流运行的起始节点（创建工作流时会自动拖出，无法复制和删除）。
配置说明
开场白：在工作流运行开始时发送一条消息，支持 Markdown 格式。
引导问题：左下角展示若干引导问题，实现引导用户输入的目的。
全局变量：
当前时间：自动获取当前时间（格式：yyyy-mm-dd hh:mm）。
最近 n 条聊天记录：记录会话页面中应用与用户的最新聊天记录，常用于总结历史记录或者基于聊天记录进行业务判断等场景，可自定义需要存储的消息条数n 。
预置问题：预置若干文本项，通常用于合同审核等需要批量预置文本的场景。
1.6.2 输入节点
功能说明
接收并存储用户在会话页面的输入，支持对话框输入和表单输入两种输入方式：
对话框输入：接收用户在对话框中输入的内容，存储在user_input 变量中。也可以上传文件和图片，分别存储在dialog_files_content和dialog_image_files
表单输入：通过弹出表单接收用户输入。表单项包括文本输入框、下拉选项和文件上传，支持拖拽排序和必填设置，灵活满足各种输入需求。
会话中对话框输入
会话中表单输入
配置说明
对话框输入：无需配置。
表单输入：可配置三类表单项的展示名称以及变量名称
文本表单：接收用户的文本输入。
下拉表单：接收用户的选择结果，支持多选。
文件上传表单：接收用户上传的文件，会自动上传到临时知识库。
1.6.3 输出节点
功能说明
在会话界面中向用户输出指定消息内容（可引用其他节点变量内容），同时支持更丰富的交互形态：
无交互：只输出消息内容文本。
选择型交互：支持用户选择，适用于多逻辑分支选择、敏感操作待人类确认等场景。
输入型交互：支持用户在编辑框中进行文本输入，用户的输入也可以作为变量提取出来，编辑框中支持预置文本（可以引用全局变量），适用于人类提出修改建议等场景。
无交互输出
选择型交互输出
输入型交互
配置说明
消息内容：消息内容中可手动输入文字，可引用其他节点的全局变量，以及上传文件/图片（点击上传按钮触发）。当运行到输出节点时，会将所有消息内容输出到会话中。
选择型交互：手动添加选项，每个选项右侧会自动展示触点，连接到后续不同逻辑分支。
输入型交互：默认为空，也可手动输入文本或插入其他节点全局变量。会话页面中用户可在此编辑框中进行编辑和确认，确认提交后的内容将会存储在 output_result功能中。

1.6.4 大模型节点
功能说明
调用大模型接口进行任务处理，可以根据需要选择单次运行或批量运行模式。
批量运行
配置说明
模型：在下拉框中选择要使用的模型，请先在模型管理功能模块中进行模型配置。
温度：调整模型生成内容的随机性，数值越大随机性越高，默认值 0.7。
提示词：
系统提示词（system prompt）， 对应系统消息，用于设置大模型人设属性相关。
用户提示词（user prompt），对应用户消息，用于设置实际会发送的用户消息内容。
视觉：视觉功能开关：默认关闭，关闭时不展示变量输入入口。开启后可以输入图片变量。
输出：
打开“将输出结果展示在会话中”开关，模型生成的结果将直接展示在会话中（支持流式输出）。
关闭“将输出结果展示在会话中”开关，模型生成结果不会展示在会话中，只会存储在变量中，供后续其他节点引用使用。
批量运行模式说明
变量赋值：选择需要批处理的多个变量（例如开始节点中的预置问题列表），当选中多个变量时，会逐一将该变量的值赋值给 batch_variable，通过在用户提示词中引用batch_variable来指代要处理的实际变量。
多次运行大模型节点：后端将会多次运行大模型节点，每次运行的结果会分别存储到对应变量中（详见输出变量列表）。如果打开“将输出结果展示在会话中”开关，将会分多条消息进行流式输出。
1.6.5 助手节点
功能说明
助手节点完整实现了BISHENG助手的功能，允许 AI 自主进行任务规划，选择合适的知识库、 mysql数据库或工具进行调用，由 AI 自主决定相关工具的入参。
配置说明
模型：在下拉框中选择要使用的模型，请先在模型管理-系统模型设置-助手模型中进行模型配置。
温度：调整模型生成内容的随机性，数值越大随机性越高，默认值 0.7。
提示词：
系统提示词（system prompt）， 对应系统消息，用于设置大模型人设属性相关。
用户提示词（user prompt），对应用户消息，用于设置实际会发送的用户消息内容。
历史记录：可选择是否包含用户会话中的历史聊天记录信息，需要历史上下文信息时建议打开，支持调整历史上下文消息条数。
知识库：AI 可以查询的知识库列表，支持多选，注意 AI 非必须查询知识库，如发生需查询知识库但实际未查询时，需对 prompt 等内容进行优化，参考助手知识库/工具/技能调用的原理与实践。
数据库：目前支持 mysql 数据库，需要填入数据库地址、数据库名称、用户名、密码。
工具：AI 可以调用的工具列表，支持多选，注意 AI 非必须调用工具，如未调用时可参考助手知识库/工具/技能调用的原理与实践进行效果优化。
输出：
打开“将输出结果展示在会话中”开关，模型生成的结果将直接展示在会话中（支持流式输出）。
关闭“将输出结果展示在会话中”开关，模型生成结果不会展示在会话中，只会存储在变量中，供后续其他节点引用使用。
批量运行模式说明
变量赋值：选择需要批处理的全局变量（例如开始节点中的预置问题列表），当选中多个变量时，会逐一将该变量的值赋值给 batch_variable。一般后续在用户提示词中引用batch_variable来指代要处理的实际变量。
多次运行大模型节点：后端将会多次运行大模型节点，每次运行的结果会分别存储到对应变量中（详见输出变量列表）。如果打开“将输出结果展示在会话中”开关，将会分多条消息进行流式输出。
1.6.5.1 助手节点数据库查询使用说明
数据库问答示例
助手数据库查询的原理如下：
完成数据库相关配置（数据库地址、名称、用户名、密码）后，会为助手节点绑定一个名为 sql-agent 的工具，模型根据用户需求理解，自主决定是否调用该工具。
该工具的入参是用户数据查询需求的自然语言描述，出参是数据查询结果。
工具具体实现逻辑：
获取该数据库中的表列表；
使用大模型判断哪些表与用户的问题相关，并检索相关表的表结构；
使用大模型基于用户问题和相关表的字段生成 SQL 查询语句；
检查生成的 SQL 查询语句是否存在错误，并尝试进行修正；
执行 SQL 查询，如果遇到错误会返回到上一步重新进行修正；
将查询结果用于生成最终答案并返回给用户。
由于sql-agent 本身是一个工具，工具的入参质量会比较大程度影响执行效果，所以需要在助手 prompt 中需要注意强调用自然语言较精准地转述用户数据查询需求，以下是prompt 示例：
Markdown你是一个智能数据分析助手，擅长根据用户需求查询，调用 sqlagent 工具进行数据查询。# task1、结合 jt_jycw_test 表字段信息，重新描述用户的数据查询需求（注意仍然使用自然语言描述，而不是给出sql语句,需要给出要查询的表名称），将该描述作为参数 query 的值，调用 sqlagent 工具；2、如果用户有多条查询需求，分两次调用sqlagent。# 数据库表“jt_jycw_test”字段介绍   "year": 年份，   "month":月份，   "corporation":单位名称，   "corporation_T":二级单位名称，   "level":实际企业级次，   "platform":单位所属平台
1.6.6 QA知识库检索节点
功能说明
一般用于客服问答场景，QA 库中已经提前存储企业积累的 QA 对，节点运行时从 QA 知识库中检索问题对应的答案，并存储到变量中，未检索到答案时为空。
配置说明
输入变量（必填）：需要检索的内容，需要从工作流中的其他节点引用变量，例如输入节点中用户输入的内容。
QA知识库（必填）：选择要检索的QA知识库，支持多选。
相似度阈值：控制检索结果过滤的阈值，低于阈值的结果将被过滤掉。默认为0.6，可根据实际情况进行调整。
1.6.7 文档知识库检索节点
功能说明
根据用户问题，从知识库中检索相关内容，并返回相关结果
支持批量运行，可选择多个用户问题。
配置说明
知识库检索设置
用户问题（必填）：从下拉框中选择用户问题，问题的值会存储在 user_question 变量中。
检索范围（必填）：选择要检索的知识库或临时会话文件（输入节点中上传的文件），支持多选。
高级检索设置：开启后，将会允许用户自定义高级检索参数
用户知识库权限校验：开启后，将会过滤用户无使用权限的知识库（在系统管理中可设置权限）。
检索器权重设置：用于调整混合检索中“关键词检索”和“向量检索”的相对权重。
检索结果重排 ：开启允许使用rerank模型完成对检索结果的重排序
检索结果长度：限制知识库检索结果的长度，防止超出模型上下文限制。
输出：
输出一个字典，包含从用户问题检索出的分块数据，包含元数据和内容两个键
批量运行模式说明
变量赋值：当用户问题选中多个变量时，会逐一将该变量的值赋值给 user_question ，在用户提示词中引用batch_variable来指代要处理的实际变量。同理，每一次变量的检索结果会赋值给retrieved_result，在提示词中引用 retrieved_result 来指代实际要处理的变量。
多次运行大模型节点：后端将会多次运行节点，每次运行的结果会分别存储到对应变量中（详见输出变量列表）。
1.6.8 文档知识库问答节点
功能说明
根据用户问题，从知识库中检索相关内容，结合检索结果调用大模型生成最终答案，适用于知识库问答等 RAG 场景。
支持批量运行，可选择多个用户问题。
配置说明
知识库检索设置
用户问题（必填）：从下拉框中选择用户问题，问题的值会存储在 user_question 变量中。
检索范围（必填）：选择要检索的知识库或临时会话文件（输入节点中上传的文件），支持多选。
高级检索设置：开启后，将会允许用户自定义高级检索参数
用户知识库权限校验：开启后，将会过滤用户无使用权限的知识库（在系统管理中可设置权限）。
检索器权重设置：用于调整混合检索中“关键词检索”和“向量检索”的相对权重。
检索结果重排 ：开启允许使用rerank模型完成对检索结果的重排序
检索结果长度：限制知识库检索结果的长度，防止超出模型上下文限制。
AI 回复生成设置
系统提示词（system prompt）， 对应系统消息，预置内容如下：
Plain Text你是一个知识库问答助手：1.用中文回答用户问题，并且答案要严谨专业。2.你需要依据以上【参考文本】中的内容来回答，当【参考文本】中有明确与用户问题相关的内容时才进行回答，不可根据自己的知识来回答。3.由于【参考文本】可能包含多个来自不同信息源的信息，所以根据这些不同的信息源可能得出有差异甚至冲突的答案，当发现这种情况时，这些答案都列举出来；如果没有冲突或差异，则只需要给出一个最终结果。4.若【参考文本】中内容与用户问题不相关则回复“没有找到相关内容”。
用户提示词（user prompt），对应用户消息，用于设置实际会发送的用户消息内容。
SQL用户问题：{{user_question}}参考文本：{{retrieved_result}}你的回答：

1.7.1 独立、完备的流程编排框架
在BISHENG中，workflow 是一个独立、完备的应用构建体系，与 BISHENG助手（类似于 GPTs、 coze 中的 bot）相互独立。
因此，BISHENG workflow 与 coze workflow 差异在于：coze workflow 强依赖于 bot 存在，workflow 的输入是通过 bot 获取的；而BISHENG workflow 则可以独立搭建应用
BISHENG workflow 与 Dify 的区别在于：Dify划分出 chatflow 和 workflow 两种类型，分别完成多轮会话应用 和 非会话的自动化任务，但这种割裂的划分并不实用，因为现实世界中一个复杂的业务场景可能夹杂着多轮对话和自动化处理。BISHENG不存在 chatflow 和 workflow 的划分，支持用一个通用框架来实现各类业务场景下应用的搭建。
1.7.2 Human in the loop：中间过程支持灵活的输入/输出和多样化的人机交互
一个能够支撑复杂业务场景的工作流，必然需要人类与 AI 进行协作，人类和 AI 共同影响和控制 workflow 的执行流程 —— 如果大模型的能力很强，那么流程中的很多判断、决策任务都可以由大模型来完成；如果大模型的能力较弱，那么仍然需要人类来完成流程执行过程中的判断、决策任务。

1.7.3 支持成环
当前网络上有大量把 DAG（有向无环图）作为 workflow 技术实现方案的思路，我们认为这是一个错误的方案，DAG 只是一种图结构，并不能通用地表达现实世界中任务的执行过程，正确的做法应该是基于自动机理论（例如 DFA）来表达任务的执行过程。
DFA（确定有穷自动机） 与 DAG（有向无环图）是两个完全不同的概念，其中一个重要的区别是是否支持成环。成环在现实世界中的应用相当普遍，例如：
基于 ReAct 模式的循环实现大模型的工具调用；
例如辅助代码编程（涉及“编写代码→调试运行→获取运行报错信息→编写代码→…”的循环）；
例如人类与 AI 多轮对话（涉及“人类输入→AI 输出→人类输入→…”的循环）。
这里的成环和 dify/coze 的循环节点不是同一概念：dify/coze的循环节点主要解决某一数组变量的迭代处理问题（BISHENG目前通过单个节点批处理模式来实现这一类场景）。
为了防止 workflow 编排者不慎编排出无限循环的场景（例如缺少输入节点中断循环，或者缺少条件分支节点跳出循环），BISHENG workflow 做了单个节点最多运行 50 次的限制，超出次数后自动停止工作流，管理员可在在系统配置中通过变量 workflow/max_steps 参数进行调整。
1.8 工作流 API
工作流 API 用来干什么？
毕昇工作流 API 可以让您在自己的平台或前端应用中，调用并执行毕昇平台上已配置好的工作流。
毕昇工作流 API 的特点
有状态：由于毕昇工作流的特点（例如支持成环、支持在任意中间过程执行输入节点从而产生中断），所以后端需要根据工作流当前状态对请求做不同响应。这意味着：同一个接口，因当前所处的工作流阶段不同，可能返回不同的数据和事件类型。
事件驱动：工作流的每一步执行都对应一个或多个事件（event）。调用者需要根据事件类型判断当前该做什么操作（渲染表单、对话框、下载文件，或者直接展示文本、图片等）。
保持上下文：在每次请求时携带 session_id，后端才能知道当前工作流进行到哪一步。如果漏掉或用错 session_id，将无法继续执行流程。
因此：对接工作流 API 时，调用方需要仔细处理返回的事件类型，并且在后续请求提交输入时携带正确的上下文（session_id、node_id 等）。

调用方处理示例
status="stream" 代表当处于流式输出中，需要根据node_execution_id 和 output_schema.output_key 来确定流式内容是否属于同一条消息（节点批量运行模式下，会共用同一个 node_execution_id，所以需要根据 output_key 来区分是否是不同的消息）。
如果找到对应的消息，则将message内容添加到对应的消息里
如果未找到对应的消息，则开启一条新的消息，并将message和后续此消息的message拼接在一起

2.4  助手知识库/工具/技能调用的原理与实践
2.4.1  原理介绍
助手支持通过以下两种方式实现工具调用，可在模型管理-系统模型设置-助手模型中设置某个模型的助手工具调用方式：
OpenAI function call 格式接口协议
ReAct 模式（几乎所有模型，具体效果取决于模型能力）
助手推理模型设置
对于助手而言，知识库/工具/技能没有区别，都等待被调用的“工具”，LLM 根据用户 query 和助手所绑定的“工具”名称和描述，来判断调用哪些特定工具。

2.4.3 Q&amp;A
Q：助手不能调用技能或者工具，是因为什么？
A：首先尽可能使用模型本身具有 function call 能力的模型；其次可以根据上述实践经验对 prompt 和相关技能/工具的名称进行优化。
Q：助手里的知识库和技能里的知识库有什么关系？助手里选了，技能里也选了会怎么样？
A：二者是独立的。
如上文原理所述，助手知识库是一个工具，技能也是一个工具。LLM 可能根据【知识库名称和描述】选择直接调用知识库，也可能根据【技能的名称和描述】来选择调用技能。
助手都调用，或者都不调用，或者只调用知识库和技能中的一个，和模型能力、prompt、知识库名称及描述、技能名称及描述都有关系。
Q：绑定的工具多了会不会影响性能？
A：会有影响，从目前我们的评测效果看，对于 GPT4 和 Command R  plus等模型而言，5-6 个工具的调用没有问题。

【更新时间】：文件在系统被更新的时间。
【状态】：该文件上传后在系统中的状态，包括[解析中]、[完成]、[解析失败]，如果失败支持右侧手动触发重新解析。
【操作】：点击[删除]删除该文件。
支持的文件格式： pdf（含扫描件）、ofd、txt、docx、pptx、md、html、xls、xlsx、doc、ppt、 wps、et、dps、png、jgp、jpeg、bmp（PDF、图片类型文件解析需要部署BISHENG可选组件：毕昇可选组件部署）
3.1.2.2  文件上传操作介绍
点击右上角【上传文件】按钮，进入文件上传页面。文件上传过程分为三步：
上传文件
分段策略
选择本地文件完成上传：点击虚线框中的区域或将文件拖拽到虚线框中的区域即可上传文件，点击×号可取消文件上传。
配置文档切分策略
文档切分逻辑介绍：
首先取最高优先级的切分符对文档进行切分，如果 切分结果长度 &lt; 分段长度设置 ，则会将此结果作为最终分段结果；
如果分段切分结果 > 分段长度设置，则会按优先级取次优切分符继续对文档继续切分，如果 切分结果长度 &lt; 分段长度设置 ，则会将此结果作为最终分段结果；
如果使用所有的切分符后，切分结果仍然大于分段长度设置，不会强行截断，将此结果作为最终分段结果。
e.g. 假如切分符策略设置为"\n\n"、"\n"，分段长度设置为 1000，使用"\n\n"进行切分时，如果分段长度为 1001，则会使用"\n"对此分段继续切分；如果该分段内有"\n"使得切分结果长度为 999，则分段的最终结果为 999；如果该分段内没有"\n"，则分段切分结果长度为 1001。
默认策略：按照系统默认配置的切分参数（chunk_size=500, chunk_overlap=50, seperator=['\n\n']）进行段落切分
自定义切分策略：
支持用户自定义切分符，默认包含 '\n\n'（会在表格、标题等场景进行切分）。切分符支持正则表达式格式，例如在"第.{1,3}条" 前进行切分时，会在“第1条”、“第ab条”“第三条”等文本之前进行切分。
切分符支持拖拽调整优先级
支持设置分段长度和重叠区长度，默认值为 1000 和 100
分段结果预览（非必须）
确定切分策略后，点击预览分段结果可在右侧进行效果预览，点击【编辑】按钮可以进入分段编辑页面，可调整分段内容。根据不同部署情况，页面元素有所差异：
未部署 bisheng-unstructured：不展示原文件。
只部署  bisheng-unstructured：展示转 PDF 后的原文件，但无法圈选文本框。
部署 bisheng-unstructured + OCR SDK：展示转 PDF 后的原文件，可定位到分段对应文本内容（标黄显示），可左键圈选调整内容范围。
分段编辑页面（bisheng-unstructured + OCR SDK 模式下）
由于等待预览时间可能较长，也可先提交分段策略，后续在分段管理页面中进行分段内容调整。
若在部署时配置了向量数据库及ES全文索引数据库，则上传的文件会自动构建向量索引与ES关键词索引

3.2  QA 知识库
QA 知识库用于存储固定 QA 对，并支持设置相似问题（提高召回率）。QA 对通常来源于企业内部沉淀的业务问题及答案，因此在遇到此类问题时，无需借助大模型能力，直接返回问题对应的答案即可，示例应用见双路径问答
3.2.1  QA 知识库管理
点击左侧导航栏【知识】一级菜单，选择【QA 知识库】tab，进行 QA 知识库创建和管理。
3.2.1.1  QA 知识库列表介绍
知识库列表包括以下字段：
【知识库简介】：包含
【知识库名称】：用户创建时填写的知识库名称
【模型】：创建知识库时，用户选择的向量模型名称
【更新时间】：是指该知识库最新上传文件的时间
【创建用户】：知识库的创建者
【操作】：
【复制】：点击复制整个知识库
【设置】：点击设置知识库名称、embbeding模型等
【删除】：点击删除知识库
3.2.1.2  QA知识库创建操作
点击右上角【创建】按钮，弹出创建知识库弹框，需填写知识库名称、知识库描述，选择模型管理中已上线的 embedding 模型。
3.2.2  QA 管理
3.2.2.1  手动添加 QA
在 QA 列表中，点击【创建 QA】按钮，可手动添加 QA对 到知识库。
支持为问题添加多个相似问题，增加 QA对 检索召回率。相似问题支持通过大模型生成，可在模型管理中配置所使用的大模型。
3.2.2.2  通过历史会话标注添加 QA
可通过标注历史中的问答数据，添加到 QA 知识库，详见审计。
3.2.2.3 QA对的批量操作
批量导入导出QA对
可以通过【导入】【导出】按钮实现批量导入导出功能
传入与示例QA文件格式相同的xls，xlsx文件实现导入
点击导出即可导出QA对，对应的xlsx文件
QA对批量启用、禁用和删除
点击左侧复选框，页面上传会出现启用、禁用和删除按钮，点击即可对QA对进行批量启用、禁用和删除
