# 长文写作优化实施与 10 集剧本实跑记录（49 号验收报告）

- 日期：2026-09-12（实跑跨 09-09 夜间至 09-12 凌晨）
- 配套方案：`docs/design/2026-09-09-writing-quality-optimization.md`（F1-F5 与调研依据）
- 结论：**F1-F5 优化后，管线首次端到端产出可用短剧剧本**——10 集全部带集尾卡点、每集含完整打脸/反转节拍，剧本格式符合竖屏短剧规范。过程中暴露并修复 3 个真实产品缺陷。

## 1. 实跑方式

- 真机 Electron（`dev:debug`，CDP 9222）+ 真实 LLM（阿里百炼 tokenplan：deepseek-v4-flash-0731 主力 / qwen3.8-max 兜底），经 `electronAPI` IPC 驱动与用户手操完全同链路。
- 编排脚本 `scripts/lw10-episode-script.cjs`（断点续跑：进度落 /tmp/lw10-state.json，任何一步失败重跑即续）。
- 剧情设定（用户授权自定）：`/tmp/lw10-premise.json`——10 集都市鉴宝爽剧《金瞳》，按 R1 节拍模板逐集设计 beat（含每集爽点配额与钩子类型）。

## 3. 实跑暴露并已修复的问题（均为真实产品缺陷）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 3-1 | 分集大纲两次"解析失败" | deepseek-v4-flash 是混合推理模型：纪律密度高的 JSON 任务触发 43K token 思维链，**预算全烧在思考上、正文 0 字**（finish=length） | 编排层模型分级重试（deepseek→qwen3.8-max）；小说正文类任务 deepseek 仍主力（思维链仅 0.7-9K） |
| 3-2 | 第 9 集正文仅 80 字落库 | 同上（24K 思维链 0 正文）+ 扩写 pass 拿到的也是垃圾 | 质量门保留（扩写 fail-soft）；编排层加最小字数守卫（<600 字判失败换模型重试），重生成 1832 字 |
| 3-3 | 第 3 集剧本"缺正文" | **场景 JSON 太啰嗦，16K 输出预算被 JSON 吃光**，正文根本没开始写（响应截断在 JSON 中段） | script-generator 加**正文救援路径**：正文缺失时用 8K 预算单独补写正文（SCRIPT_BODY_ONLY_PROMPT），实测成功 |
| 3-4 | 剧本生成 "Request timed out" | OpenAI SDK 客户端硬编码 60s 超时，非流式长剧本必超 | `AI_PROVIDER_TIMEOUT_MS` 环境变量可覆盖（默认 60s 不变），实跑设 600000 |

## 4. 质量评估（对照 R1 方法论逐项检查）

**格式规范**（每集检查）：
- 场景标题行（"1 典当行店内 午后"）✅；对白"角色：台词"短句 ✅；动作描写现在时 ✅；无 Markdown ✅
- 每场 2-3 句对白内浮出冲突 ✅（E1 开局第 2 句即"赔不起就跪着捡"）
- 首出场外貌锚定 ✅（苏晚"象牙白风衣/眉眼清冷"、何瑞"锃亮皮鞋"）

**节奏纪律**：
- 黄金三秒 ✅：E1 直接从碎瓷羞辱切入，无环境铺垫开场
- 打脸四步完整 ✅：E1 羞辱(踩瓷/嘲讽)→隐忍(盯三秒)→反击(三处鉴定破绽)→释放(满屋寂静/何瑞脸白)
- 每集集尾卡点 ✅：10/10 通过（自动检查+人工抽查），且做到"切在问题上"——E1"给我查"、E3"勿信孔"、E5"想活就承认你是守镜人"、E9"铜镜是假"、E10"守镜人不止你一个"
- 钩子类型轮换 ✅：悬念/身份/信息/情绪/反转交替，无相邻同型

**对照 premise 节拍表**：E1 拍卖会打脸 ✓、E3 官仿官反转 ✓、E5 盲鉴公开反击 ✓（模型把孔老质问转化为"守镜人"纸条，属合理再创作）、E8 大火谷底 ✓、E9 发布会揭露 ✓、E10 终局清算+第二季钩 ✓。

**样本全文**：`outputs/金瞳.md`（第 1 集人工逐行评估：对白占比约五成、无独白滥用、场景≤4、卡点落在最后一场最后一拍）。

## 5. 残留与建议

1. **deepseek 思维链预算问题**是管线性风险（3-1/3-2 同根因）：建议平台层给"结构化 JSON 生成"任务默认禁用思考或抬 thinking 预算上限——需探明 token-plan 网关的思考预算参数，单独一轮。
2. **场景 JSON 体积**（3-3 根因）：视频管线要的字段多，纯剧本交付场景下可出"轻场景模式"（只出骨架场表）——登记待议。
3. 质量门 verdict/扩写信息已随 `data.qualityGate` 透出，章节工作台 UI 尚未展示——前端小改可让用户看到"已自动扩写"。
4. 本次实跑为 10 集短剧形态；长篇小说形态（30+ 章跨卷）的黄金三章/去向卡效果待一次长跑验证。
