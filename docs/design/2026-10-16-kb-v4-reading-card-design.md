# V4 详细设计一：章级结构化阅读卡（reading card）

- 日期：2026-10-16
- 上级设计：`2026-10-16-knowledge-brain-v4-whole-book-funnel-design.md`（§4 方案 A1，阶段 V4-1）
- 复杂度评估：**高**（新存储列 + 新消化遍 + 三画像 schema + 多消费方切换 + 存量补跑）

---

## 1. 目标与定位

给每章产出一份**分域结构化的阅读卡**，作为整条书级产线的统一中间层：

- **取代章节摘要的职责**：摘要是一段 600 字纯文本，只有全书概要一个消费方；阅读卡是分域 JSON（梗概/事件/人物事实/设定事实/伏笔动作/文风摘抄，全部带章内定位），供名册、编年段、卷、书级全部产物取材。
- **完整性有保证**：逐章落盘、只随本章内容变化而重做，永不互相覆盖——大部头读完，中间层是全量的（压缩但不失真）。
- **层次自此有了载体**：卡内每个事实天然属于一个域（人物/设定/剧情/文风），上层归并按域取材——「宏观到微观的层次」由漏斗结构保证，不再依赖模型在单章内自标层。

**参考来源**：deepwrite 阅读卡（per-chapter record：summary/events/characters/world/plot.foreshadowing/style，程序校验章号合法性、逐章为独立保存检查点）。差异：deepwrite 按 ≤20 章阅读块批读批量提交；v4 按**章**为最小单元（章级台账/裁决/溯源全部锚在章上，见总设计 §3）。

## 2. 数据结构

### 2.1 存储

`kb_chapters` 加两列（可空，无回填压力）：

```
brain_card       TEXT NULL     -- 卡 JSON（§2.2）
brain_card_hash  VARCHAR NULL  -- 卡内容 sha256（消费方廉价失效判断）
```

- 卡的有效性由**章级台账**管理（`passType='card'`，`passKey='card'`，`chapterHash` 章内容指纹）——内容没变跳过、失败留痕可重试、审核拦截封账，全部沿用现有台账语义，不新增状态列。
- 卡是过程产物：不进知识卡列表、不进检索池、不做向量（消费方按 documentId+ordering 顺序直读）。
- 大小护栏：整卡序列化 ≤8000 字符（典型 2-4KB；千章书全量卡 ≈2-4MB SQLite 完全可承受）。

### 2.2 卡 schema（按画像三变体）

公共字段 + 画像域字段。所有事实字段一律带 `ch`（章号，程序校验必须等于本章章号——deepwrite 硬校验同款，防模型跨章编造）。

**novel（小说）**

```jsonc
{
  "v": 1, "profile": "novel",
  "summary": "……",                        // ≤500 字：谁、在哪、做了什么、结果、章末钩子
  "events": ["……"],                        // ≤8 条，因果单句
  "characters": [                          // 本章出场人物事实
    { "name": "规范名", "aliases": ["别称"],
      "facts": [{ "t": "此后有效的事实单点", "ch": 12 }],   // ≤6 条/人
      "endState": "本章结束时的处境" }],    // ≤12 人/章
  "world": [                               // 本章出现的设定事实
    { "domain": "势力|地理|体系|规则|物品|其他",
      "name": "……", "facts": [{ "t": "……", "ch": 12 }] }], // ≤10 条目
  "foreshadow": [                          // 伏笔动作（六动作枚举）
    { "label": "伏笔线索名", "action": "plant|reinforce|misdirect|partial_reveal|reveal|payoff",
      "t": "发生了什么", "ch": 12 }],      // ≤6 条/章；无则空
  "style": [                               // ≤2 条：值得学的写法观察（观点句，不抄原文）
    { "t": "观察结论", "why": "好在哪里" }],
  "hook": "章末悬念一句话"                  // 可空
}
```

**knowledge（知识类：经管/科普/教程）**

```jsonc
{
  "v": 1, "profile": "knowledge",
  "summary": "……",                        // ≤500 字：本章回答什么问题、结论是什么
  "claims": [                              // ≤6 条核心论点
    { "t": "论点单句", "ch": 5,
      "evidence": ["论据/例证要点"],        // ≤3 条
      "kind": "主张|方法|框架|反例" }],
  "concepts": [                            // ≤10 条概念
    { "term": "术语", "definition": "本章给出的定义", "ch": 5,
      "refines": "若修正前文定义，写前文术语名" }],
  "methods": [                             // ≤4 条方法/步骤
    { "name": "方法名", "steps": ["步骤"], "ch": 5 }],
  "quotes": [                              // ≤2 条金句（逐字，≤120 字）+ 为什么值得摘
    { "t": "原文", "why": "……", "ch": 5 }]
}
```

**history（历史/传记）**：novel 与 knowledge 的混合裁剪——`summary/events(时间线向)/characters/world(制度·背景)/quotes`，无 `foreshadow`、无 `style`。

**规则**：
- 全部域可空（空数组合法）——过场章/纯理论章某域为空不算失败，覆盖账本记账（子设计三）。
- 校验链沿用 atomize 同款：响应提取 JSON → ajv 校验 → 错误清单回喂重试 1 次 → 仍失败本章卡标 failed（不阻断 base 遍）。
- `ch` 常量校验：任何事实的 `ch !== 本章 ordering` → 整卡拒收回喂（错误信息指明字段路径）。

## 3. 产线设计

### 3.1 挂载点：digestChapter 步骤 0

阅读卡作为章级基础遍的**第 0 步**（在 atomize 之前），同一章循环内完成，不另起文档级循环：

```
digestChapter(chapter):
  ensurePass(card)          → done-same-hash 跳过 / running 让位 / 耗尽按现有三态
  setRunning(card pass)
  ① 调 LLM 产卡（1 次调用）→ 校验 → 写 brain_card / brain_card_hash
  ② setDone(card pass, {domains: n}, cost)
  ③ 失败：非审核错误 → setFailed(card pass) 并**继续** base 遍（fail-soft）；
          审核拦截 → markExhausted（沿用封账语义），base 照走
  ensurePass(base) …（现状不变）
```

理由：复用现有章循环的进度上报/熔断/审核封账/串行纪律，card 与 base 同章共进退，台账各自独立互不阻塞。

### 3.2 调用规格

| 项 | 值 |
|---|---|
| 输入 | 书名+章号/总章数、本章标题、**正文全文（>12000 字截断，沿用现有章截断常量）**、已知实体规范名表（现有 knownEntityNames，防称呼漂移）、画像类型 |
| 输出上限 | maxTokens 4000 |
| 模型档位 | **adjudicate 高档**（待拍板项，总设计 §10——卡是全漏斗地基，错卡污染全链；只比摘要贵一档） |
| 幂等 | 台账 `passType='card', passKey='card', chapterHash`；重跑替换式重写 brain_card |
| 非叙事章 | 版权/简介等前置页跳过（复用 isNonNarrativeChapter），不产卡、台账 done 零产出 |

### 3.3 提示词要点（prompts/index.ts 新增 READING_CARD_SYSTEM 三变体 + 组装函数）

1. 角色设定：「为整书知识库做章级结构化笔记」，**不是**摘要器——每个域都有明确「收什么/不收什么」。
2. 事实纪律（直接继承 deepwrite 通读员要点并本地化）：只记原文出现的事实、每条带章号、推断标 `inferred`（novel 卡人物事实加此可选标）、伏笔只记**已发生的动作**（对后文的猜测不登记）、人物事实写「此后有效」的单点不写情节链（与 atomize v3 新书判据同语境但**不设换书测试门**——卡是证据层，书内事实合法，这是卡与论断的本质分工，必须在 prompt 里写清防止模型自我审查掉书内事实）。
3. 章号纪律：输入明确告知本章章号 N，要求所有 `ch=N`；schema 校验兜底。
4. 少样本：每画像 2 组正反例（从试点书实料取，评审前补）。

### 3.4 与章节摘要服务的处置

- 现有章节摘要服务**保留不动**（未启用大脑的库仍靠它供 UI/检索）。
- 大脑启用库的跳过（待拍板项，建议采纳）：摘要调度入口按 `digestion.enabled` 跳过；已生成的旧摘要保留作降级材料。
- **降级链**：消费方读卡 → 卡缺失 → 降级读 `chapter.summary`（600 字纯文本，按旧上限逻辑）→ 双缺则该章记覆盖缺口。

## 4. 消费方切换清单（V4-1 范围）

| 消费方 | 现状取材 | V4-1 切换后 |
|---|---|---|
| 全书概要（book-passes outline） | 章摘要 600 字，≤600 段均匀采样 | 卡 summary+events+hook；采样上限改为**预算配额**（按模型窗口装满为止，装不下按段均匀抽样并注明——完整版多级归并在 V4-3） |
| 目标提炼（goal-distill） | 章摘要分批 map | 卡分批 map：目标域相关的域字段优先（如「经典场面」目标吃 events+characters，「文风」目标吃 style），证据包组装器雏形 |
| 名册（V4-2） | — | 唯一原料（characters/world/concepts 域聚合） |
| 滚动阅读四件套 | 工作记忆 | **V4-1 不动**，V4-4 切换 |
| 分层补标/重判/冶炼 | 论断池/事件轨 | 不动 |

## 5. 存量补跑

- 已 digested 文档的章没有 card 台账 → 复用**场面补采模式**：新增 `backfillCards(kbId, {batch})`——按库遍历已消化文档章节，`ensurePass(card)` 后逐章产卡；每轮 ≤200 章、6h 冷却、成本熔断同口径，挂自动化（与场面补采同槽位顺序）。
- 内容重排（reprocess）的文档：章 hash 变化自然触发 card 重做（与 base 遍同机制），无需特殊处理。

## 6. 成本核算

| 项 | 估算 |
|---|---|
| 单章卡 | 输入 ≤12k 字（≈18k token）+ 提示词 ≈2k；输出 ≤4k token。**1 次调用/章** |
| 对照 | base 遍每章 1-2 窗 ×（1-2 次）调用；卡增加约 +50%~100% 章级调用 |
| 对冲 | 摘要跳过后每章 −1 次（摘要走宿主档，金额口径略降）；卡换来的上游收益是名册/归并全部**不再需要**为取材而重读正文（deepwrite 实测的平方级输入教训在此规避） |
| 熔断 | 与消化同口径（每日调用上限），自动化分日推进 |

## 7. 验收

1. 试点书（≥500 章）消化完成后：叙事章卡覆盖率 100%（空域合法），`brain_card_hash` 全量可校验；
2. 章号合法率：抽 200 卡人工+程序双检，`ch` 错误率 0（schema 拒收兜底的证明）；
3. 全书概要对照：同一本试点书，旧（摘要+600 段采样）vs 新（卡+预算配额）两版概要的事件完整性对照报告入档 docs/progress；
4. 成本对照：试点书消化前后（v3 vs V4-1）每章均次调用数入档；
5. 断点恢复：card 遍中途强杀重启，已完成章不重跑（台账幂等）、失败章可补。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 模型不守 schema（域乱放/编章号） | ajv+回喂重试；`ch` 常量校验整卡拒收；试点期统计首次通过率，<80% 则收紧提示词而非放宽 schema |
| 超长章截断丢卡信息 | 12000 字截断沿用（章内后 1/4 丢失可接受，覆盖账本对「截断章」打标，必要时后续按半章分片产双卡——预留 schema 的 `segment` 字段不首发） |
| 卡质量差污染全链 | 高档模型（待拍板）；审校回路（V4-4）专查「卡与上层产物不一致」；卡可单独重跑（台账独立） |
| 双写期不一致（卡与摘要并存） | 消费方统一走「卡→摘要→缺口」降级链，禁止直接读摘要的新调用点（code review 检查项） |
