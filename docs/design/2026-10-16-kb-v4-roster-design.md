## 1. 目标与定位

在「章卡齐备」与「书级归并」之间插入**名册阶段**，回答两个问题：

1. **谁是谁**：全书出现的人物/设定词/术语，哪些称呼指同一对象（别名归并）；
2. **谁重要**：每个对象在全书中的分量等级（分级），决定后续归并产物的建档粒度与取材顺序。

**定位澄清（防止过度设计）**：名册不是新实体系统——它是**实体池的一次整书级归并与分级升级**。章级流水线照旧 upsert 实体（mention 流不改）；名册在其上做事后归并（合并同书重复实体、补全别名）与分级（写权威名册），解决「人物册只取前 20 个实体、别名归并错误一路传导」的病根。

**参考来源**：deepwrite 名册阶段（程序聚合提及→模型分片裁决→程序确定性合并→人审→分级驱动整合）。两处刻意降级：人审从专门编辑器降为**收件箱名册卡**；`nameIndex` 程序推导改为**实体池外键承担**（本项目实体本就是规范对象，无需名册再建一层索引）。

## 2. 数据结构

### 2.1 权威数据：artifacts 工件快照

名册权威数据存 `kb_brain_artifacts`（`document_id` + `artifact_key='roster'`，表设计见总设计 §7）：

```jsonc
{
  "v": 1,
  "status": "auto | confirmed | dismissed",   // auto=自动定级；confirmed=人审接受；dismissed=人审忽略整册
  "characters": [
    { "entityId": "…",            // 归并后的实体 id（外键，程序维护）
      "name": "规范名", "aliases": ["…"],
      "tier": "protagonist | major | minor | passerby",
      "mentionChapters": 42,       // 出现章数（程序统计）
      "firstChapter": 3, "lastChapter": 812,
      "sampleFacts": ["来自卡的代表性事实 ≤3 条，带章号"],
      "tierReason": "定级理由一句话" } ],
  "terms": [
    { "entityId": "…", "name": "…", "aliases": ["…"],
      "category": "势力|地理|体系|物品|概念|其他",   // novel 取前五种；knowledge 术语册 category 自由归纳（≤8 类）
      "tier": "core | supporting | reference",      // knowledge/history 用三档
      "mentionChapters": 30, "firstChapter": 1,
      "sampleFacts": ["…"], "tierReason": "…" } ]
}
```

### 2.2 实体池回写（非规范化缓存 + 真归并）

名册裁决产生两类实体池副作用：

1. **真归并**：同书重复实体（「韩立」/「韩师兄」各自 upsert 过）→ 沿用**既有实体软合并机制**（品类归并同款：entity.merge + 论断挂点改指 + 边改指），程序执行、可追溯。**边界**：只并同书内、同名册组的实体；跨书归并仍归品类归并管（纪律不变：人物/地点/组织绝不跨书并）。
2. **分级缓存**：`attrs.roster = { docId, tier, order }` 写入实体 attrs（非规范化，供实体列表快捷展示）；**权威 tier 以 artifacts 快照为准**——多文档库中同一实体被两本书的名册定了不同级时，各自快照各自生效，消费方按「本书快照」取级，attrs 缓存只在单书库（实体论断集中于一书）时回写，避免互相覆盖。

### 2.3 人审载体：名册卡

- 新卡类型 `'roster'`，proposed 进收件箱。正文 = markdown 名册表（人物表：规范名/别名/级/出现章数/理由；术语表：规范名/类别/级/出现章数），头 description 写明「接受=采纳当前分级；结构修正（合并/改名/分级调整）请到实体管理界面操作后重跑名册」。
- **人审语义（诚实边界）**：接受 → 快照 `status='confirmed'`（定级生效，重跑不再降级覆盖用户确认）；拒绝 → 快照保持 `auto`，后续重跑仍可演进；**用户对卡正文的编辑不解析回写**（markdown 表格反解析不可靠，v1 明确不做）——结构修正的唯一入口是实体管理界面 + 重跑名册（重跑以实体池当前状态为归并基础，人工修正得以保留）。这条边界写进卡 description，用户预期不落空。

## 3. 产线设计

挂书级遍时段（文档消化收尾，base 遍之后、书级归并之前），台账 `passType='book', passKey='roster'`，chapterHash=本书全部章卡的联合指纹（任何一章卡重做→名册自动重算；`status='confirmed'` 时重算仅更新统计字段、**不覆盖人工确认的 tier**）。

```
① 聚合（程序，零 LLM）
   遍历本书全部章卡：characters[].name/aliases/facts 与 world[]（knowledge: concepts[]）
   → 按「规范名优先、别名跟随」聚成对象；统计出现章数/首末章/代表性事实
   → 与实体池对齐：名→既有实体 id（精确名+别名匹配）；未匹配的新名字建实体（复用 upsertMention）
   → 产出【提及清单】：每行 = 编号、域（人物/术语）、规范名、别名、章数、首现章、≤3 条示例事实

② 分片裁决（LLM，每分片 1 次调用）
   提及清单按证据预算（模型窗口×0.5，复用 deepwrite 证据包公式）切分片
   每分片一次调用，输出**决定**而非名册：
   { groups: [[编号…]]（同一对象的编号组，组内首号为规范名来源）,
     tiers: { 编号: tier 建议 + tierReason }（novel: 人物四档；knowledge: 术语三档）,
     categories: { 术语编号: 类别 } }
   纪律：拿不准不并（保持分开）、级别宁低勿高——错并比漏并危害大（沿用品类归并协议）

③ 程序确定性合并（零 LLM）
   分片内 groups 直接并；跨片重复：程序先按规范名/别名精确归并，
   剩余「跨片疑似同对象候选簇」（同域、名相似或共享别名）单独一次调用终审——只判这少量簇

④ 定级校准（程序规则 + 已有 LLM 输出）
   程序兜底规则：出场 <3 章 → 至多 minor；主角判定必须有 ≥30% 章覆盖且 tierReason 含证据
   → 写 artifacts 快照（status='auto'）+ 实体软合并 + attrs 缓存

⑤ 名册卡进收件箱（proposed 'roster'）
   同题卡已存在且 proposed → 更新正文演进；已 confirmed 的库 → 卡直接 published（不再打扰）
```

### 3.2 与现有产线的关系

| 现有产线 | 关系 |
|---|---|
| 章级 mention→实体 upsert | **不改**（名册是事后归并，不阻塞消化主链） |
| 实体摘要演化 | 名册归并后触发受影响实体摘要重算（挂点变了） |
| 品类归并（跨书） | 顺序：名册（书内）→ 品类归并（跨书）；品类归并的候选构建改读名册快照的规范名，减少跨书误并 |
| 视角遍/论断裁决 | 不动 |

## 4. 消费方按级取材（V4-2 落地部分）

| 消费方 | 现状 | 接名册后 |
|---|---|---|
| 人物册卡 | 实体池前 20 人物 × 3 论断 | **主角/主要配角：全部建档**（V4-3 升级为卷小传合并）；次要：群像卡一组 ≤10 人；路人：只列名。取材原料从论断换成卡人物域事实 |
| 设定索引卡 | setting 论断 ≤200 条 + 实体前 30 | 按名册类别逐类取材（V4-3 拆成设定档案），类别内**无数量上限**（预算配额） |
| 关系图谱（四件套） | 工作记忆抽取 | V4-4 切换：名册提供参与者规范名全集，图谱抽边只对 major 以上 + 术语 core 建档对象进行 |
| 体系汇聚（v3） | setting-system 实体 | 取材改读名册 terms 的体系类（对齐 v3 方向） |

## 5. 成本

| 项 | 估算 |
|---|---|
| 聚合/合并/回写 | 0 次调用（纯程序） |
| 分片裁决 | ceil(提及清单体积 / 预算) 次；千章书典型 80-200 个名字对象 ≈ 2-5 次调用 |
| 跨片终审 | 0-1 次 |
| 重算频率 | 仅章卡指纹变化时；confirmed 后不重覆盖 |
| 对照 | 一次性成本 ≈ 3-6 次高档调用/书，远低于任何一轮书级遍 |

## 6. 验收

1. 试点书名册卡进收件箱，人物表/术语表完整；「前 N 个实体」截断在人物册/设定索引中消失（代码层断言：取材处不再有硬 limit）；
2. 别名归并质量：人工抽查 30 组归并决定，错误并 ≤1（宁缺勿造口径）；
3. 分级合理性：主角/主要配角名单与人工常识对照（试点书主配角显然入选）；
4. 幂等：重跑名册，confirmed 快照的 tier 不被覆盖；章卡重做后统计字段更新；
5. 软合并安全性：归并后论断挂点/边改指无死链（复用品类归并的既有测试）。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 归并错误传导（错并两人） | 拿不准不并；软合并可逆（target_entity_id 留痕）；审校回路（V4-4）查「人物档案与卡事实矛盾」 |
| 分级失准（主角被判次要） | 程序兜底规则（覆盖率门槛）+ tierReason 必填 + 人审一道门；分级只影响建档粒度，错级损失=档案粗而非知识错 |
| 多文档库实体缓存冲突 | 权威在本书快照；attrs 缓存仅单书库回写（§2.2） |
| 大部头提及清单超大（人物 ≤5000 上限） | 分片天然承载；超上限按章数排序截断、剩余建 passerby 并在名册卡注明（覆盖账本可见） |
