# V4 详细设计三：书级多级归并产线（编年段→卷→书 + 证据包 + 覆盖账本 + 审校回路）

- 日期：2026-10-16
- 上级设计：`2026-10-16-knowledge-brain-v4-whole-book-funnel-design.md`（§4 方案 A3/A4/B5/B6/B7，阶段 V4-3 与 V4-4）
- 前置：阅读卡（子设计一）、名册（子设计二）
- 复杂度评估：**中高**（新归并产线 + 四类书级卡改造 + 程序记账 + 审校修复回路；无新模型能力，重在产线编排）

---

## 1. 目标与定位

把书级知识生产从「**论断池抽样拼卡**」（设定索引 ≤200 条、人物册 20 人×3 条、伏笔台账 ≤80 条、概要 600 章采样）改造为「**从漏斗上层逐级归并**」：

```
章卡（全量，子设计一）
  → 编年段（按证据预算分段，段内归纳：剧情点/论点链）      ← 过程产物（artifacts）
    → 卷梗概（段归并，不跨卷）                             ← 过程产物（artifacts）
      → 全书主线 / 人物档案 / 设定档案 / 伏笔线 / 知识体系图 / 文风画像   ← 知识卡（成品）
```

配套四件事：
- **证据包组装器**：一切书级取材改为程序按预算组装（硬上限退役）；
- **覆盖账本**：每章被漏斗各层覆盖的情况由程序记账，缺口可见、可自动补跑；
- **审校修复回路**：成品卡分领域交叉核对，问题带章号，自动修复一轮；
- **伏笔线**：从「悬置点清单」升级为「带六动作节拍链的线」。

**明确不做**：不做 deepwrite 的连续性账本/批次提交（无续写重建目标）；不引入并行执行（阶段四可选，见总设计 §4 B8）。

## 2. 归并链设计

### 2.1 编年段切分（纯函数，零 LLM）

输入本书全部章卡（按 ordering 排序），输出段列表：

- **切分预算**：单段输入预算 =（归并模型窗口 − 输出预留 8k − 提示词）× 0.5（证据包公式，与名册分片同源）；段大小按卡体量估算（每章卡 ≈ 摘要 500 字 + 事件/事实按条数折算，保守 1500 字/章）。
- **不跨卷**：卷边界取章表 `parent_title`/`level` 层级；无层级结构的书按纯预算切。
- **knowledge 画像变体**：段优先按**目录层级**（篇/章组）聚合主题，预算只作上限——论证段的语义是「主题章节组」而非时间序（总设计 §6.2）。
- 段 id：`chronicle:<n>`；切分结果写入消化状态（重算仅当章卡集合指纹或模型窗口变化）。

### 2.2 单元依赖图（拓扑序，串行执行）

| 单元（台账 passKey） | 输入（证据包） | 输出（artifacts） | 依赖 |
|---|---|---|---|
| `chronicle:<n>` | 段内全部章卡（全字段） | 段梗概 + 剧情点（novel：`{title, startCh, endCh, cause}`）或论点链（knowledge：`{claim, evidence[], ch}`） | 章卡 |
| `volume:<卷名>` | 该卷全部段梗概+剧情点 | 卷梗概（≤800 字）+ 卷级转折 | 该卷 chronicle:* |
| `plot:mainline` | 全部卷梗概（+段剧情点索引） | 全书主线（主角目标/阻力/转折/阶段结果）+ 核心梗 | 全部 volume:*（无卷书直接挂 chronicle:*） |
| `character:<entityId>` | 该人物名册条目 + 其卡事实全集按卷分组 | 卷小传（多卷人物先按卷）→ 人物档案卡 | 名册 |
| `world:<category>` | 该类别名册条目 + 卡设定事实全集 | 设定档案卡（类别概览+条目，冲突说法并列带章号） | 名册 |
| `foreshadow` | 全书卡伏笔动作 | 伏笔线卡（§2.4） | 章卡 |
| `style` | 卡 style 域 + 程序抽样原文 | 文风画像卡 | 章卡 |
| `knowledge-map`（knowledge） | 概念论点链 + 术语名册 | 知识体系图卡（树文本；实体树仍走 v3 体系汇聚产线） | chronicle:* |
| `review:<domain>` | 见 §5 | 审校报告（artifacts）+ 修复重跑 | 对应成品 |

执行纪律：单元全部有台账（`passType='book'`，`chapterHash`=其输入指纹——输入 artifacts 或卡集合变化自动重跑）；单单元失败 fail-soft 不挡后续（沿用书级遍现状）；全部过程产物写 `kb_brain_artifacts`，成品才进知识卡（proposed/直发按 §6）。

### 2.3 证据包组装器（B7，全产线统一取材入口）

替换现有 `MATERIAL_ATOM_CAP=200 / FORESHADOW_CAP=80 / ROSTER_CHAR_CAP=20` 等硬上限：

```
assembleEvidence(sections[], budget):
  1. 各 section 按优先级（主题相关度 > 时间跨度均匀）分配配额
  2. 装不下：按均匀步长抽样并注明「已按 1/N 抽样」（保跨度不截头，deepwrite 同款）
  3. 永不静默丢弃：被抽样的 section 记入覆盖账本（§4）
```

- 预算按消费方模型窗口计算（书级归并走 adjudicate 档）；
- 论断池（atoms）降级为**补充证据**：成品卡以卡/名册/段为主料，检索命中的相关论断按预算追加（沿用 brain-query 检索，不再作为唯一取材）。

### 2.4 伏笔线（A3）

- **聚线（程序）**：章卡伏笔动作按 `label` 精确+别名聚合（同名先聚）；剩余「疑似同线」候选簇（label 相似度/共享人物）一次 LLM 调用校准——协议与名册归并一致（拿不准不并）。
- **成线**：每条线 = `{ label, coreQuestion（核心悬念，聚线后一次小调用归纳或取自首埋注记）, status: open|partial|resolved（由动作推导：出现 reveal/payoff 即 resolved）, beats: [{action, ch, note}]（按章序）}`。
- **产物**：`foreshadow-ledger` 卡升级为线列表（渲染：每线一节，节拍链表格式）；被「已回收」线与 open-question 论断的对应关系保留（回收动作章号回写悬置点论断状态，供既有伏笔扫描/边候选继续工作）。
- **事后扫描兜底**：现有伏笔扫描保留——漏登记的伏笔仍由扫描补充候选（人审），双通道互补。

## 3. 书级卡改造明细

| 卡 | 现状 | 改造后 |
|---|---|---|
| 全书概要 `book-outline` | 章摘要一级 map-reduce，≤600 段采样 | 消费卷梗概（无卷则段梗概）归并；主线/转折/阶段结构必填；**多级** |
| 人物册 `character-roster` | 前 20 实体×3 论断合传 | 变为**次要配角群像**（一组 ≤10 人小节）；主角/主要配角迁出为独立人物档案卡 `character-dossier`（每人一卡：一句话简介/核心特征/关系/最新状态/经历时间线——稳定特征与变化分写；多卷人物先卷小传 artifacts 再合并，档案引用小传） |
| 设定索引 `setting-index` | setting 论断 ≤200 + 实体前 30 归类 | 变为**索引卡**（类别清单+一句话概览）；每类别另出设定档案卡 `setting-dossier`（概览+条目+冲突并列，无条目上限、证据包预算） |
| 伏笔台账 `foreshadow-ledger` | 悬置点论断 ≤80 清单 | 线列表（§2.4） |
| 知识体系图 `knowledge-map` | setting/craft 论断 ≤200 | 消费论点链+术语名册；树文本渲染；与 v3 体系汇聚共享树存储 |
| 文风画像 `style-profile`（novel 新增） | 无（散在综述） | 卡 style 域聚合 + 程序确定性抽样（首章/每卷末/全书中点各 ≤300 字原文）配点评 |

兼容语义：全部沿用现有同题卡处置（proposed 同题→正文演进；published/archived→不覆盖）。画像切换参与书级指纹（总设计 §7）——画像变更自动重汇总对应关卡。

## 4. 覆盖账本（B5）

**程序推导，零 LLM**。每次书级遍收尾时重算，存 artifact `'coverage'`：

```jsonc
{
  "chapters": { "总章数": 1024, "有卡": 1020, "入段": 1018, "入卷": 1018, "名字全归属": 1015 },
  "gaps": [
    { "ch": 233, "kind": "card-missing | segment-uncovered | name-unassigned | foreshadow-orphan",
      "detail": "…" } ],
  "sampling": [ { "unit": "plot:mainline", "note": "段梗概按 1/2 抽样" } ],
  "updatedAt": "…"
}
```

- 缺口驱动补跑：`card-missing` → card 遍 pending；`name-unassigned` → 名册重算；`segment-uncovered` → 编年段重切——全部走既有 ensurePass 幂等，自动化巡检天然消化（无需新动作类型，health 服务读账本即可见收敛情况）。
- 展示：V4-3 先接 health 服务数据接口（面板 UI 呈现放后期 UI 收敛一并做，遵守零点击与 UI 收敛方向）；缺口数超阈值时打一条告警日志（沿用漂移告警通道，v3 已把它升级为收件箱卡）。

## 5. 审校修复回路（B6，阶段 V4-4）

- **领域**：novel：人物/设定/剧情/文风；knowledge：概念/论证/方法；history：人物/时序/制度。
- **审校单元**（`passKey='review:<domain>'`）：证据包 = 该领域全部成品卡 + 名册摘要 + 相关段梗概抽样 + 随机抽 3 章原卡（供交叉核对）；任务=查**上层产物与卡/名册的矛盾**（人物档案与卡事实冲突、设定前后不一、主线阶段与剧情点错位、伏笔状态与节拍链矛盾、概念定义与论点链冲突），每个问题必须给 `chapterOrders[]` 证据章号 + 修复建议 + 定位到成品单元。
- **修复**：问题按 `unitKey` 分组 → 对应成品单元强制失效重跑（台账 hash 拼入 issue 摘要→指纹变化自动放行），重跑时证据包末尾附审校意见（deepwrite 同款）。**一轮修复，不递归**；仍未解决的记入报告留档。
- **报告**：artifact `'review:<domain>'`；问题数 >5 时收件箱一张审校摘要卡（用户可见但不强制操作——修复已自动完成，卡是知情而非待办）。

## 6. 产物审批

沿用 v3 拍板 B：**带证据密度门槛直发 published + undo**，低置信进收件箱。门槛统一为：卡内每条实质结论可追溯到 ≥1 个章号证据、且证据密度 ≥ 每千字 1 条（归并产物天然满足；不满足=证据包退化了，进收件箱）。名册卡例外（永远 proposed，见子设计二）。

## 7. 自动化接入

| 动作 | 槽位 | 冷却 |
|---|---|---|
| 编年段/卷/书归并 | 消化收尾（现状 bookPasses 时段），台账幂等 | 随消化；书级指纹不变不重跑 |
| 覆盖记账 | 每轮书级遍收尾 | 零成本随跑 |
| 审校修复 | automation 新步骤 | 24h（修复重跑不加冷却——它是ensurePass 放行） |
| 卡补跑 | 复用场面补采槽位（子设计一 §5） | 6h |
| 名册重算 | 章卡指纹变化触发 | 随消化 |

## 8. 成本核算（千章书，单轮全量）

| 单元 | 调用数 |
|---|---|
| 编年段（≈30-50 段） | 30-50 |
| 卷梗概（≈3-10 卷） | 3-10 |
| 主线/伏笔聚线/文风 | ≈5 |
| 人物档案（主角+主要配角 ≈5-15 人，多卷小传 ×2 级） | 10-40 |
| 设定档案（类别 ≈5-8） | 5-8 |
| 审校（4 领域）+ 修复 | 4-12 |
| **合计** | **≈60-125 次高档调用/书/轮**（对照：章级 base+card 每轮 ≈2000-3000 次低档——书级占比小，收益集中） |

## 9. 验收

1. 大部头试点（≥1000 章）：全书主线可下钻（主线→卷→段→章卡逐级可溯源）；设定档案无 200 条上限（条目数由名册与卡决定，对照旧卡条目数入档）；
2. 伏笔线：试点书伏笔线数量与已知悬置点对照，节拍链章号抽查正确率 ≥90%；回收状态与正文一致；
3. 覆盖账本：人为抽掉 5 章卡 → 缺口可见 → 自动补跑收敛（自动化挂机验证）；
4. 审校回路：注入 3 处成品-卡片矛盾 → 审校全报出且带章号 → 修复重跑后复检通过；
5. 旧对照：同书新旧两版「设定索引/人物册」信息量对照报告入档 docs/progress（沿用 V4-1 验收尺）；
6. 幂等：中途强杀重启，单元台账续跑、artifacts 不丢不重。

## 10. 风险

| 风险 | 缓解 |
|---|---|
| 多级误差累积（段错→卷错→书错） | 逐级带章号证据可下钻；审校专查上下层矛盾；宁缺勿造 |
| 归并产物同质化（每段梗概像流水账） | 段提示词以「因果/论点链」为纲（deepwrite 编年员要点）；验收对照真实章节抽查剧情点质量 |
| artifacts 与卡双源不一致 | 单向依赖：卡→artifacts→成品卡；覆盖账本每轮校验上游指纹 |
| 修复回路震荡（修了又坏） | 一轮修复封顶；审校 24h 冷却；同一单元连续 2 轮被报问题 → 告警卡并停修（防烧钱循环） |
| 卷结构与目录层级缺失的书 | 无层级按纯预算切段，卷级归并自动跳过（主线直挂段） |
| 千章书归并时长（60-125 次高档调用串行） | 自动化分日推进；阶段四并发可选；覆盖账本暴露进度 |
