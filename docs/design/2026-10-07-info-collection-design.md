## 0. 结论摘要

一句话方案：

> **新建 `info-collection`（信息搜集）功能包：以"采集蓝图"为通用模型的搜集管线，内容经"抽取→复核→整理→人审"后写入知识库（复用既有切块/嵌入/BM25/检索消费面），过程治理（审阅状态/去重簇/刷新游标/质量台账）落在五张轻量 `ic_` 过程表。质量不是附带章节，而是管线的每个阶段都有硬闸门。**

四条设计原则：

1. **通用性**：模块不认识"人口""政策"这些具体领域。任何主题走同一条管线；领域差异全部体现在**采集蓝图**（AI 按主题起草、用户确认的规格文件：信息需求清单 + 抽取 schema + 信源策略 + 整理规格 + 判停规则）里。蓝图本身是通用产物，三个示例主题只是 M1 验收用例。
2. **知识库是内容的家**：清洗后的正文、整理产出、数据表文档全部落 kb，走既有向量化与混合检索；chat / topic-research（kbs 选项）/ 长文 context / kb-brain 等**既有消费方零改造即可用**。模块自建表只存过程治理数据，不复制内容。
3. **质量是一等公民，且必须可度量**：引用锚定、双模型复核、转载簇识别、冲突归因、孤证标记、证据链反查——每项措施都对应一个可统计的指标；模块价值用**评测集 + 基线对照**证明（无评测不进实现，照飞轮 M0 硬门槛）。
4. **先规格后采集，AI 起步人审关门**：AI 采集/整理的一切产出进待审区，用户确认才入知识库（全项目 dl_plan / kb 提议箱 / human-review 既有模式）。

## 1. 什么叫"流于表面"——本设计逐条防的六个反面形态

| 反面形态（常见"完成任务式"搜集） | 本设计的防线 | 落在哪个阶段 |
|------|------|------|
| 给一堆链接就算"搜集完了"，正文没存、页面失效全丢 | 抓取后**先落快照再解析**，快照与条目绑定 | 阶段 2 |
| 搜索引擎第一页照搬，二手转述当一手信源 | 一手来源优先 + **转载簇识别**（内容指纹聚簇，只认主源）+ 分级下限硬过滤 | 阶段 1/3 |
| 数字看不出处，模型抄错/编造数无人知道 | **引文锚定**（每条数据必须带原文引句且回验）+ 第二模型逐条复核 | 阶段 4 |
| 两个来源数字打架，简单标"冲突"了事 | **冲突归因**（时间不同/口径不同/修订版/真矛盾四分类），归因后才决定合并还是待审 | 阶段 5 |
| 整理稿是"看起来全面"的复读机，无法核查 | 整理稿**每个结论可反查**（结论→引句→快照三层链），第二模型审覆盖度与忠实性，出**质量报告** | 阶段 5 |
| 模块好不好用说不清 | 过程指标仪表 + **评测集与基线对照**（资料库辅助 vs 现搜现答） | §4.3/4.4 |

## 2. 核心模型

### 2.1 概念层级（通用，无领域假设）

```
搜集项目 Project（一个长期资料分区，如任意主题）
 ├─ 采集蓝图 Blueprint（v1）——主题的通用规格文件，AI 起草、人确认，可修订升版
 │    ├─ 信息需求清单 IR[]（原子化、可判定满足与否）
 │    ├─ 抽取规格（每条 IR 可附 JSON schema；无 schema 默认"引文卡"）
 │    ├─ 信源策略（渠道矩阵/分级下限/语言地域/查询种子/一手机会点）
 │    ├─ 整理规格（产出物清单及其字段定义）
 │    └─ 判停规则（覆盖率目标/边际收益/硬预算）
 └─ 搜集任务 Task（一次蓝图执行，可重复运行 = 增量刷新）
      ├─ 执行台账 Passes（幂等重跑）
      ├─ 源记录 Source（每个 URL 的抓取/评估/去重/入库状态）
      │    └─ 原文快照（dataPath，先存后解析）
      ├─ 结构化行 Row（按蓝图 schema 抽取的数据行，可空）
      └─ 整理产出（kb 文档：要点卡/数据表/时间线/引用清单/质量报告）
入库：kb_documents / kb_chunks / 向量 / BM25（全部既有管线）
```

### 2.2 采集蓝图（Blueprint）——通用性的承载物

```ts
interface IcBlueprint {
  version: number
  goal: string                       // 主题与边界（时间/地域/语言/口径假设显式列出）
  assumptions: string[]              // 未澄清的假设必须显式声明，禁止静默假设
  requirements: IcRequirement[]      // 信息需求清单（原子化）
  sourceStrategy: {
    channels: Array<'search'|'info-source'|'url'|'kb'|'manual'>
    minTier: 1|2|3|4                 // 信源分级下限（分级体系沿用 topic-research v5 四级）
    languages: string[]              // 查询与取材语言（默认中文主题也扫英文源）
    seedQueries: string[]            // 查询词种子（AI 起草：同义扩展/中英双语/不同切入角度）
    primaryHint: string[]            // 一手来源机会点（权威域名/机构/原始出版物提示）
  }
  stopRules: {
    coverageTarget: number           // IR 满足率目标（如 ≥0.8）
    minIndependentSources: number    // 关键需求最少独立源数（默认 2）
    marginalRounds: number           // 连续 N 轮无新 IR 满足即停（默认 2）
    budget: { maxToolCalls: number; maxMinutes: number }  // 默认 300 / 120，对齐 topic-research
  }
  organizationSpec: IcDeliverable[]  // 整理规格（§2.3）
  autoConfirm: boolean               // 低风险自动确认，默认 false
}

interface IcRequirement {
  id: string                         // "R1"、"R2"…
  question: string                   // "该指标 2015-2024 年逐年数值及口径"
  form: 'data'|'fact'|'document'|'opinion'|'case'  // 需求形态（仅决定默认抽取模板，可覆盖）
  priority: 'must'|'should'|'nice'
  schemaId?: string                  // 指向 blueprint.schemas 中的 JSON schema
  timeWindow?: { from?: string; to?: string }
  tierFloor?: 1|2|3|4                // 覆盖 sourceStrategy.minTier
}

schemas?: Array<{ id, title, jsonSchema,      // 抽取 schema（ajv 校验），任意主题自定义
                 convention?, checks? }>      // convention: measure 约定列映射；checks: 跨行恒等式校验（存储设计 §3/§5）
```

**预置抽取模板库（仅是起点，蓝图可改可弃）**：`data`（指标/值/单位/时间/地域/口径）、`fact`（论断/语境）、`document`（题名/发布者/日期/文号/效力状态/关键条款）、`opinion`（观点/持有者/场合）、`case`（主体/事件/结果/启示）。模板解决 80% 常见形态，剩余 20% 由 AI 按 IR 起草自定义 schema——**模板是素材，不是功能边界**。

**整理规格（IcDeliverable）**：`summary-cards`（要点卡：结论+证据链）、`data-table`（数据表：行级溯源）、`timeline`、`comparison-matrix`、`source-list`（引用清单：链接+访问日期+分级）。同样可按主题增删定义。

### 2.3 数据落点：内容在 kb，过程在 `ic_` 表

**为什么不是零表**：纯 kb 无法承载过程治理——一条来源处于待审还是已入库、属于哪个任务、和谁构成转载簇、刷新游标到哪——这些字段 kb_documents 不该背。所以：**正文与整理产出落 kb（唯一内容存储），`ic_` 表只存过程元数据**（v1 设计中 items 表的 text_content/summary 等内容字段全部删除）。

```sql
-- ① 搜集项目
ic_projects(id, user_id, name, goal, blueprint_json, blueprint_version,
            kb_id /*对应知识库*/, refresh_policy_json /*{mode:'manual'|'cron',cron?}*/,
            status /*active|archived*/, created_at, updated_at)

-- ② 任务（一次蓝图执行）
ic_tasks(id, user_id, project_id, blueprint_version, run_id /*工作流运行*/,
         status /*pending|running|reviewing|done|failed|cancelled*/,
         stats_json /*IR覆盖率/源数/工具调用/成本*/, created_at, finished_at)

-- ③ 执行台账（幂等重跑，照搬 kb_digest_passes：唯一键(task_id,pass_key)+MAX_ATTEMPTS+人工复活）
ic_task_passes(id, task_id, pass_key, attempt, status, stats_json, cost_json,
               started_at, finished_at)

-- ④ 源记录（过程心脏：一个 URL 一行）
ic_sources(id, user_id, project_id, task_id,
  url, url_normalized /*去 tracking 参数*/,
  tier, tier_rationale /*为什么定这个级*/, is_primary /*转载簇主源*/,
  cluster_id /*转载/同文簇*/, published_at, collected_at,
  snapshot_path, content_hash, text_fingerprint /*正文指纹，簇判定用*/,
  fetch_status /*ok|partial|failed|blocked*/,
  review_status /*staged|confirmed|rejected|merged*/,
  kb_document_id /*入库后的 kb 文档*/, ir_hits_json /*该源满足了哪些 IR*/,
  created_at, updated_at)

-- ⑤ 结构化行（蓝图 schema 定义的任意字段，行级溯源；row_json 为行的全量唯一权威）
ic_rows(id, user_id, project_id, task_id, source_id, schema_id,
        row_json,                                        -- 全量数据字段（任意形状兜底）
        value NUMERIC, unit, period, metric, dims_json,  -- measure 约定列（可空；归一化器从 row_json 派生的可计算投影）
        quote /*引文锚*/, confidence /*high|low*/,
        status /*draft|confirmed|superseded|stale*/, superseded_by,
        content_hash, created_at, updated_at)
-- 存储选型论证（为何不是文档/不是物理表）、约定列、宽表归一、恒等式校验
-- 详见 docs/design/2026-10-07-info-collection-storage-design.md
```

索引：`(user_id, project_id, review_status)`、`url_normalized`、`cluster_id`、`(schema_id, content_hash)`。**多租户全部走 BaseRepository 的 ALS scoped**，新增表强制跨用户隔离单测（飞轮 §11.5-8 教训）。

**kb 侧落库规范**（复用既有表与管线，不改 kb 模型；若 kb_documents 缺元数据列，实施时以标签/扩展字段承载，不轻动共享表）：

- 每个搜集项目 = 一个知识库（自动创建，标记 `origin=info-collection`），天然获得：kb 全文/向量混合检索、topic-research 的 `kbs` 挂载选项、kb-brain 可选消化、kb 面板管理。
- **每源一文档**：清洗后正文 + 文档头（来源 URL/标题/分级/发布时间/采集时间/项目与 IR 标签）+ 引句锚点。既有 kb 管线切块、嵌入、倒排——**向量化零新代码**。
- 整理产出（要点卡/数据表/时间线/引用清单/质量报告）各为一份 kb 文档，与源文档同库。**数据表文档是"表说明页"投影**（口径/单位约定/来源构成/头部样例行/关键聚合值），封顶渲染——大表不整表切块入 kb（污染检索），全量数据走查表工具与导出（存储设计 §6）。

## 3. 管线全流程（八个阶段，逐步详述）

> 图：澄清 → 蓝图 → 检索获取 → 提取评估 → 抽取复核 → 裁决整理 → 人审入库 → 刷新时效
> 每阶段写明：目的 / 输入 / 处理步骤 / 质量闸门（不过闸怎么办）/ 产出。

### 发起模式（v3 修订：快速为默认，蓝图不设硬门槛）

| | **快速搜集（默认）** | **精调搜集（可选）** |
|--|--|--|
| 入口 | 输入主题，直接开跑（UI 一键 / `ic_collect` 工具 / 应用模板） | 输入主题 → 澄清问答 → 蓝图确认 → 开跑 |
| 蓝图 | AI 数秒内对当前主题现场起草，自检通过**自动确认即锁**，用户无需查看 | AI 起草 → 用户确认（可修改）后锁定 |
| 澄清包 | 全部按默认假设执行，假设清单随产出报告展示 | 用户逐条回答或采纳默认 |
| 适用 | 任意主题随手搜集（**通用性的主入口**） | 重要 / 高成本 / 口径敏感的搜集 |

**蓝图不是预制配置，是运行时对当前主题现场生成的计划**——换主题即换蓝图，代码零领域逻辑。任何采集都必然有隐含计划（搜什么词、抽什么字段、何时停、花多少预算）：蓝图只是把这份必然存在的计划从"AI 脑子里不可见的一段话"变成"可检查、可重跑的结构"。快速模式下它在后台自动生成与锁定，任务详情中可展开复核；只有精调模式才前置为确认门槛。

### 阶段 0：需求澄清

- **目的**：把一句话主题变成无歧义的搜集边界。质量事故的大头是"口径没对齐"（统计口径、时间范围、地域范围），必须在花钱采集前钉死。
- **输入**：用户主题描述（一句话或一段话）。
- **处理**：LLM 产出**澄清包**——≤5 个选择题式问题（口径/范围/时间窗/用途），每问附默认假设。用户可逐条回答或一键"按假设执行"。
- **质量闸门**：**禁止静默假设**。任何未被用户确认的口径必须显式写入蓝图 `assumptions`，并在后续整理稿中随结论展示（"以下数值按常住人口口径"）。抽查规则：蓝图起草时检查 `assumptions` 为空且主题含歧义信号（多义指标名/无时间范围）→ 打回重起草。
- **产出**：需求备忘（澄清问答记录 + 假设清单），进入蓝图 `goal/assumptions`。

### 阶段 1：采集蓝图起草与确认

- **目的**：先规格后采集。蓝图质量决定一切后续质量——这是整个模块最重要的单点。
- **输入**：需求备忘。
- **处理**：
  1. **IR 原子化**：主题拆成可独立判定"满足/不满足"的信息需求；每条标形态/优先级/时效窗/信源下限。拆分纪律：一条 IR 只问一件事（"近 10 年政策清单"应拆为"发布清单"与"效力状态"两条，因为满足路径不同）。
  2. **抽取 schema 起草**：按需求形态选预置模板或起草自定义 schema；**自检字段可得上性**（网页上真能抽到的字段才允许出现，如"政策效力状态"若多数页面不标则降级为人工标注字段）。
  3. **信源策略**：查询词种子（同义扩展、中英双语、不同角度——机构视角/数据视角/事件视角）；一手机会点（该主题下应优先直取的权威站点/出版物类型）；分级下限（默认 must 级 IR=1，should=2）。
  4. **整理规格**：与用户确认要什么产出物（默认：要点卡 + 引用清单；数据类需求加数据表）。
  5. **判停规则**：覆盖率目标、独立源下限、边际轮次、预算。
- **蓝图的可得上性定位**：可得上性自检是启发式，真正的可得性只有执行能证实——蓝图是假设不是承诺。因此 stopRules 的覆盖率目标 <100%、每 IR 设检索努力上限、负结果处置（阶段 4-4）与蓝图 v2 修订机制共同构成"找不到"的完整出路。
- **质量闸门**：**蓝图自检清单**（全部程序化检查，不过不允许执行）——①每条 IR 可判定满足与否；②每条 IR 至少映射到一条种子查询；③schema 字段均可得上；④must 级 IR 有 minIndependentSources≥2；⑤预算与 IR 数量匹配（每 IR 至少预留 N 次工具调用）。自检通过后：**快速模式自动确认即锁**（未确认的假设全部显式入 assumptions，随产出报告展示）；精调模式人审确认后锁。确认即锁（执行期间蓝图版本不变，改蓝图=新版本=允许重跑）。
- **产出**：`blueprint v1`（confirmed）。

### 阶段 2：检索与获取

- **目的**：按信源策略拿到候选页面，**先保命（快照）再解析**。
- **输入**：蓝图信源策略。
- **处理**：
  1. **查询执行**：多引擎并行（12 引擎按配置路由）；每轮查询记录**查询日志**（query → 命中数 → 哪些 URL 进入候选、哪些被过滤及原因）——查询日志是可诊断性的前提，飞轮教训：没有 query 日志就说不清质量。
  2. **候选过滤**：URL 规范化（去 tracking 参数、统一协议/域名）；黑名单过滤（域名信誉 + 内容农场启发式信号：标题党模式/正文短而广告密）；**增量跳过**（url_normalized 已在 ic_sources 且 fetch_status=ok 的跳过，除非刷新策略要求重访）。
  3. **抓取**：politeFetch（超时/限长/重试分类：网络错误可重试、403/429 记 blocked 不硬撞）；**抓到即落快照**（单文件 HTML + markdown 双格式，web-collect 同款），快照先行于一切解析——页面日后失效/反爬升级都不影响已采内容。
  4. **动态页处理**：检测到 JS 渲染墙（正文提取过短/骨架页特征）→ 标记 `blocked/needs-manual`，进"手动导入建议清单"，不引入浏览器自动化。
- **质量闸门**：抓取成功率 < 60% 时任务暂停并报告（可能渠道配置错误而非网页问题）；blocked 源占比过高时提示用户调整信源策略。
- **产出**：源记录（staged）+ 快照文件 + 查询日志。

### 阶段 3：正文提取与源评估

- **目的**：把 HTML 变成干净正文，并对"这个源本身可不可信"给出有依据的评估——信源质量是搜集质量的地基。
- **输入**：快照。
- **处理**：
  1. **正文提取**：web-extract + html-to-markdown；乱码/编码检测；正文长度异常检测（<300 字标记疑似反爬墙或骨架页，转人工）。
  2. **发布时间提取**：页面元信息 + 正文日期模式；**提取不到发布时间的源标 `time-unknown`**（时效性降权：不得用于"最新数据"类 IR 的唯一依据）。
  3. **分级评估**：按四级体系定级，**必须写 tier_rationale**（依据：机构性质/域名属性/署名/内容特征），不允许裸定级；用户可在审阅时改级（改级留痕）。
  4. **转载簇识别**：正文指纹（分段 shingle 哈希采样）聚类；同簇内按"发布时间最早 + 等级最高"选**主源**，其余标佐证源。一手优先原则的执行点：后续若发现同事实的更高级一手源，主源**升级**而非并排堆放。
  5. **利益立场提示**：LLM 判断源与主题的利益相关性（企业白皮书谈自家行业 = 相关方源），写入 tier_rationale 供整理时参考（相关方源不得作孤证）。
- **质量闸门**：无 rationale 的定级不允许入库；`time-unknown` 源不得满足带时效窗的 must IR。
- **产出**：干净正文 + 源评估卡（tier/rationale/cluster/时间/立场）。

### 阶段 4：信息抽取与复核（网页 → 结构化条目）

- **目的**：从正文抽出蓝图 schema 要求的条目，**防幻觉是此阶段的第一目标**。
- **输入**：干净正文 + 蓝图 IR/schema。
- **处理**：
  1. **引文锚定抽取**：每条抽取必须携带 `quote`（原文片段，字符级）；系统**回验** quote 确实存在于正文（归一化包含匹配，失败降级模糊匹配 ≥0.9，再失败**拒收**）——这是防编造的硬机制，抽取值找不到原文就是幻觉。
  2. **归一化**：单位换算统一、日期规范化、地名/机构名规范化（同一实体不同写法归一）；数值必填四件套：值/单位/时间/地域，口径能取则取。
  3. **第二模型复核**：照搬 topic-research 双模型与飞轮"自己蒸馏自己不可靠"教训——独立模型逐条复核：数值条目对原文核数；claim 条目核"quote 是否支持该表述"。不一致 → 标 low confidence 进待审，**不静默丢弃也不静默放行**。
  4. **需求映射与不可得处置**：每条抽取标注满足哪条 IR（`ir_hits`）。**负结果也是结果**——某 IR 多轮尝试仍无满足时，先归因四类，按类处置，不许装作没发生：
     - **① 检索未中**（信息存在但没搜到）：换查询（同义扩展/中英双语/换角度）、换引擎、换渠道（信息源库直连/站内检索）再攻；受**每 IR 检索努力上限**约束（默认 2 轮 / 8 次工具调用），防死磕一项烧光预算；
     - **② 获取受阻**（页面在但拿不到：JS 墙/反爬/PDF 过复杂）：转手动导入建议清单；同一事实的权威转载源可作替代（转载簇在此反向利用——主源拿不到时从佐证源取，溯源如实标注实际来源）；
     - **③ 真不存在**（公开渠道确无此信息）：宣告不可得，负结果记录必须附证据（试过什么路径、为何判断权威源没有），这是合法且常见的结局；
     - **④ 蓝图错误**（需求本身提错：如要月度粒度实际只存在年度数据、schema 字段无页面会暴露）：记录发现，建议蓝图 v2 修订该 IR 后重跑——第一版蓝图是假设，执行是实验，v2 吸收实验结论。

     **替代与决策权**：同口径的源形态替代（官方原文拿不到 → 采引用它的权威二手源）自动执行、溯源如实标注实际来源；**凡涉及口径 / 时间粒度 / 地域范围的降级**（月度→年度、分省→全国），快速模式自动选取最近可得替代但**必须在整理稿与质量报告中显著标注，禁止静默降级**，精调模式暂停请示。must 级 IR 长攻不下 → **提前上报**（附已试路径与替代建议），不烧完预算才报告失败；should/nice 级记录负结果后继续，任务按 stopRules 正常交付，覆盖率如实统计。
- **质量闸门**：无 quote 拒收；quote 回验失败拒收；schema ajv 校验失败 → 归一重试一次 → 仍失败弃置并计数（弃置率是整理稿覆盖率差异的解释项）；复核不一致率 > 20% → 该源整体降级待审（说明正文质量或抽取提示词有问题）。
- **产出**：结构化行（ic_rows，draft）+ 抽取统计 + 负结果记录。

### 阶段 5：裁决与整理（条目 → 可用知识）

- **目的**：去重、归并、消解冲突，按蓝图整理规格产出**可核查**的知识文档。这是"整理质量"的主战场。
- **输入**：draft 行 + 源记录 + 蓝图整理规格。
- **处理**：
  1. **三层去重**：①精确（url_normalized + content_hash）→ merged；②跨 URL 同文（text_fingerprint 簇）→ 并入主源；③语义近重复（向量 ≥0.92 merged / 0.80-0.92 待审，阈值沿用飞轮）。**裁决分域**：只在 `(user, project)` 内比较，跨项目永不互裁。
  2. **冲突归因**：同 IR 不同值必须先归因再处置——四分类：**时点不同**（2015 vs 2024 数据，非冲突，进时间轴）/ **口径不同**（常住人口 vs 户籍，并列并标注口径）/ **修订关系**（初步数 vs 核实数，新版 supersede 旧版并保留链）/ **真矛盾**（归因不了，needs_review 并排展示）。归因由 LLM 给出并附理由，归因失败的按真矛盾处理。
  3. **孤证标记**：must 级 IR 仅一个独立源支撑 → 数据/结论带"孤证"徽标（独立 = 跨机构且非转载簇同源）。
  4. **恒等式校验**：蓝图 `checks` 声明的跨行恒等式（如"资产 = 负债 + 所有者权益"）按 (schema, period, dims) 分组运行，不平 → 整数据集 needs_review 并标注差额（通用数据自洽机制，人口平衡方程同理；v1 范围与语法见存储设计 §5）。
  5. **整理产出生成**（按蓝图整理规格）：每张要点卡/每行数据表必须**可反查**：结论 → 引句（quote）→ 源（快照+链接+访问日期）三层证据链；数据表每行带 source；时间线按归因后的时点排序；引用清单含分级与访问日期。**整理稿不得出现无法回链到条目的新事实**（LLM 生成时禁 free-writing，程序化校验：整理稿文本中的数值/专名必须能在条目集合中定位，定位不到即删）。
  6. **整理稿第二模型审**：三个问题——覆盖（蓝图 IR 满足率如实统计）、充分性（孤证/低置信是否如实标注）、忠实性（整理稿是否比条目"多说了什么"）。审出问题 → 修改或标注，不出带病稿。
  7. **质量报告生成**（随任务交付，见 §4.5）。
- **质量闸门**：覆盖率未达 stopRules 目标时，任务**不伪装完成**——交付物明示"哪些 IR 未满足、为什么、建议下一步"；反查校验失败的句子直接删（宁可空缺不可无据）。
- **产出**：整理文档族（draft）+ 质量报告 + 待审清单（冲突/孤证/低置信分组）。

### 阶段 6：人审与入库

- **目的**：AI 的一切产出在此关门；确认后的内容进知识库成为全系统可用的资产。
- **输入**：draft 的源文档、整理文档、行数据；待审清单。
- **处理**：
  1. **审阅 UI**：按 IR 分组批量审阅；冲突并排对比（左右源+引句）；孤证/低置信/needs_review 高亮；支持逐条编辑后确认、整批确认、驳回（驳回需选原因：来源不可信/抽取错误/无关——原因进质量统计）。
  2. **入库动作**（确认后执行）：清洗正文 + 文档头（溯源元数据）→ kb 文档；整理文档族 → kb 文档；行数据保持 ic_rows（confirmed）+ 数据表渲染为 kb 文档。走既有 kb 管线切块/嵌入/倒排。
  3. **入库前清单**（程序化）：元数据齐全（URL/分级/时间/rationale）、快照文件存在、引句锚点完整、项目 kb 正确。
  4. `autoConfirm=true` 时：低风险（tier≤2、有 quote、复核一致、非孤证）自动确认，其余仍进人审——开关默认关。
- **质量闸门**：入库失败（嵌入服务不可用等）→ 重试台账 + 明确状态（源 confirmed 但 kb 未同步），绝不允许"看起来入库了实际没入"；批注入库后抽验 3 条的向量可检索性。
- **产出**：kb 文档 + confirmed 行 + 入库台账。

### 阶段 7：刷新与时效治理

- **目的**：资料库活着，不烂库。
- **输入**：refresh_policy（manual/cron）、蓝图版本。
- **处理**：同蓝图重跑阶段 2-5（增量：url_normalized 跳过已采、focus 在时间增量）；**新版本数据**（修订/更新）→ 新行 confirmed + 旧行 superseded（链可回溯）+ kb 文档更新走 kb 既有版本语义；**过期检测**：消费时若条目发布时间超出 IR 时效窗，返回带 stale 提示（不删，不瞒）。
- **质量闸门**：刷新后输出 diff 报告（新增 N 条/更新 M 条/失效 K 条），不静默变更。
- **产出**：diff 报告 + 版本链。

## 4. 质量体系（度量、评测、报告）

### 4.1 搜集质量指标（过程可统计）

| 指标 | 定义 | 健康线（初值，评测后校准） |
|------|------|------|
| 一手源占比 | tier 1-2 且非转载簇佐证的源 / 总源 | ≥60%（数据/政策类） |
| 转载簇占比 | 佐证源 / 总源 | 参考（过高说明查询同质化） |
| quote 回验通过率 | 回验通过抽取 / 总抽取 | ≥95%，低于说明提示词或源质量差 |
| 复核不一致率 | 第二模型判不一致 / 总复核 | ≤5% |
| 抓取成功率 | ok / 总抓取 | ≥80% |
| IR 覆盖率 | 满足的 IR（含负结果确认）/ 总 IR | ≥ stopRules 目标 |
| 孤证率 | 孤证支撑的 must 结论 / must 结论 | ≤20% |
| 快照存档率 | 有快照的 confirmed 源 / 总 confirmed 源 | 100%（硬要求） |

### 4.2 整理质量指标

| 指标 | 定义 | 健康线 |
|------|------|------|
| 反查通过率 | 整理稿中可回链的数值/专名 / 全部数值专名 | 100%（硬闸门，不通过即删句） |
| 冲突归因率 | 完成归因的冲突 / 全部冲突 | ≥90% |
| 覆盖率如实性 | 报告声明覆盖率与实际核对一致 | 抽检 100% 一致 |
| 忠实性抽检 | 第二模型审"多说了什么"发现处数 | 趋势下降 |

### 4.3 质量仪表（项目级，UI 常驻）

来源构成（分级分布饼图）、IR 覆盖热力（哪些需求还没满足）、待审积压、孤证清单、冲突未决清单、指标趋势（§4.1/4.2）。**坏信号主动报警**：一手源占比跌破健康线、复核不一致率超线、快照存档率 <100%。

### 4.4 评测体系（M0 硬门槛——模块价值必须被证明，不是自我感觉）

照飞轮 A2 教训（全上下文基线常打平专用系统，厂商数字不可信）：

- **评测集**：选 2-3 个**与示例主题不同**的真实主题（验证通用性），每主题 20-30 问，含事实型（可查证）与综合型（需多源整合）；**标准答案+权威源预先人工钉死**。
- **对照**：①无资料库（agent 现搜现答）②资料库辅助。同题同模型同预算。
- **指标**：可答率、**答案准确率**（对照权威源人工判定）、**溯源正确率**（给出的引用确实支持答案——防"引用了不支持的源"的假溯源）、时效正确性。
- **红线**：资料库模式必须显著优于现搜现答（否则模块价值不成立，回头改设计）；评测报告入库，指标健康线据此校准。

### 4.5 质量报告（每次任务随交付物，一页）

来源构成（分级/一手占比/转载簇）、IR 覆盖明细（满足/未满足+原因）、冲突与归因结果、孤证与低置信清单、负结果记录、预算消耗、与上次任务 diff。**未满足的 IR 明示，不掩盖**——这是"高质量"与"完成任务式"的分界线。

### 4.6 商用验收门槛

本章健康线是**过程质量线**（每任务自动统计，进质量仪表）；商用判定单列于 `docs/design/2026-10-07-info-collection-commercial-metrics.md`，终版为 **3 道闸门 + 1 个北极星**：G1 零静默错误（凡错必标）、G2 溯源正确率 ≥90%、G3 评测不输现搜现答且溯源显著赢、北极星 W2 回访 ≥40%，外加盲测四条。两条原则：**宽进严出**（严格标准只在验收层，运行时一切失败降级为待审/标注/手动导入，不存在"采不到数据"的结局）；结构性保证归测试套件、过程健康线归本章仪表。一句话判据：**发布前 G1-G3 全过 + 盲测四条过 = 可商用；发布后月度只盯静默错误与 W2 回访。**

## 7. 治理纪律（沿用飞轮 §11.5 已付费的教训）

| 项 | 规则 |
|----|------|
| 迁移顺序 | `create-info-collection.ts` 注册进 `src/electron/database/index.ts` 有序清单，依赖表先建、PC/Web 成对（坑 #5/#9） |

| 合规 | 快照仅本地、引用带链接与访问日期、不绕反爬、不做整站抓取 |

## 8. 分期实施

| 阶段 | 内容 | 验收 |
|------|------|------|
| **M0 评测先行（硬门槛）** | 评测集构建（2-3 主题 × 20-30 问，答案+权威源钉死）；基线跑分（现搜现答 vs 无任何辅助） | 评测报告入库；**无基线不进 M1** |
| **M1 骨架+管线最小闭环** | 类型/迁移/五表/蓝图起草与自检/检索获取/快照/quote 回验抽取/审阅 UI/入 kb | 一个非示例主题端到端跑通；quote 回验与快照存档率 100%；重跑同 URL 不重复 |
| **M2 质量层** | 双模型复核/转载簇/冲突归因/孤证标记/整理产出与反查校验/质量报告/评测集复测 | 反查通过率 100%；评测：溯源正确率显著优于基线 |
| **M3 消费面** | `ic_search`/`ic_collect` 工具、通用搜集应用模板、topic-research kbs 挂载验证、导出 | chat 一句话取数成功且带溯源；资料库 kb 可被既有消费方检索 |

## 9. 风险与开放问题

| 项 | 处置 |
|----|------|
| 蓝图质量参差（用户不会审蓝图） | 自检清单程序化 + 蓝图页给"预检结论"（如"must IR 缺独立源要求"高亮）；评审后可加蓝图模板库 |
| 评测成本 | 评测集小而硬（20-30 问/主题）；只在新版本/新指标上线时复测 |
| 每源一文档使 kb 增长快 | 项目级 kb 隔离 + 项目归档（kb 同步归档）；kb-brain 消化按 opt-in |
| 簇/指纹误判 | 簇判定只影响主源选择与去重，不删内容；待审通道兜底 |
| ~~开放~~：`ic_rows` 与 kb 文档的双写一致性 | **已关闭**（存储设计 §6）：行表为唯一权威，kb 数据表文档与约定列均为幂等投影，损坏即从行表重建，无同步协议 |
| **开放**：跨项目同名 IR 的经验复用（蓝图模板沉淀） | M4 后视使用数据决定，暂不做 |
| **开放**：模块中文名 | 暂定「信息搜集」，包名 `info-collection` |

## 10. 明确不做的事

1. 不内置领域专属逻辑（人口/政策/AI 行业等示例不进代码，只进评测集与测试用例）。
2. 不做通用爬虫框架（无 JS 渲染、无 CSS 选择器编排、无代理池）——动态页走手动导入。
3. 不绕过反爬、不做整站抓取。
4. 不做自动 publish——AI 采集/整理产出一律 draft 起步（autoConfirm 默认关）。
5. 不在 ic_ 表复制正文内容——内容唯一存储在 kb。
6. 不做"无 quote 的抽取""无快照的入库""无 ration的定级"三类硬违规。
7. 不做跨用户共享（租户隔离默认）。
