- 日期：2026-10-10

- 前置文档：`2026-10-05-knowledge-brain-v2-redesign.md`（v2，其 P0-P4 已落地）、`2026-09-16-knowledge-brain-design.md`（v1）

## 0. 一句话定位

把知识大脑的生产目标从「这本书里有什么」改成「**这本书作为写作范例教会了我们什么**」：以「对写一本新书有没有用」为唯一判据，把样本书消化为**五种形态的写作方法知识**（方法卡/关系图/体系树/阶段表/证据条），全程自动、按写作时刻供给 agent——**用户合上电脑，价值在写作那一刻自动兑现**。

---

## 1. 目标与总判据（不可妥协项）

1. **总判据只有一条：对写一本新书有没有用。** 每条产出、每道工序、每个验收指标都用这把尺子量。书内长效 ≠ 跨书可迁移——这条判据差就是「读书笔记」和「写作知识」的分界线。
2. **大脑的第一用户是 AI。** 产出的验收方式是真机上 agent 写作时取到、取对、用上；不是 UI 面板好看。
3. **零点击。** 用户操作 = 开关 + 预算 + 收件箱（稳态趋零）；自动化覆盖从消化到产出到质检的全链，静默停摆视为缺陷。
4. **多书一库成立。** 同类书进一个库，跨书归纳出品类的体系、套路与结构惯例；单书只是语料的第一本。
5. **提取维度开放不写死。** 维度从语料归纳生长，数据驱动，加维度不改产线。
6. **知识按形态组织**：文档卡（方法）、图（关系）、树（体系）、阶段表（序列）、引用条（证据）——不是一切皆论断。

## 2. 非目标（明确不做）

1. 不优化第一部分知识（书籍内容问答）——chunks 与现有 RAG 检索不动，那是已解决的问题。
2. 不做用户书稿的世界管理——大脑对长文域（lw_*）只读供给，红线沿用。
3. 不做通用桥段百科、全库 GraphRAG 社区摘要（沿用 v1/v2 否决）。
4. 不做跨书人物重名的强行归并（宁缺勿造，沿用 graph-build 纪律）。
5. 不做物理删除代谢（archived/supersede 留痕，沿用）。
6. 不引入新工作流引擎/图数据库（SQL 表 + 现有向量存储 + 现有引擎，沿用）。

## 3. 现状诊断摘要（详见对齐记录 §2）

- **形态可行已证明**：冶炼成品卡质量达设计样板（套路卡带骨架/频率/变体/边界/实例引句）。
- **但生产目标错位**：98% 算力花在论断层（3037 条，大部分读书笔记级），第二部分知识只有 23 张卡。
- **四个断点**：知识出不了库（69 张积压 proposed、卡片零索引、滚动阅读产物不可见）；多书前提未成立（2/3 书未消化、归并死链、大库停产）；自动化有头无尾（四件套不入 automation、质量门半失明、4 个静默死链）；消费闭环零真实验证（0 次真实 agent 调用、eval 基线未跑、写前链路未挂大脑）。

## 4. 知识观 v3：生产什么、怎么抽象

### 4.1 两层产出观

| 层 | 是什么 | 形态 | 给谁 |
|---|---|---|---|
| **证据层**（降位） | 书内事实：场面事件、人物词条、经典片段原文 | 事件轨 + 词条原子 + 引用条 | 只作卡片/树/表的实例支撑与溯源锚点，**不直接当知识端给 agent** |
| **知识层**（主角） | 写作方法：体系怎么设计、套路怎么写、结构怎么搭、人物弧线怎么走、原理为何有效 | 方法卡 + 关系图 + 体系树 + 阶段表 | agent 按写作时刻取用 |

### 4.2 抽象的三级价值链（沿用 v2，原料换血）

```
证据层   事件/词条/片段（带溯源）——书内事实，永不冒充知识
   ↓  跨章汇聚 / 跨书聚类（维度驱动）
知识层   体系树（惯例+变体）· 套路卡（骨架+频率+边界）· 阶段表（结构/弧线惯例）
   ↓  跨套路归纳
原理层   原理卡 · 品类认知 · 反面模式
```

### 4.3 新书判据的操作化（提取与裁决的硬约束）

对每条候选知识问三个问题，任何一问不过即降档或丢弃：

1. **换书测试**：写另一本同类书时，这条要不要为它设计自己的版本/用得上吗？（设定体系✓；「韩立已叛出师门」✗）
2. **删除测试**（结构类）：删掉书里任何一章它仍然为真吗？（主线阶段划分✓；单章事件✗）
3. **抽象测试**：它是从 N≥2 个实例归纳出来的、还是从一章里抄出来的？（单实例只能进证据层）

## 6. 提取层改造（判据换血 + 分层收缩）

### 6.1 atomize v3：新书判据进提取（M1）

改 `prompts/index.ts` ATOMIZE 段：

- **layer 枚举收缩**：`outline/setting/describe/detail` → `setting/describe/detail/craft`。
  - `outline` 废除：概要是全书属性，章窗口无权产出——结构知识一律走通读派生（§8.3）。
  - `craft` 新增：技法观察（「以物证驱动调查线」类）的独立归属，不再借住概要/描写层。
  - 同步改 `kb-atom.entity.ts` 的 `KbAtomLayer`、`layer-intent.ts` 信号词表、`LAYER_RELABEL_SYSTEM`、UI 分层筛选。
- **setting 层定义收紧**：只收「世界如何运转」——体系/制度/地理/规则/品阶，配换书测试反例（现有定义方向对、产出跑偏，靠反例校准）；人物状态、剧情事件、物品归属现状一律不收（事件走 events 轨）。
- **原子性纪律强化**：禁止一条多事实炖煮（现有库里大量「…；…；…」长句），单条单事实、≤80 字为宜。
- **每条过三问**（§4.3），prompt 内给出正反例各 ≥3 条（从审计实料取）。

### 6.2 裁决（adjudicate）增设有用性档位（M1）

改裁决 prompt 与 `digest-orchestrator` 落库逻辑：裁决输出从「duplicate/contradicted/无关」扩为四值——新增 **`reader-note`**（书内事实：不复读、不改判，落库为 `role='evidence'` 的论断；已有同名 events 则丢弃）；`contradicted/superseded` 语义不变。

### 6.3 维度归纳 dimension-induct（M1 起，持续生长）

- 新 `services/kb-brain/dimension-induct.service.ts`：
  1. 抽样已消化书（每库抽 3-5 本的部分章节+滚动阅读记忆），开放提取「这本书展示了哪些可学的写作维度」；
  2. 嵌入聚类 + LLM 归纳为维度提案（名称/定义/适用体裁/提取 hint）；
  3. 写入维度库，进收件箱由用户增删（初版预置种子维度：结构、节奏、钩子、场面设计、对话、情感线、成长弧、体系设计、伏笔、爽点机制、雷点、对话潜台词…）。
- 维度库为数据：新表 `kb_dimensions`（kbId 可空=品类级，name/definition/hint/enabled/source: 'seed'|'induced'|'human'）。
- 消费方：冶炼聚类按维度加权、goal-distill 建议目标、brain-pack 按维度组包——**加维度不改产线**。

### 6.4 事件轨保全（M0 修复项前置）

修场面补采空正文 bug（§11 清单 #1）——事件轨是套路/弧线/结构的原料，先保证它不再静默断流。

## 7. 存储层改造（五形态落地）

### 7.0 契约新增：证据角色列（M1，随 layer 枚举一起冻结）

- `kb_atoms` 加 `role` 列：`'knowledge' | 'evidence'`（缺省 `'knowledge'`）。
  - `knowledge` = 通过换书测试的写作知识，可进 provider/检索知识供给；
  - `evidence` = 书内事实（裁决 reader-note 档、存量重判降档），保留检索锚点与溯源资格，**不进知识供给**（provider/brain-pack 知识段排除）。
- 与 layer 正交：layer 管「哪类内容」，role 管「知识还是证据」——存量重判（§10）与裁决（§6.2）都只写 role，不改 layer。

### 7.1 体系树（全新，M2）

- `kb_entities` 加 `attrs` JSON 列（属性槽：力量阶梯节点的 {能力,寿命,突破条件}、地理节点的 {特征,势力} 等）。
- `kb_knowledge_edges` 关系枚举新增：`sublevel-of`（体系层级，兄弟次序由节点 attrs.order 定）、`requires`（突破/使用前置）、`enables`（解锁关系）。
- `kb_edges` 增列 `valid_from_chapter` / `valid_until_chapter`（可空；人物关系边随章节演变的表达；graph-build 落边时从证据章节填）。
- 体系树不是新表——实体+边+属性槽的组合；树查询/渲染走新仓储方法。

### 7.2 阶段表（M2）

- `kb_notes` 加 `structure_stages` JSON 载荷列（沿用 pattern_skeleton 先例）：
  `[{ name, position(0-1 全书相对位置), function, coreConflict, turnPoint, cost, evidence[] }]`
- `KbNoteType` 增 `structure-map`（故事卷结构）、`character-arc`（角色弧线）；类型白名单/渲染标签同步。

### 7.3 卡片检索索引（M0 修断点，最高优先）

- 新 `note-index` 逻辑（并入 smelt/冶炼/通读落卡路径）：卡片 published 时同步写 `kb_vectors`（`note:` 前缀）+ 倒排索引行——打通 brain-query 的 note 通道、平铺回退与 provider 的卡片召回（当前全部空转）。
- 一次性回填存量 23 张 published 卡。

## 8. 产线改造（冶炼与派生）

### 8.1 冶炼层：维度驱动 + 门槛修复（M1-M2）

- 聚类从「sceneType 单轴」扩为「sceneType × 维度」双轴（维度来自 kb_dimensions）。
- 修大库停产：`SMELT_CLUSTER_MAX=30` 改为按桶规模自适应分片（桶 >500 事件时细分聚类），成卡门槛保持 max(8, 2%)。
- 修 corpus 归并死链（§11 #2），跨书归并真正跑起来。

### 8.2 体系汇聚 system-aggregate（M2，本方案最大新增产线）

新 `system-aggregate.service.ts`：

1. **单书汇聚**：按体系类型模板（力量阶梯/资源经济/组织制度/地理势力）跨章聚合设定词条+实体+通读记忆 → 单书体系树（树节点+attrs+边，全带章节证据）；
2. **跨书对齐**：同类体系树结构对齐（「玉清/上清/太清」↔「炼气→筑基→金丹」）→ 品类体系惯例卡（setting-system 卡：通用骨架+各书变体矩阵）+ 惯例树；
3. **产物形态**：树入库（§7.1）+ setting-system 卡入收件箱；渲染器负责给 agent 的文本视图。

风险最高工序，纪律：**宁缺勿造**——对齐不上就各书独立成树，不强拼；每节点必须带 ≥1 条原文证据；先力量阶梯（结构最规整）试点，制度/地理随后。

### 8.3 通读派生：结构阶段表与角色弧线（M2）

- goal-distill 升级：「故事线设计」「人物设计亮点」两类目标改**结构化输出**（structure_stages 阶段表），不再只出散文 synthesis 卡；阶段必须带全书相对位置与章节证据（删除测试硬约束）。
- 滚动阅读记忆（book-reading）作为弧线提取的主要输入：主角/核心配角逐人提取「起点→触发→转变→终点」阶段表 → character-arc 卡。
- 打开 `patterns.characterEnabled`（当前为 false——人物产线被关着）。

### 8.4 质量闭环修复（M0-M1）

- qa-judge：maxTokens 提至 2000+、接每库模型（§11 #5）；
- 自适应审批扩展：滚动均门控从冶炼卡扩展到体系树/阶段表/维度提案（带证据密度门槛的产物直发 published，其余进收件箱）；
- 漂移告警从 logger.warn 改为收件箱卡片（用户可见）。

## 9. 消费层改造（按知识形态路由）

### 9.1 brain-pack v3（M3）

改 `brain-pack.service.ts`，三时刻三配方（诊断时刻从 backlog 转正）：

| 时刻 | 配方 |
|---|---|
| 写前搭骨架 | 品类认知卡 + **体系树渲染**（惯例+变体）+ **结构阶段表**（品类结构惯例）+ 套路菜单 + 代表作档案标题行 |
| 写中取材 | 场面套路卡（含边界）+ 2-3 个案例原文片段 + 相关设定词条 + 关系现状清单（出场人物） |
| 修改诊断 | 对应场面类型的原理卡 + 反面模式卡 + 好坏对比案例 |

- 白名单收编全部成品形态（现缺 reading-memory/book-summary/structure-map/character-arc/体系树——**通读产线的知识资产必须进包**）。
- 渲染器新 `knowledge-render.service.ts`：renderSystemTree（缩进树+属性槽）、renderRelationNet（现状清单）、renderStages（阶段表）——agent 永远消费 prompt-ready 文本。

### 9.2 provider v2 与检索（M3）

- `brain-provider.ts`：供卡+体系树+词条，**不再直供 detail 层论断**（当前端读书笔记的主通道就此关停）；include 从 ['atom','note'] 改为 ['note','system','entry']。
- `brain-query.service.ts`：layer 权重表适配新枚举（craft 层给写作思路类查询加权）；detail 降为 context（同源 chunk 降级先例）。

### 9.3 写前挂载（M3，待拍板决策点见 §13）

长文写前链路（故事概要/大纲/世界观/人物生成，`longwriting-ai.service.ts` 各裸 callAIStream 处）接大脑：默认方案=提示词模板加引导句+工具描述按写前场景优化（不动 2026-09-22 决策）；若真机验收发现 agent 不自觉调用，升级为可配置轻注入（默认开，仅大纲/世界观/人物三类）。

### 9.4 消费记账与真机验收（M3）

- 新 `kb_consumption_log`（kbId/tool/mode/task/hits/pack 预算命中/是否被采纳信号）——消化率仪表增加「被 agent 用了多少」维度，兑现「以被检索命中、被创作引用验收」。
- **真机端到端验收（硬门）**：建 20 本级修真品类库 → 合上电脑 7 天 → 真机 agent 执行「帮我写一本修真小说」从搭骨架到写一个场面，全程调用日志+取包内容存档 `outputs/`。没有这次验收，消费闭环不算成立。

| 决策 | 理由 |
|---|---|
| 生产目标二分：大脑只产写作方法知识，书内内容降为证据 | 用户明确「侧重点在第二部分」；第一部分 RAG 已覆盖 |

| 提取维度开放（schema induction），五项只是种子 | 用户明确「不要写死」 |
| 五形态存储（卡/图/树/表/引），体系树新建、阶段表走 notes 载荷 | 按查询方式定形态；复用现有表不新引存储引擎 |

## 14. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 体系树归纳质量（全方案最高技术风险：跨书体系对齐比事实抽取难一个量级） | 力量阶梯先行（结构最规整）；对齐不上不强拼、各书独立成树；节点 100% 带证据可人工核；宁缺勿造写进 prompt |
| 「有用性」判断依赖模型品味，判据可能被模型理解漂移 | 评测集内置边界样本（换书测试正反例）；judge 抽检新书判据遵守率；漂移进收件箱 |
| 维度库冷启动与爆炸 | 种子维度预置；每库维度集上限（如 ≤20）；维度有采纳信号（产卡/被引用），长期不产出的维度自动休眠 |
| 存量重判误伤（好知识被降档） | 三档处置全部可逆（archived 可恢复）；抽样人工核；处置报告入档 |
| 多书消化成本（20 本×千万 token 级） | 熔断分日推进（沿用）；新枚举提取 prompt 不比旧版长，单章成本不涨 |
| layer 枚举变更的兼容面 | 检索端为软权重不硬过滤（layer-intent 设计如此）；UI 筛选/白名单同步清单在 M1 改动列表中穷举 |
| 开放问题：非小说体裁（科普/文史）的体系树与阶段表语义 | 沿用 v2 待定项，按品类适配维度与模板，M2 后另议 |
