## 0. 一句话定位

把知识大脑的书级知识生产从「**细节池抽样拼卡**」改造为「**逐层压缩漏斗**」：原文 → 每章结构化阅读卡 → 名册/编年段 → 卷 → 全书成品，宏观知识从上一层的完整产物逐级归并出来，覆盖由程序记账，全程是引擎内部产线——**不新增任何用户操作面**，产物形态仍是 v3 的五形态知识 + 证据层。

---

## 1. 病根与药方

v3 之后的真机反馈：提取质量有提升，但**层次不够分明**（宏观架构到微观设计没有分层结构）、**完整度远远不够**（大部头书的知识覆盖率低）。代码级诊断（对照 deepwrite 后确认）：

| # | 病根 | 现状证据 |
|---|---|---|
| 1 | 知识层次是「自下而上贴标签」，不是「自上而下建结构」 | 层次（setting/describe/craft/detail）由模型在单章 6000 字窗口内自标；分层补标（layer-relabel）也是看局部文本——模型从未有机会「先看懂全书架构再决定层次」 |
| 2 | 书级产物全部有取样上限，超出静默丢弃 | 设定索引 ≤200 条论断、伏笔台账 ≤80 条、人物册 ≤20 人×3 条、全书概要章纲 ≤600 章采样且每章只看 600 字摘要 |
| 3 | 滚动阅读的工作记忆必然失真 | 记忆硬上限 12000 字，情节段保尾丢头；四件套（图谱/复核/综述）全部建立在失真记忆上；且 7 天才轮一本 |
| 4 | 归并只有一级 | 全书概要是「章→书」一级 map-reduce；归纳整理只有分批 map 没有全局 reduce；中途无中间层可复用 |
| 5 | 两条产线各跑各的 | 论断池（章级原子化）与工作记忆（滚动阅读）互不供数；书级关卡吃论断池、四件套吃记忆，没有统一中间层 |
| 6 | 实体无归并人审、无重要性分级 | 实体是章级流水线 upsert，别名归并错误一路传导到人物册/设定索引的「前 N 个实体」截断 |
| 7 | 伏笔只有「悬置点清单」 | open-question 论断列表 + 事后埋设-回收边扫描；无过程动作（埋/强化/误导/揭示/回收）记录 |

**药方（一句话版）**：建一条「章卡 → 名册/编年段 → 卷 → 书」的结构化漏斗替代「滚动记忆 + 抽样拼卡」，所有书级产物改从漏斗上层取材，上限截断改为预算配额，覆盖缺口由程序记账并可补跑。

## 2. 定位与边界（对齐「不是拆书功能」）

1. **引擎内部产线改造**，不是新功能：不加页面、不加按钮、不加新面板。用户可感知的变化只有一个——知识卡的质量与覆盖变好，以及收件箱里多一类「名册卡」待审条目。
2. **人审走现有收件箱**：deepwrite 的名册确认是专门 UI；v4 的名册定级结果以一张 markdown 名册卡进收件箱，接受/拒绝/忽略沿用现有待审流。结构化修正（合并/改名/分级）继续走已有实体管理界面，名册卡只做「确认门」不做「编辑器」（取舍见名册子设计 §5）。
3. **产物形态不变**：五形态（卡/图/树/表/引）+ 证据层（v3 §4.1）。阅读卡、编年段梗概、覆盖账本、审校报告都是**过程产物**，存内部工件表，不进知识卡列表、不进检索供给（deepwrite 同款纪律：成品归真实目标，过程归任务目录）。
4. **不照搬的部分**（沿用 v3/C 级结论）：不做「重建一本书」的续写模式与连续性账本；不做多智能体运行时框架；自动化巡检架构保留；跨书冶炼（套路/案例/原理/品类）保留并继续是差异化优势。
5. **v3 决策全部沿用**：新书判据三问、证据/知识二分、layer 新枚举、维度开放、零点击、Electron-only。本方案的漏斗是 v3 §8.3「通读派生」的落地载体——v3 只说了「结构知识走通读派生」，v4 给出通读派生的具体产线。

## 3. deepwrite 参考 ↔ v4 取舍对照

| deepwrite 做法 | v4 取舍 | 理由 |
|---|---|---|
| 数据逐层压缩漏斗：原文→阅读卡→编年段→成品 | **照搬结构**，层数收敛为「章卡→编年段→卷→书」 | 直接对症病根 1/4 |
| 每章结构化阅读卡（分域、带章号事实、程序硬校验、逐章落盘） | **照搬**，schema 按画像分小说/知识/历史三变体 | 对症病根 2/5；知识类书籍差异见 §6 |
| 名册阶段（程序聚合→模型分片裁决→程序合并→人审→分级驱动整合） | **照搬流程**，人审降级为收件箱名册卡 | 对症病根 6；省掉专门 UI |
| 伏笔线（六动作节拍链挂章号） | **照搬数据结构**，产线并入编年段归并 | 对症病根 7 |
| 覆盖由代码校验（每章必有梗概/每必需键必达） | **照搬**为覆盖账本（记账+可补跑），校验从「阻断式」放宽为「报告+补跑」（引擎无人值守场景不能弹窗等确认） | 场景差异：deepwrite 是交互式任务，v4 是挂机自动化 |
| 分领域审校 + 修复重派 | **照搬**，审校对象改为书级卡之间交叉核对 | 现有终审复核只对记忆、不回流 |
| 证据包由程序预组装（窗口×比例配额，禁分页翻查） | **照搬**为书级取材的证据包组装器 | 顺带替换现有 200/80/20×3 硬上限 |
| 主控+并行子智能体（≤5 并发） | **不搬运行时，搬单元化**：书级关卡拆成带依赖的单元（复用台账幂等），v4 先串行执行，单元化后并行只是调度参数（阶段四可选） | 本项目无子智能体框架；SQLite+单进程下并发收益有限、风险面大（熔断计数/进度乱序/写竞争），后置 |
| 阅读块 ≤20 章/≤60k token 批量通读 | **不搬**：保持章为最小单元（本项目章级台账/裁决/溯源全部锚在章上），卡按章产出 | 改块级会牵动整个溯源与幂等体系，收益只是省几次调用 |
| 真实目标直写+回执对账+冲突检测 | 不搬（本项目产物走待审/直发双轨，已有 undo/台账，语义等价） | 已解决 |
| 成本预估与 2 倍熔断 | 借鉴估算公式进覆盖账本展示，熔断沿用现有日上限 | 已有旋钮 |

## 4. 方案逐条评审与复杂度评估

复杂度档：**高**（新存储+新产线+多处消费改造，需单独设计）/ **中高**（新产线为主）/ **中**（新产线或跨模块改造）/ **低**（程序逻辑重构）。

| # | 方案 | 改动面 | 复杂度 | 依赖 | 决策 |
|---|---|---|---|---|---|
| A1 | 章级结构化阅读卡（取代章节摘要成统一中间层） | 章表加列、digestion 新增 card 遍、双/三画像 schema+提示词、校验、消费方切换、存量补跑 | **高** | 无（起点） | 采纳，阶段一，单独设计 |
| A2 | 名册（实体聚合+归并裁决+分级+收件箱人审） | 聚合器（吃 A1）、分片裁决产线、实体 attrs 回写、名册卡类型、消费方按级取材 | **高** | A1 | 采纳，阶段二，单独设计 |
| A3 | 伏笔线（六动作节拍链） | A1 卡内登记伏笔动作 + 归并产线汇聚成线 + 伏笔台账卡改造 | **中**（卡内部分随 A1，汇聚随 A4） | A1 | 采纳，并入阶段三 |
| A4 | 书级多级归并链（章卡→编年段→卷→书；人物档案分级建档、设定按类别建档、概要多级化） | 归并产线（单元规划纯函数+台账）、artifacts 工件表、四类书级卡改造、证据包组装器、旧卡重建语义 | **中高** | A1、A2 | 采纳，阶段三，单独设计 |
| B5 | 覆盖账本（每章被哪些书级产物覆盖的矩阵，缺口可见可补跑） | 程序推导（零 LLM）+ artifacts 存储 + 体检面板缺口展示 + 补跑挂自动化 | **低中** | A1、A4 | 采纳，并入阶段三 |
| B6 | 分领域审校修复回路（书级卡交叉核对、问题带章号、修复重跑） | 审校遍（passType='book' passKey='review:*'）、问题 artifacts、自动化冷却接入 | **中高** | A4 | 采纳，阶段四 |
| B7 | 证据包模式（程序按预算组装取材，替换硬上限） | 书级取材函数重构（纯代码，无新存储） | **低** | 无（随 A4 落地最自然） | 采纳，并入阶段三 |
| B8 | 并行单元执行（章级遍并发 2-3） | 消化编排器并发化：熔断计数、进度事件、SQLite 写竞争、审核封账状态机 | **中**（风险面大收益中等） | A1（单元化已具备） | 采纳但**后置**到阶段四可选，先保证串行漏斗跑通 |
| C9 | 知识类书籍拆法（画像驱动双模式） | 设计问题而非独立工作量：A1 schema 变体 + A4 产物清单按画像切换 | —（随 A1/A4） | — | 采纳，见 §6 |

**关键路径**：A1 → A2 → A4 →（B5/B7 随 A4、A3 随 A1+A4）→ B6 →（B8 可选）。串行依赖明确，每阶段独立可验收、可停。

## 5. 目标架构

```
                      ┌────────────────────────────────────────────┐
                      │ 消费层（不变）：brain-pack / provider / 检索  │
                      └───────────────────▲────────────────────────┘
                                          │ 五形态知识 + 证据层
┌─────────────────────────────────────────┴──────────────────────────┐
│ 书级成品层（v4 改造：全部从漏斗上层取材，证据包预算配额）                 │
│  全书主线（段→卷→书多级）· 人物档案（分级+卷小传合并）· 设定档案（按类别）  │
│  伏笔线（节拍链）· 知识体系图/概念树（knowledge）· 文风画像 · 品类冶炼（不变）│
├────────────────────────────────────────────────────────────────────┤
│ 中间归并层（新增，过程产物存 artifacts 工件表）                          │
│  编年段（章卡按窗口分段→段梗概+剧情点/论点链）→ 卷梗概                     │
│  名册（程序聚合→分片裁决→程序合并→分级→收件箱人审）                        │
│  覆盖账本（程序记账）· 审校报告（分领域）                                  │
├────────────────────────────────────────────────────────────────────┤
│ 章级阅读卡层（新增，kb_chapters.brain_card）                            │
│  小说域：梗概/事件/人物事实/设定事实/伏笔动作/文风摘抄（全部带章号）          │
│  知识域：梗概/核心论点/概念定义/论据/方法步骤/术语/金句                     │
├────────────────────────────────────────────────────────────────────┤
│ 章级细节层（不变）：atomize 论断+场面事件（证据层原料）+ 实体挂点 + 裁决      │
└────────────────────────────────────────────────────────────────────┘
```

产线顺序（消化一本书）：`card 遍（每章）→ base 遍（每章，现状不变）→ 名册 → 编年段 → 卷 → 书级成品 → 审校 → 覆盖记账`。card 失败不阻断 base（fail-soft）；名册及以后集中在文档消化收尾（书级遍时段）执行，全部有台账幂等。

与现有两条线的关系：**滚动阅读四件套保留**（它的价值在「续写向连续性」与综述文章），但取材改吃阅读卡+名册（工作记忆退居辅助）；**论断池保留**（证据层原料 + 检索锚点），书级产物不再从论断池抽样拼卡。

## 6. 知识类书籍怎么拆（回答问题 1）

总原则：**漏斗结构不变，schema 与产物清单由内容画像切换**。画像检测（novel/knowledge/history/other）已存在，v4 把它从「选提示词+选关卡」升级为「选卡 schema + 选名册形态 + 选归并产物」。

### 6.1 三种画像的漏斗对照

| 层 | novel 小说 | knowledge 知识（经管/科普/教程） | history 历史/传记 |
|---|---|---|---|
| **阅读卡域** | 梗概/事件/人物事实/设定事实/伏笔动作/文风摘抄 | 梗概/核心论点（带章号）/概念定义/论据与例证/方法步骤/术语/金句 | 梗概/事件（时间线向）/人物事实/制度与背景事实/引文 |
| **名册** | 人物名册（主角/主要配角/次要配角/路人）+ 设定词名册 | **术语名册**（核心概念/支撑概念/示例引用——分级=概念在全书论证中的地位，按「定义章数×被引次数」程序预评 + 模型校准） | 人物名册（同小说，等级=传记分量）+ 术语名册（制度/职官/地名） |
| **编年段** | 剧情点（因果链） | **论证段**（论点→论据→结论链；段=主题章节组而非时间章组） | 编年（天然的 timeline，段=时期） |
| **卷→书归并产物** | 全书主线/卷梗概/人物档案/设定档案/伏笔线/文风画像 | **知识体系图（概念树：概念依赖+论点结构，衔接 system-aggregate 的树存储）**/方法清单（step 类论点归并）/书评级综述 | 大事年表（structure-map 的时间线语义）/人物档案/制度沿革/史学观点综述 |
| **不产出** | — | 伏笔线、文风画像（降为可选） | 伏笔线 |

### 6.2 知识类书籍的三个特殊处理

1. **「章节」弱化为主题单元**：知识书常无严格章节叙事，编年段切分依据从「章序+模型窗口」变为「章序+目录层级」（利用章表的 parent_title/level 列——卷/篇结构已入库）；无层级结构的按窗口切，段名用主题归纳。
2. **概念定义的版本演化**：同一概念在多章被细化/修正（知识书常态），概念条目按「首定义章→修正章」链记录（复用论断 validFrom/validUntil 的章区间语义），体系树节点 attrs 记录最终定义并保留演化链证据。
3. **换书判据的画像化**：v3 的「换书测试」对知识书表现为「引书测试」——这条知识写另一本同主题书时是否要为它设计自己的版本（方法论✓、本书案例✗）。该判据已够用，仅 prompt 内换例。

### 6.3 画像失准兜底

画像检测失败/误判（把知识书判成小说等）的兜底链：`other` 走最小漏斗（梗概卡+术语名册+知识体系图）；用户可在库设置改画像，改后按画像触达的关卡台账 hash 失效自动重汇总（沿用书级指纹机制，扩为「画像值参与指纹」）。

## 9. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 消化成本上升（card 遍每章 +1 次调用） | 摘要职责被卡接管，大脑启用库可跳过独立摘要服务（净成本≈持平）；card 用 atomize 档位（低档）即可，归纳质量由上层归并保证；覆盖账本暴露每书卡成本 |
| 卡 schema 校验失败率（模型不守格式） | 沿用 atomize 解析链（提取 JSON→ajv→错误回喂重试 1 次）；schema 字段全部可选化降级（缺域只记覆盖账本缺口，不阻断） |
| 名册裁决错误传导 | 定级宁低勿高（拿不准=次要）；人审收件箱一道门；分级只影响「建档粒度与取材顺序」，错误定级的损失是档案粗一点而非错误知识 |
| 多级归并的误差累积（段错→卷错→书错） | 每级产物带章号证据可下钻核验；审校回路专查「上下层不一致」；宁缺勿造纪律沿用 |
| artifacts 表膨胀 | 过程产物随文档重消化替换式更新（key 唯一）；清理服务（cleanup）扩一条 artifacts 过期清理 |
| 大部头单文档消化时长进一步变长（card+归并串行） | 阶段四可选并发；短中期靠自动化分日推进（熔断分日，已有） |
| 开放问题：非小说画像下的四件套语义（复核/综述对知识书的价值） | V4-4 时按试点书观察再定，先保持现状取材切换 |

### 11.2 实现期偏差决策（相对子设计）

| 偏差 | 理由 |
|---|---|
| 证据包预算用**字符常量**（env `KB_BOOK_EVIDENCE_CHARS`/`KB_ROSTER_PART_CHARS`，缺省 24000/12000）而非模型窗口比例 | provider 侧拿不到窗口元数据（llm.ts 既有结论）；沿用滚动阅读 24000 字先例 |
