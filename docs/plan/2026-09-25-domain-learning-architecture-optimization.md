# 领域共学空间：从病根出发的架构优化方案

> 定位：与《2026-09-25-domain-learning-knowledge-planning-fix-plan.md》（下称"修复方案"）互补。
> 修复方案回答"这 20 个问题怎么改"；本文回答"这些问题为什么会长成这样、什么结构让这一类问题不再发生"。
> 结论先行：审查发现的 20+ 个问题不是 20 个独立失误，而是 **5 个结构性决策的必然产物**。逐条修补（5~6 天）能让分数回到 8.5，但同类问题会在下一次迭代中换皮重生；按本文的结构性方案收敛（8~12 天）才能把模块推向 9 分档。

---

## 一、评判标准：这个模块到底要做什么

领域共学空间的本质是一个**闭环**（与学习科学文献库 d-learning-science 的结论一致）：

```
画图（规划体系）→ 沿图学（讲义/辅导）→ 测（掌握度/自测/困惑）→ 修图（补全/拆解/重排）→ 巩固（复习）
        ↑______________________________________________________________________|
```

模块的核心资产是**知识图 + 掌握度状态**，其它一切（规划、讲义、答疑、排程）都是对这个状态的读写。评判任何优化的标准只有一条：**这个闭环转得是否顺畅——画出来的图对不对、沿图学是否顺、测量结果是否回流修图**。

用这个标准看，今天的模块：画图有仪式感但图的质量靠运气；沿图学最强（五道卡级门禁是全模块质量最高的部分）；测做得对（掌握门控、困惑计数）；**修图是断的**——测量结果不回流规划，修复全靠用户手动点「AI 补全」；巩固有队列但没有和图联动。

## 二、全局诊断：五个病根

### 病根 1：空间没有"学习阶段"这个一等状态，每轮都在猜

空间明明有生命周期（没规划→诉求对齐中→体系确认中→落库中→稳态学习），但这个状态**不存在于数据库里**，而是每一轮由 harness 重新推断：`isEmptySpace` + 消息里的字符串标记（`PLAN_SYLLABUS_CONFIRMED_MARKER`，deps.ts:31-33）+ 意图正则（`shouldInjectMapCompletionSkill` deps:310、`isPlanPhaseMessage` deps:123）。

`dl_plan` 表里其实存着 confirmed 状态——但 harness 不把它当权威，而是每次用文本信号重新拼装出"现在是什么阶段"。**状态从消息文本推断，而不是从数据读取**，这一个决策直接产出了一类 bug：

- P1-7：落库轮失败重试后 `isEmptySpace` 翻转 → 阶段指令和额度全部丢失（task 模式踩过这个坑，打了 `isPlanPhaseMessage` 补丁；research 模式漏了同构补丁——**补丁本身在繁殖**）；
- P1-2：补全轮同轮注入两份相反指令（意图正则命中了技能注入，但消息没有确认标记又命中了第 1 步指令）；
- `isPlanningSaveRound`（bindings.ts:76-87）三个参数两个特判，本质是在用布尔组合模拟一个不存在的枚举。

代码注释里那些"2026-09-13 自查发现的坑""否则会掉出规划轮"就是这类 bug 的化石层。

### 病根 2：四套流程化石层叠，没有收编，靠"注入顺序新 = 权威高"维稳

按代码注释的日期可以考古出进化史：`learning-domain-map` 技能（JSON 规划草案）→ `learning-map-completion`（09-12，先采集后规划）→ 固定三阶段（09-13，把起步研究拆成三轮）→ bootstrap 技能改在落库轮注入（09-13）。**每一次迭代都是新流程叠在旧流程上，旧的没删**：

- 旗舰技能 learning-domain-map 的输出契约（6 个字段）没有任何代码消费方（P2-6）——因为它服务的入口已经被三阶段取代，但技能还在、research 提示词第 1 条还在引导调它；
- 落库轮注入 bootstrap **全文**只为了用它的 S4，结果 S2 的"3-8 个知识点"和阶段指令的"全部落库"同轮打架（P1-3）；
- research 系统提示词积累到 17 条 5000+ 字，13/14/15 条与快照内容三处重复。

模型每轮面对的是一份"新旧并存、以注入顺序暗示优先级"的指令堆。强模型能猜对，弱模型全凭运气——这是"不同模型表现方差急剧拉大"的根源。

### 病根 3：同一事实多处声明，没有单一权威

前置关系同时存在于四处：`dl_relation` 边（自称权威）、`attrs.prerequisites` 声明、方案里的 `layer`、`dl_project.prerequisites` 主题前置；前置"是否已落点"的判定有两套口径（快照/progression 用双向子串 `matchPrereqName`，手工连边用严格等名）；证据标注有四套方言（`evidenceLevel` 字符串、`prior` 布尔、`needs_verification`、`source` 枚举——后者已被硬编码误用）。每对"声明 vs 权威"之间没有同步机制，只有快照里的 ⚠️ 事后提示。P1-4（方案零闭合校验）、P2-4（layer 落库即失）、P2-5/P2-8 都是这一个决策的产物。

### 病根 4：校验的时机和层级错位

卡（讲义）级校验极强：五道门禁（evidence/区集/视觉/难度/渐进）、版本化、verify 流水线。图/方案级校验极弱：normalize 只查非空和去重，用户**确认弹窗**——整个人机协同里最重要的控制点——拿到的是一份未经任何图不变量检查的草案，且只能勾选/调序。已有的图检查（coverage 评分、前置欠账）全部只以"事后警告"形态出现在快照里。同一个领域不变量（无环、闭合、layer 一致、粒度）分散在三处口径不一的地方：提示词恳求、normalize 放行、快照叹气。

### 病根 5：学习闭环缺最后一条边——测量结果不回流规划

pace 调度器已经会自动推进"无卡概念"和"open 问题"两类工作项（设计干净、可测试），但它**看不见**：coverage 缺口、前置欠账、环、以及 `splitSuggested`。尤其后者：用户两次"没懂"后系统判定该拆解概念（`learning-sequence.rules.ts:81-85`），前端弹一次提示（`DomainLearningSpace.vue:1753`）——**然后没有任何环节消费它**，既没有一键拆解的动作，也不进调度队列。地图一旦画错（缺台阶/粒度太粗），唯一的修复入口是用户想起并手动点「AI 补全」。「测 → 修图」这条边在今天只存在于提示词的恳求里，不存在于系统里。

## 三、结构方案：五个 Move

总原则：**收编，不重写**。规则层纯函数、五道卡级门禁、幂等仓储、预算体系、verify 流水线、快照数据总线——这些是高质量资产，全部保留。要动的是它们的组织方式。

### Move 1：把学习阶段升级为一等状态（消灭"从文本猜状态"这一类 bug）

- `dl_project` 加 `plan_phase` 列：`draft → understanding_confirmed → syllabus_confirmed → building → steady`（重规划 = 显式回到 `syllabus_confirmed` 前态，补全/重排成为可枚举的入口而非正则意图）。
- 状态变迁只由 `dl-plan.service` 的 propose/confirm 驱动（confirmed 查询已存在，提升为空间级字段，事务内落）。
- harness 每轮**读** phase 决定注入与绑定；消息标记降级为前端触发器的载荷（不再是状态判定依据）。isEmptySpace 保留为展示信息，不再参与流程分支。
- 迁移：存量空间首回合按现有推断逻辑算一次 phase 然后持久化（一次性 script 或惰性写入）。
- **吸收**：P1-7 及其未来同构变体、P1-2 的一半、isPlanningSaveRound 全部特判、shouldInjectMapCompletionSkill 正则。

### Move 2：流程收编——一个课程引擎，技能降级为被编排的步骤

- 建立唯一的 per-phase 编排定义（声明：本阶段目标、注入哪些正文**段**、允许哪些工具类、出口动作）。注入单元从"技能全文"改为"技能的具名段落"（bootstrap 只注入 S4；map-completion 按 phase 注入 S2-S4 或提示先走方案）。
- `learning-domain-map` 的独立 JSON 契约**退役**：其排序公理/粒度锚点/防幻觉三层合并为 syllabus 阶段的写作规范，且像 `lesson-template` 那样**由代码渲染注入**（仓库已有这个正面先例：区集契约同源渲染，注释原话"避免提示词一份口径、门禁另一份口径"——把这个模式推广到规划侧）。
- 确立一条硬纪律并写成测试：**凡提示词引用的工具/字段必须有代码消费方；凡代码能算的数字，提示词不重复写**（静态扫描技能正文中提到的 dl_* 工具名与字段名，缺失即测试红——这类 contract test 仓库里已有 dl-channel-consistency.spec.ts 的先例）。
- research 系统提示词从 17 条压缩为"角色 + 纪律 + 快照引用"三段式，数字细节全部下沉快照动态块。
- **吸收**：P1-3、P2-6、C4/C5 全部，以及"弱模型方差大"这个未列入清单但更贵的问题。

### Move 3：图不变量收敛为"地图 Linter"，一个模块三个消费时机

- 新纯函数模块 `map-lint`：无环（cycle 检测）、闭合（前置落点，精确名匹配）、layer 一致性、相邻跨度、粒度提示。**全模块唯一的图不变量实现**。
- 三个消费点：① propose 时——normalizePlanSyllabus 调用，违规项作为 changes 透传到确认弹窗（用户拍板前看到）；② 落库动作层——saveRelation/saveConcept 对 P0 级违规（环）硬拦；③ 快照诊断——存量空间的 ⚠️ briefing（把现有 coverage/欠账清单并进来，一个出口而不是三处重复）。
- 前置匹配器统一为一个（exact = 落点；substring = 仅提示），所有消费方（快照/progression/手工连边/空间前置反推）共用。
- **吸收**：P0-1 的正式归属地、P1-4、P2-8、A3、coverage 分散检查。修复方案里的 A1 是本 Move 的第一个消费者，先做不冲突。

### Move 4：数据口径单一权威化（渐进，不搞大迁移）

- 定契约并写进类型注释与快照渲染：**`dl_relation` 边 = 前置的唯一权威**；`attrs.prerequisites` 定位为"待建边队列"（语义已如此，把它变成显式契约）；方案 `layer` 只在确认期有效，落库后一律 `levelsOf` 重算，`attrs.layer` 仅展示参考。
- 证据标注四套方言收敛为一个结构化字段（`attrs.evidence = { kind: 'material'|'prior'|'verified', ref? }`），`source` 枚举恢复注释语义（saveConcept 落 `material`，verify 通过升级 `ai_verified`）。存量数据不回改，读侧做兼容归一。
- **吸收**：P2-4、P2-5、证据方言、匹配口径漂移。

### Move 5：补上闭环的最后一条边——统一工作队列，让地图活起来

把 pace 调度器的候选从 2 类扩为**统一工作队列**，全部复用现有 sendMessage 通道：

| 工作项 | 来源（已存在） | 动作 |
|---|---|---|
| 无卡概念 | listConceptsNeedingResearch | 研究轮（已有） |
| open 问题 | listOpenQuestions | 子研究（已有） |
| coverage 缺口 | assessMapCoverage 九类缺口 | 补全轮（限主干/前置/跨度/粒度四类，对应 map-completion 的 S2） |
| 前置欠账 | collectPrereqShortfalls/RelationGaps | 建边/建点的小额落库轮 |
| **拆解建议** | splitSuggested（现在止步于一次 toast） | 一键拆解：AI 提子概念方案 → 用户确认 → 落库（复用 dl_plan 的 syllabus 机制，挂 parentId） |

优先级 = 阻塞度（下游概念数）× 邻近度（当前在学的概念上游优先）。「AI 补全」按钮从唯一修复入口降级为"手动触发一次全队列扫描"。这一步不是修 bug，是让模块的形态从"规划一次、然后消费"变成第 5 步讨论的"画图 → 学 → 测 → **修图** → 巩固"的完整闭环——也是它区别于"AI 版目录生成器"的核心竞争力。

## 五、路线图

| 阶段 | 内容 | 预估 | 产出 |
|---|---|---|---|
| **Phase 0**（先行） | 修复方案中的不变量子集：A1 防环 + B1 attrs 合并 + D3 + D6；过渡补丁 C1/C2 可选 | 1~2 天 | P0 关闭；任何后续重构都不报废这些改动 |
| **Phase 1** | Move 1 状态机（含存量迁移）+ plan_phase 驱动注入；吸收 D3 补丁 | 2~3 天 | "从文本猜状态"类 bug 绝迹；补全/重排成为显式入口 |
| **Phase 2** | Move 3 map-linter 三消费点 + Move 2 流程收编（技能分段注入、契约退役、contract test、research 提示词三段式） | 3~4 天 | 规划产物过 linter 才见用户；提示词矛盾类问题绝迹 |
| **Phase 3** | Move 4 数据口径归一 + Move 5 统一工作队列（含一键拆解） | 2~3 天 | 学习闭环合拢；地图由测量结果驱动生长 |

合计 8~12 天（纯修补是 5~6 天，多出的是状态机迁移、技能收编和队列的存量兼容）。每个 Phase 独立可发布、可回滚；Phase 1 落地后，修复方案里的 D3/D4/C1/C2 等过渡补丁被自然吸收删除。

## 六、明确不做

- **不重写 harness/规则层/仓储层**——它们是资产；本方案动的是状态来源、注入契约和校验归属；
- **不做自动破环/自动删数据**——不变量违规永远"检测 + 人审"，Move 3/5 都遵守；
- **不搞一次性数据大迁移**——Move 4 的口径归一全部走"写新读旧兼容"，让时间自然收敛存量；
- **不追求提示词文学**——Move 2 的方向是让提示词变短（代码渲染 + 快照引用），不是写得更华丽。

## 七、验收口径（对应第一节的标准）

1. **画图对不对**：空空间跑三阶段 ×3 个不同领域，方案确认弹窗上可见 linter 结果且无悬空前置；换用弱模型跑同样流程，落库条目数 = 已确认方案条目数（不再吃 bootstrap 的 3-8 口径）。
2. **闭环转不转**：造一个缺台阶的图（删掉中间概念）→ 调度队列在 N 个周期内自动提交补全方案；概念两次没懂 → 出现一键拆解入口 → 拆解方案走确认落库。
3. **回归资产**：现有 rules/card 门禁/幂等/预算测试全绿；dl-channel-consistency 与新增 contract test（提示词引用的工具/字段必须存在）常红常清。
