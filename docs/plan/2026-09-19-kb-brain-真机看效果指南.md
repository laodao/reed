# 知识大脑·真机查看效果指南

代码全部就绪（16 提交，78 例测试绿，六轮对抗 review）。本文是真机启动效果的逐步操作指南——所有步骤都在 Electron 应用内完成，需要至少一个可用的 LLM 提供商配置。

## 0. 启动

```bash
cd /home/ubuntu/workdir/the-bot-kb-brain   # worktree（分支 feat/kb-brain）
npm run dev                                 # 或现有启动方式
```

## 1. 开启大脑（一次性）

知识库页 → 选中一个库 → 点「大脑」页签 → 右上「大脑·关」按钮 → 勾选「启用知识大脑」+「自动消化新文档」→ 保存。
- 阈值保持 0.8；「情节模式卡归纳」先不开（成本高，等论断质量验证后再开）。
- 廉价模型路由（可选）：启动前 `export KB_ATOMIZE_MODEL=<便宜模型id>`、`KB_ADJUDICATE_MODEL=<强模型id>`。

## 2. 看消化（核心链路）

上传 1-2 本书（txt/md 优先，先小后大）→ 文档列表等处理完成 → 消化自动开始：
- 文档行「大脑」页签可见论断逐批出现；通知有「消化完成：论断 N 条、合并 N、疑似矛盾 N」。
- 检查点：论断页签看语句质量（自包含？出处引句对不对？）、「悬而未决」数、待审数。
- 疑似矛盾进冲突面处理：`kb:brain:conflicts`（面板后续迭代，先走论断页签 status=suspected 过滤）。

## 3. 看检索升级

检索面板查综合型问题（如「这些书的复仇手法有什么流派」）——对比开脑前后：
```ts
window.electronAPI.knowledgeBase.brain.search({ knowledgeBaseId, query: '...', include: ['chunk'] })       // 存量
window.electronAPI.knowledgeBase.brain.search({ knowledgeBaseId, query: '...', include: ['chunk','atom','note'], intent: 'synthesize' })  // brain
```

## 4. 看提炼（思想卡/设定卡）

点数到重要性阈值后自动提炼；或手动触发：`electronAPI.knowledgeBase.brain.distill({ kbId })`。
→ 「待审提议」出现思想卡（论断式标题+何时用我+证据指针）→ 批准/拒绝。

## 5. 看创作装配

研讨室（长文）会话直接问创作问题——agent 上下文自动带论断/卡片段；或让 agent 调 `kb_brain_query`。剧集制作会话同。

## 6. 看深度研究

面板/调试：`electronAPI.knowledgeBase.brain.research('这个类型的复仇写法有哪些没被做烂的方向')` → 过程事件 + 综合报告卡（synthesis）入收件箱 + 悬置点转 open-question 论断。

## 7. 看学习与导出

- 复习：`brain.reviewNext({ kbId })` → 逐卡 `brain.reviewGrade({ kbId, noteId, rating })`（需 learning.enabled）。
- 导出：`brain.exportSkill(noteId)` → SKILL.md 内容存盘。

## 8. M0 基线（放量前必做）

1. 导评测库 A（同类型小说 3 本节选）→ 全量标注 `eval/fixtures/kb-novels.json` 的 expectedDocumentIds。
2. `npx tsx src/core/platform/services/kb-brain/eval/run-eval.ts --kb <kbId>` → 双模式对比报告落 docs/progress/。
3. 门线：综合型 recall@5 Δ≥+5pt 且事实型 ≥0 → 通过后才放量消化大库。
4. 顺手记录台账成本（`brain.stats`），校准 KB_BRAIN_DAILY_COST_LIMIT。

## 已知边界（诚实清单）

- 真机 LLM 端到端零次验证——POC（原子化质量≥85%/裁决≥80%/对齐≥60%）就是为此设计的，跑完再看放量。
- 划线选区 UI 未做（观感捕捉走对话/面板通道）；深度研究的 agent 工具循环版是服务级编排的升级项。
- P-5 实体窗口、幅度参数（软衰减 180 天、聚类阈值 0.72）需实测调优。
