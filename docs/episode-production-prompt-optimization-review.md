### 2.5 HYP-1：过度强调 JSON 输出是否真的有效？

#### 假设声称

重度 JSON 强调可能无效，轻度强调可能足够。

#### 逻辑链条审查

1. **观察**：✅ 事实
   - 代码中有 8 层 fallback
   - 提示词有重度 JSON 强调

2. **推理**：❌ 逻辑错误
   - 文档推理：有 fallback → 强调无效
   - **问题**：这是逻辑错误
     - 有 fallback 不代表强调无效
     - 可能强调减少了格式问题，但仍有部分问题需要 fallback
     - 正确的因果链应该是：强调 → 减少格式问题 → 但仍有部分问题 → 需要 fallback
   - **正确的推理**：
     - 如果有 fallback 说明格式不稳定，这是事实
     - 但不能推断"重度强调无效"
     - 需要对比三组：重度强调 vs 轻度强调 vs 无强调

3. **验证方案**：❌ 设计有缺陷
   - 文档的 A/B 测试：对照组（重度） vs 实验组（轻度）
   - **问题**：缺少"无强调"组
   - **正确设计**：应该有 3 组
     - A 组：重度强调（当前版本）
     - B 组：轻度强调
     - C 组：无强调（只保留格式说明，不强调）

#### 结论

❌ **逻辑链条有缺陷，A/B 测试设计不完善**

文档应该：
1. 删除"重度强调可能无效"的推理
2. 改为"有 fallback 说明格式不稳定，需要验证不同强调程度的效果"
3. A/B 测试应该包含 3 组（重度 vs 轻度 vs 无强调）

### 2.7 HYP-3：添加 Few-shot 示例能否提升格式稳定性？

#### 假设声称

Few-shot 示例可显著提升格式稳定性。

#### 逻辑链条审查

1. **理论依据**：⚠️ 有问题
   - 文档引用 GPT-3 论文（Brown et al. 2020）
   - **问题**：
     - GPT-3 论文是在英文模型上做的
     - 论文中的任务是简单的 QA 和文本生成，不是复杂的结构化输出
     - 不能直接推导到中文模型和复杂任务

2. **观察**：✅ 事实
   - 分镜生成、场景润色等功能没有 few-shot 示例
   - 代码有多层 fallback

3. **推理**：❌ 逻辑跳跃
   - 文档推理：没有 few-shot + 有 fallback → 添加 few-shot 能提升稳定性
   - **问题**：
     - 已有详细的格式说明，few-shot 可能不会显著改善
     - 需要验证

4. **验证方案**：⚠️ 设计有缺陷
   - 示例中的场景太简单（"茶馆 · 白天 · 张三"）
   - 实际场景更复杂（多角色、多对话、多动作）
   - **问题**：简单场景的示例可能无法代表复杂场景

#### 结论

❌ **理论依据不充分，验证方案不完善**

文档应该：
1. 明确说明 GPT-3 论文的局限性
2. 示例应该包含复杂场景（多角色、多对话）
3. 预期效果"提升 15-30 个百分点"是凭空猜测，应该删除
