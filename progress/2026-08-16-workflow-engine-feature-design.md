# 工作流功能设计（功能层终稿 V1.0）

> 状态：功能设计已评审定稿，作为后续详细设计的依据基准
> 日期：2026-08-16
> 前置调研：详见对话中的选型调研（Vue Flow 画布 + 自研引擎路线、n8n/Dify 许可证不可行结论）

---

## 1. 功能定位（一句话）

让用户把系统里已有的 AI 能力（LLM 对话、长文写作、知识库、图像、语音、翻译、搜索）和少量通用逻辑能力（条件、循环、变量、HTTP）**编排成可重复运行、可观察、可中断续跑的流水线**。

## 2. 用户价值（对比现状）

现状痛点：系统各模块能力是孤岛，每个都要人守着逐步点。比如"写完一章 → 润色 → 生成下一章"、"章节 → 分镜 → 生图 → 配音"，每步都是手动触发、手动搬运上下文。

工作流解决：**一次编排，反复执行；中途可看进度、可暂停、失败可续跑**。

## 3. 已定决策汇总

| 决策点 | 结论 |
|--------|------|
| 定位 | 通用工作流底座，不偏向单一场景 |
| 触发 | 手动 + 定时（cron/预设）+ 事件，三种全做 |
| 人工介入 | 完整支持人工审核节点（批准/修改后批准/驳回/超时策略） |
| 分享 | 仅本机，JSON 导入导出备份 |
| 节点失败 | 重试耗尽走**错误分支**（未画失败连线才中断运行） |
| 错过定时 | Electron 未运行期间错过的调度**跳过**，不补跑 |
| 并发实例 | 同一工作流运行中时新触发**跳过**并记录历史 |

## 4. 用户视角的概念模型

| 概念 | 含义 |
|------|------|
| **工作流** | 一张可编辑的流程图，有名字/描述/图标，带**版本**（每次发布保存新版本，运行记录绑定版本，改图不影响历史） |
| **节点** | 流程中的一步，有类型和配置（如"LLM 对话"节点配置模型、提示词） |
| **运行（Run）** | 工作流的一次执行实例，有独立状态、输入输出、历史记录 |
| **触发器** | 什么情况下启动一次运行：手动 / 定时 / 事件 |
| **变量** | 节点之间传值的机制，`{{某节点.输出字段}}` 引用上游结果 |

## 5. 编排功能（编辑器）

- **画布操作**：拖拽添加节点、连线、框选、对齐、缩放、小地图、撤销/重做
- **节点配置面板**：点击节点右侧滑出，按节点类型动态渲染表单
- **变量引用**：任何输入框可插入上游节点输出（提供变量选择器，不要求手写语法）；开始节点定义整个工作流的**输入参数**（名称/类型/默认值），触发时填写
- **校验**（保存/运行时）：
  - 未连接的节点、无入边的中间节点 → 警告
  - 意外成环（非循环节点形成的环）→ 阻止运行
  - 节点必填配置缺失 → 定位到节点提示
- **版本**：草稿可随时保存；"发布"生成正式版本，只有已发布版本可被定时/事件触发

## 6. 执行功能（运行时）

**运行生命周期**：`排队中 → 运行中 →（等待人工）→ 成功 / 失败 / 已取消`

- **实时观察**：画布上节点按执行状态点亮（待执行/执行中/成功/失败/跳过），右侧日志面板显示节点级输入摘要、输出摘要、耗时、错误信息
- **取消**：运行中随时可取消，正在执行的节点中断
- **重试**：节点可配置"失败自动重试 N 次、间隔 X 秒"
- **断点续跑**：失败或中断的运行，可从断点继续——已成功节点不重跑、直接复用其输出；提供"强制重跑指定节点"选项
- **多运行并行**：不同工作流可同时运行；同一工作流按并发策略（见 §10）跳过新触发

## 7. 人工审核节点（完整支持）

- 运行到审核节点时**挂起**（状态持久化，应用重启后仍保持等待）
- 待审核内容展示上游节点产出（如生成的章节文本），用户可：
  - ✅ **批准**：原样继续
  - ✏️ **修改后批准**：编辑内容后继续（下游拿到修改版）
  - ❌ **驳回**：走"驳回"出边（可接通知/降级逻辑），无驳回连线则终止运行
- 可选**超时策略**：等待超过 X 后自动批准/自动驳回/中断
- 审核记录（谁、何时、改了什么）进入运行历史

## 8. 触发器（三种全做）

| 触发方式 | 说明 |
|----------|------|
| **手动** | 编辑器点"运行"，弹出输入参数表单填写后启动 |
| **定时** | cron 表达式 + 常用人性化预设（每天 9 点 / 每小时等）；Web 端常驻生效；**Electron 端仅应用运行期间生效（明确告知用户）**；错过的调度直接跳过（不补跑） |
| **事件** | 系统事件自动触发，如：知识库文档入库完成、长文章节生成完成、图像生成完成。首批事件源清单在详细设计阶段以代码盘点为准 |

## 9. 首版节点总表

| 分类 | 节点 | 出边 |
|------|------|------|
| 流程控制 | 开始 | 正常×1 |
| | 结束 | 无（可有多个） |
| | 条件分支 | 正常×N（条件表达式） |
| | 并行分支 / 合并 | 正常×N / 多入×1 |
| | 循环（遍历列表） | 循环体入/出 + 完成 |
| | 延时 | 正常×1 |
| | 人工审核 | 批准×1 + 驳回×1 |
| | 变量赋值 | 正常×1 |
| AI 能力 | LLM 对话、知识库检索、知识库入库、联网搜索、翻译、图像生成、TTS、STT、长文·生成章节、长文·润色 | 正常×1 + 失败×0..1 |
| 通用 | HTTP 请求、应用内通知 | 正常×1 + 失败×0..1 |

**错误分支语义**：

- 每个业务节点可选配置一条"失败连线"，重试耗尽后走失败分支（可接通知/降级/人工审核）
- 失败但走了错误分支的节点，状态标记为"失败已恢复"，运行最终状态不受影响
- 画布上节点有三种出边：正常出边（可多条，条件分支）、失败出边（最多一条）、审核节点的批准/驳回出边

## 10. 失败与并发策略（已定）

- **节点级**：重试耗尽 → 有失败连线走失败分支；无失败连线 → 运行中断（失败）
- **触发级**：同一工作流上个运行未结束时，新触发（定时/事件）直接**跳过**，并在历史里记一条 `skipped`（含跳过原因），保证触发行为可审计
- **定时错过**：调度器按"下次到期时间"推进，应用未运行期间错过的时段全部跳过，应用启动后从当前时间起算下次调度

## 11. 运行历史

- 列表页：工作流筛选、状态筛选、触发方式、起止时间、耗时
- 详情页：节点时间线回放（各节点何时开始/结束/耗时）、每节点完整输入输出查看、审核操作记录
- 历史不可篡改，仅可删除整个运行记录

## 12. 导入导出

- 导出：工作流定义（含图结构和节点配置）为 JSON 文件，**不含**运行历史、不含任何密钥（Provider 以配置 ID 引用，导入方自行配）
- 导入：校验节点类型是否存在、格式版本是否兼容，冲突时让用户选择覆盖/新建副本

## 13. 安全与边界（明确的产品行为）

- API Key 永不进入工作流定义——节点只引用 Provider 配置
- userId 数据隔离（沿用现有多租户机制）
- 防失控保护：单次运行最长时长上限、循环节点最大迭代次数上限、节点输出超大时截断存储（可配置）
- Electron 端应用退出时运行中的工作流标记"已中断"，启动后可续跑

## 14. 默认参数策略（详细设计再精调，先定基调）

- 节点重试默认：0 次重试，可选配 1–10 次 + 间隔
- 单次运行最长时长：默认上限 24h，可配置
- 循环最大迭代：默认 100 次，可配置
- 人工审核默认无超时（无限等待），可选配

## 15. 明确不做（V1 边界）

- 代码执行节点（沙箱安全复杂度高）
- 子工作流节点
- 视频合成节点（链路太长，二期）
- 在线模板市场
- 启动补跑错过的定时触发
- 同一工作流并行多运行

## 技术方向备忘（详细设计阶段的输入，非功能需求）

- 路线：自建（Vue Flow 画布 MIT + 自研 DAG 执行引擎），n8n（Sustainable Use License 限制嵌入）/ Dify（修改版 Apache 2.0 + Python 架构不匹配）均不可行
- 引擎置于 `src/core/modules/workflow/`，双端（Electron IPC / NestJS Controller）调用同一 Service
- 数据模型：`workflow_definitions` / `workflow_runs` / `workflow_node_runs` 三表，graph 存 JSON，节点级检查点支持断点续跑
- LLM 节点内部可复用 AgentService（Vercel AI SDK 适配 BaseProvider，见 2026-08-16 harness 调研结论）——agent 是节点内部循环，workflow 是节点间编排
