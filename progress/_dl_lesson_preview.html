2 为什么“工作应用”要从张量开始 这块没懂

《深度学习》一书在正式讲深度学习之前，先安排了一整章线性代数，理由是：

"A good understanding of linear algebra is essential for understanding and working with many machine learning algorithms, especially deep learning algorithms."

落到日常工程里，张量这件事支撑三类具体工作（后两类来自工程先验，待查证）：

  1. 看懂报错：RuntimeError: The size of tensor a (3) must match the size of tensor b (4) 这类信息，本质是形状规则没对齐；
  2. 估算资源（先验待查证）：参数数量、激活占用、显存峰值都要从形状算出来；
  3. 对齐数据接口（先验待查证）：模型、数据集、部署导出工具对维度顺序（如 NCHW / NHWC）的约定不一致时，要先看形状再改代码。
3 先看例子：五个真实形状 这块没懂

先例后律——先把数字看熟，再谈定义。

对象 形状 读法 元素个数
一次训练的整体损失值 () 0 维，就是一个数 1（例如 0.6931）
一个样本的特征向量 (784,) 1 维，784 个特征 784

逐式计算（每一步只做一个运算）

  1. 图像批的元素个数：224×224 = 50176；3×50176 = 150528；32×150528 = 4816896。即约 481 万个数。
  2. 这批图像的 float32 显存：4816896×4 = 19267584 字节；19267584÷1048576 ≈ 18.4 MiB（尚未包含中间激活）。
  3. 权重参数量：784×128 = 100352；再加 128 个偏置：100352+128 = 100480，即约 10 万个参数。
  4. 一次前向的乘加次数：32×784 = 25088；25088×128 = 3211264，即约 321 万次。
4 定义：张量到底是什么 这块没懂

张量 = 一批同类型的数值，按规整的网格排列，轴的数量可以任意。

标量、向量、矩阵都不是新东西，而是它的三个特例：

  • 《深度学习》第2章的定义："A scalar is just a single number, in contrast to most of the other objects studied in linear algebra, which are usually arrays of multiple numbers."
  • 关于向量："A vector is an array of numbers. The numbers are arranged in order. We can identify each individual number by its index in that ordering."

于是：

阶（轴数） 常见叫法 形状例子
0 标量 ()
1 向量 (784,)
2 矩阵 (784, 128)
3 及以上 高阶张量（统称张量） (32, 3, 224, 224)

工程上，一个张量必须同时记住四件事：形状 shape（每个轴多长）、数据类型 dtype、所在设备 device（CPU/GPU）、是否求梯度 requires_grad。养成先 print(x.shape, x.dtype) 的习惯，能省掉大量排查时间（后三项为框架通行做法，本讲未取得官方文档原文，标为先验待查证）。

5 三类核心运算与它们的形状规则 这块没懂

规则一：逐元素运算——形状必须一致

NumPy 文档的表述："In the simplest case, the two arrays must have exactly the same shape." 示例中的 a = [1., 2., 3.]、b = [2., 2., 2.]，对应位置相乘：1×2 = 2；2×2 = 4；3×2 = 6，结果是 [2., 4., 6.]，形状仍是 (3,)。

规则二：广播（broadcasting）——形状不同也能算

NumPy 文档原文："The term broadcasting describes how NumPy treats arrays with different shapes during arithmetic operations. Subject to certain constraints, the smaller array is 'broadcast' across the larger array so that they have compatible shapes."

执行办法：把两个形状从最右边对齐，逐轴比较：相等 → 通过；其中一个为 1 → 把它“拉伸”到另一个；都不是 1 且不相等 → 报错。

例 A：(3,1) + (1,4)

  • 轴 1 上 4 对 1 → 通过；轴 0 上 3 对 1 → 通过；结果形状 (3,4)。
  • 取 a=\begin{bmatrix}10\20\30\end{bmatrix}，b=\begin{bmatrix}1&2&3&4\end{bmatrix}，逐项相加：
    • 第 1 行：10+1 = 11；10+2 = 12；10+3 = 13；10+4 = 14
    • 第 2 行：20+1 = 21；20+2 = 22；20+3 = 23；20+4 = 24
    • 第 3 行：30+1 = 31；30+2 = 32；30+3 = 33；30+4 = 34
  • 结果：\begin{bmatrix}11&12&13&14\21&22&23&24\31&32&33&34\end{bmatrix}。输入一共只有 3+4 = 7 个数，输出有 12 个数。

例 B（工作中最常见）：加偏置 (32,128) + (128,) —— (128,) 右对齐后视作 (1,128)，再广播成 (32,128)，即“同一组偏置加到 batch 里每个样本上”。

例 C（最常见的一类 bug）：(3,) + (4,) —— 3 ≠ 4 且都不为 1，直接报错。

规则三：矩阵乘法——只看内维

要求前一个的最后一轴 = 后一个的倒数第二轴：(2,3) @ (3,2) 得到 (2,2)。

取 A=\begin{bmatrix}1&2&3\4&5&6\end{bmatrix}，B=\begin{bmatrix}1&0\0&1\1&1\end{bmatrix}，逐项算（每步只做二元运算）：

  • 第 1 行第 1 列：1×1 = 1；2×0 = 0；3×1 = 3；先 1+0 = 1，再 1+3 = 4
  • 第 1 行第 2 列：1×0 = 0；2×1 = 2；3×1 = 3；0+2 = 2，再 2+3 = 5
  • 第 2 行第 1 列：4×1 = 4；5×0 = 0；6×1 = 6；4+0 = 4，再 4+6 = 10
  • 第 2 行第 2 列：4×0 = 0；5×1 = 5；6×1 = 6；0+5 = 5，再 5+6 = 11

结果 AB=\begin{bmatrix}4&5\10&11\end{bmatrix}，形状 (2,2)。工作量：2×2 = 4 个输出元素，每个元素 3 次乘加，4×3 = 12 次乘加。

带 batch 的版本（工程通行约定，先验待查证）：(B, m) @ (m, n) 得到 (B, n)，即“每个样本各自乘同一个权重矩阵”。上面 (32,784) @ (784,128) 得到 (32,128) 就是这一条。

a = np.array([[1., 2.], [3., 4.]])          # 形状 (2, 2), 默认 float64
b = torch.tensor([[1., 2.], [3., 4.]])      # 形状 torch.Size([2, 2]), 默认 float32

b.shape, b.dtype, b.device, b.requires_grad # 张量的四个“身份牌”

逐元素乘 a * a b * b
矩阵乘 a @ a b @ b

一条实用习惯：任何一层运算之前，先打印参与运算的 shape，再决定要不要 reshape / transpose——这比读完栈报错更快。

7 常见坑（都从形状规则长出来） 这块没懂
  1. 广播不是“更聪明的复制”，但它可能悄悄吃内存。NumPy 文档明确提醒："There are, however, cases where broadcasting is a bad idea because it leads to inefficient use of memory that slows computation."（先验补充：用 (N,1) 与 (1,N) 相减去构造方阵时尤其危险。）
  2. 形状对得上，语义却错了（先验待查证）：(B, C) 与 (C, B) 在方阵情形下都能算，但含义完全不同。
  3. 维度顺序的约定不一致（先验待查证）：PyTorch 图像常用 NCHW，部分部署/移动端工具偏好 NHWC，转换时要显式确认。
  4. dtype 不一致（先验待查证）：NumPy 默认 float64、框架参数默认 float32，混用会报类型错或悄悄降精度；整型张量相除会被截断。
  5. 转置后的连续性（先验待查证）：转置只改“怎么读”，不搬数据，随后直接 view 可能失败，需要 contiguous() 或改用 reshape。
8 自测（先自己做，再对答案） 这块没懂

Q1 形状 (32, 3, 224, 224) 一共有多少个数？若为 float32，占多少字节？

Q2 a=\begin{bmatrix}1\2\3\4\end{bmatrix}（形状 (4,1)）与 b=\begin{bmatrix}10&20&30\end{bmatrix}（形状 (1,3)）相加，结果形状是什么？第 2 行是什么？

Q3 (2,3) 与 (3,) 能相加吗？如果能，输出形状是什么？这个操作在工作中常用来做什么？

Q4 为什么 (2,3) @ (2,3) 报错？怎么改？

Q5 一个 (784, 128) 的全连接层有多少个参数（含偏置）？一批 (32, 784) 过它的乘加次数是多少？

显示答案（建议先自己做）
  • A1 元素个数：224×224 = 50176；3×50176 = 150528；32×150528 = 4816896 个数。float32 每数 4 字节：4816896×4 = 19267584 字节；19267584÷1048576 ≈ 18.4 MiB。
  • A2 (4,1)+(1,3)：轴 1 上 3 对 1 → 通过，轴 0 上 4 对 1 → 通过，结果 (4,3)。第 2 行是 2 分别加 10、20、30：2+10 = 12；2+20 = 22；2+30 = 32，即 [12, 22, 32]。
  • A3 能。(3,) 右对齐后视作 (1,3)，广播成 (2,3)，所以输出是 (2,3)——这正是“给每个样本减去同一个均值向量 / 加上同一组偏置”的写法。
  • A4 矩阵乘要求内维相等，这里 3 与 2 不相等。改成 (2,3) @ (3,2) 得到 (2,2)，即把第二个张量做最后两轴的转置 B.transpose(-1,-2)（也可调换两操作数顺序）。
  • A5 参数：784×128 = 100352，再加 128 个偏置得 100352+128 = 100480；乘加次数：32×784 = 25088，25088×128 = 3211264。
