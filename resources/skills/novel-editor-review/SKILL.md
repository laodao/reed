## 任务输入

- 被审内容：{{param.content}}
- 内容类型：{{param.content_type}}
- 题材标签：{{param.genre}}

## 审阅顺序

严格按以下顺序推进，先宏观后细节：

1. **先判四件事**：题材标签是否清晰、目标读者是否明确、一句话卖点是否成立、全稿最大的问题是什么（编辑第一判断）。
2. **再分项审阅**：开篇 → 主角 → 人物关系 → 节奏 → 情绪回报 → 差异化 → 连载扩展性。

## 核心判断清单

逐项检查，能对应到具体文本的必须引用原文位置：

1. **钩子时效**：前 100 字、前 500 字和第一章是否尽快出现人物、事件、冲突和继续阅读理由。
2. **主角**：是否有明确目标、具体困境、主动行为、可识别人格，以及持续制造剧情的能力。
3. **故事发动机**：核心设定是否能反复制造冲突，而不是只停留在简介里。
4. **情绪回报**：爽点、甜点、虐点、燃点、悬念是否及时，情绪回报是否与铺垫匹配。
5. **多线互推**：感情线、事业线、复仇线或升级线是否互相推动。
6. **结构闭环**：前三章是否形成小闭环，前十章是否持续升级或产生有效变体。
7. **差异化**：与同类相比的真正差异点是什么；哪个卖点应进入简介、导语和开篇。

## 修改意见规则

- 每条意见必须对应原文、设定或章节规划的具体位置。
- 每条意见必须说明它影响阅读、留存或投稿的原因。
- 每条意见必须给出明确的修改动作；必要时给原创示例方向，但不仿写具体作品。
- 禁止"有吸引力""不够新"式空泛评价。
- 推荐输出顺序：编辑第一判断 → 题材与读者 → 卖点 → 开篇 → 人物 → 关系 → 节奏 → 连载 → 差异化 → 优先修改的 3—5 个动作。

## 连载风险清单

对长篇或连载规划，必须逐项检查并给出配套修正方式：

1. **主线可持续性**：主线是否能持续产生新问题。
2. **爽点重复**：同一爽点是否被机械复用。
3. **逐级升级**：反派和目标是否逐级升级。
4. **配角功能性**：配角是否承担剧情功能，而非工具人堆砌。
5. **感情线停滞**：感情线是否长期原地踏步。
6. **中段疲软成因**：是否因误会拖延、设定耗尽或单一打脸循环导致中段疲软；每项风险必须配一条修正方式。

## 与本系统的分工

本 Skill 做的是"商业性 / 可读性"评审。设定与正文的一致性（死亡、关系、物品、伏笔等矛盾）由长文写作模块的 R1-R10 一致性扫描负责，两者互补、不重复。建议用法：

- 在故事研讨室的大纲阶段，作为大纲共识前的商业性门禁补充。
- 在章节写作"章法五步"的写后三重审读之外，作为第四维度（市场/编辑视角）的审读意见。

## 交付与门禁

- 当审稿报告作为落盘交付物产出时，使用 `node scripts/creative-run-gate.cjs` 做阶段门禁与交付前校验，按 init → enter → accept → check → validate 流程推进；校验不通过时不得声称完成。
- 交付物缺少核心板块（编辑第一判断 / 分项审阅 / 优先修改动作）、含占位符，或泄露内部检查过程/门禁日志时，不得回复"已完成"，必须先补齐或修正。
- 审稿结论写入研讨室共识账本或设计文档时，只写结论与修改动作，内部检查清单不进入正文。
