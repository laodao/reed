## 输入参数

- 片段分镜：{{param.storyboard_segment}}
- 关键帧清单：{{param.keyframes}}
- 时长：{{param.duration}} 秒
- 画幅：{{param.aspect_ratio}}
- provider：{{param.provider}}

## 核心原则：画面元素让关键帧图承担

关键帧图已承载构图、材质、服装、光源方向、色温、道具位置等画面元素，prompt 文字**不再复述**这些（避免与图冲突、双重解释）。文字只负责四类内容：

1. **运镜**（把分镜的枚举 key 转写成自然语言：`tracking_right`→"镜头匀速水平向右平移"）。
2. **动作**（肢体细化+量化参数，见下文）。
3. **剧情推进**（时间段内发生什么、因果承接）。
4. **声音**（台词/音效/音乐/旁白，符号协议见下文）。

连续性维度（角色面部一致、服装剪裁、道具尺寸/锁扣位置不移位）用**负向约束**写在末尾约束段，不在正文复述。

## 关键帧 = 时间锚点声明

每张关键帧在 prompt 开头声明：**时间锚点身份 + 命中判定标准 + 对应绝对时间点**——

- **首帧**：0 秒开场画面必须与其一致。
- **中段锚点**："9-12 秒画面必须经过此帧状态（决定性瞬间）"。
- **尾帧**："12-15 秒收束画面必须落到此帧状态"。
- **承接参考帧**：上一片段的尾帧传入时标注为"承接参考帧"（连续性参考，非本片段首帧）。
- 单张关键帧默认作首帧；对应镜头不在 0 秒起点时声明为对应时间点的中段锚点。微电影向"光影转折"帧可在运镜描述里补一句状态提示（"色温从冷转暖"），但不展开光源细节。

场景资产图默认不再传入视频阶段（关键帧已承载场景信息），仅当关键帧只有 1 张且无法完整表达空间时才补传并说明原因。

## 分镜映射表（每个视频一份，全链路回溯）

```markdown
| 视频 | 集数 | 章节 | 片段 | 片段时间 | 使用镜头 | 分镜原文摘要 | Prompt 时间段 | 关键帧对齐 |
|---|---|---|---|---|---|---|---|---|
| 片段一视频(15s) | 第1集 | 第一章 遗物 | 片段一 | 00:00-00:15 | 镜头1 | 林远推门，斜光尘埃 | 0-3 秒 | KF01 首帧(空间锚点) |
| 片段一视频(15s) | 第1集 | 第一章 遗物 | 片段一 | 00:00-00:15 | 镜头4 | POV 俯看铁盒 | 9-12 秒 | KF02 中段锚点(决定性瞬间) |
```

每个 prompt 时间段必须能追溯到集/章/片段/镜头编号与分镜原文；找不到分镜原文或时间戳不连续时，停止生成并回到分镜阶段补齐。

## 时间戳动作规划（带量化参数）

把分镜绝对时间戳转成 `0-3 秒`、`3-6 秒` 连续动作规划；相邻镜头动作连续可合并，但必须保留因果。动作描述带量化参数：

- 运镜速度（"以 0.6m/s 匀速水平右移"）、步频（"每秒 1 步渐缓至静止"）、晃动幅度（"0.5° 幅度轻微晃动"）、停留时长（"停留约 1 秒"）、动作幅度（"扫开约 3cm 宽的灰痕"）。
- 音乐节拍（"约 60 BPM"）、音效时长与间隔（"吱呀声两声，间隔约 1 秒"）。
- 情绪用外化细节（"眉头微微收紧、下颔线绷紧"），不写抽象词。

**声音符号协议**（从分镜继承）：音乐 `()`、音效 `<>`、台词 `{}`、旁白 `『』`、字幕 `【】`。非中英文台词标注语种。

**多主体场景**：开头用稳定标签定义主体（"@图1 中的高个子男人是警察"），后续每次涉及该主体都明确指代、不省略主语。

## 负向约束尾巴（默认必带）

prompt 末尾必须加入："禁止生成字幕、文字、LOGO、水印"。只有用户明示要字幕才移除"禁止生成字幕"（无关文字/LOGO/水印仍禁）。常规连续性负向：禁止人物面部漂移、服装颜色/剪裁变化、道具尺寸/位置漂移、道具消失、无关角色乱入、穿模卡顿。

## Provider 适配要点（{{param.provider}}）

**Seedance（火山方舟，默认）**
- 时长 4-15s（请求会被 clamp 到该区间）；比例支持 16:9/9:16/1:1/4:3/3:4/21:9；分辨率 480p/720p/1080p。
- **generate_audio=false**：视频模型不出声。台词/音乐/音效在 prompt 里只作"声音设计标注"，实际音频由独立 TTS/配乐环节生成后合成——不要指望视频模型生成人声台词，台词时长只需与镜头时长适配。
- 图生视频传 1 张参考图（首帧语义）。

**MiniMax-H3（局域网网关，自带配音）**
- ≤15s（24fps，时长→帧数 秒×24+1，上限 362）；比例仅 9:16/16:9；分辨率 480x864/704x1248。
- **refs 上限 2 张**：Picture 1=首帧、Picture 2=尾帧；中段锚点关键帧不传给该 provider，只在 prompt 文字里保留锚点语义。
- **自带配音/环境声**：台词 {} 与环境音可以直接写进 prompt 由模型发声。
- **三段式 prompt 协议**：若上游 prompt 未含 `subject_definitions:` / `summary:` / `retention_analysis:` 三段，网关会自动包裹；你也可以直接按三段式写——subject_definitions 声明各 Picture 与主体外观来源，summary 放镜头描述（前缀 `[reference generation + audio reference]`），retention_analysis 声明主体保持策略。

**万相（阿里百炼，wanx）**
- 以**图生视频为主**（wanx2.1-i2v-plus 系列），文生视频可用但图生效果更稳；本地图片经临时上传/OSS 转 URL。
- prompt 聚焦首帧出发的动作与运镜描述，首尾双帧支持取决于具体模型版本，规划时默认按单首帧。

## 质量检查（生成前逐条确认）

- 映射表已列出，每个时间段可回溯到分镜镜头编号与原文。
- 关键帧全部声明了时间锚点身份+命中标准+绝对时间点；承接参考帧标注正确。
- 文字未复述关键帧图已有的画面元素；连续性约束以负向形式落在末尾。
- 时长、比例、provider 适配要点已按上文核对。
- 负向尾巴"禁止生成字幕、文字、LOGO、水印"已带（用户明示要字幕除外）。

## 输出格式

每个视频用一句话介绍 + Markdown 语法展示（`![片段一视频](...)`），并附完整 prompt 文本供提交/调优。

## 与本系统管线的衔接

- 输出 prompt 流入 **video-generation.service**：按 storyboards.videoProviderId/videoModelId 提交任务，providerTaskId 落库供重启恢复查终态。
- 关键帧数决定 video_mode（0→text2video / 1→image2video / ≥2→keyframes2video），provider 不支持时自动降级（keyframes2video→image2video→text2video），超帧数上限时均匀采样保首尾。
- MiniMax-H3 只取 start/end 两帧作 refs；中间帧仅参与 prompt 锚点声明。
- Seedance generate_audio=false，prompt 中的 {}台词/()音乐/<>音效 是给独立 TTS/配乐环节的需求单，不是给视频模型的。
- 生成结果 videoPath 回写 storyboards 行，include_in_final=1 的分镜进入最终合成。
