## 1. 里程碑

### M4-A 架构合规整改(先)
- 依据 4 个横切子代理审查报告(数据层 3NF / 服务-宿主 harness / IPC-包-前端接线 / 横切规范),整理为 tasks/2026-09-09-domain-learning-m4-review-fixes.md 整改清单(P0/P1 全改,P2 择优);
- 改项典型:重复 buildTree/stats/normalize-parse/JSON safeParse 收敛;魔法串集中为枚举/常量(状态/trigger/视图种类/侧重词/关系标签/时间键/技能 id);空 catch/无日志路径补齐;错误结构化/审计;巨型组件按需拆分;shared 常量去前端重复;ForceGraph/基座复用确认;每改一项跑对应单测/回归(仍 TDD),不得复制粘贴与另造基座;
- 收尾:全 dl 单测 + 相关平台 spec 回归,tsc/vue-tsc 零新增。

### M4-B 知识库关联 + 三重来源生成(后)
- 数据/服务:建空间参数与 UI 增「绑定知识库(kbId)」选择;新增 dl:set-space-kb(改绑);校验 kb 归属与有效;
- 宿主检索:研究模式快照注入「本空间绑定 KB 信息」+ 提示词检索纪律(KB 命中优先、evidence 回链 kbDocId);把空间 kbId 作为 wf_kb_retrieve 的默认 kb 上下文(核对工具参数签名,必要时在绑定静态参数/工具层透传);
- 内容编排:research prompt 明确定序 —— KB 检索(命中→提炼落卡)→ 联网(http_get/wf_web_extract/arxiv,web_search 有默认源才用)→ 仍不足+先验有把握→初稿待验证(needs_verification)→ 人审;evidence_sources 允许 {kind:kb, kbDocId} 并在讲义/档案展示 KB 出处;
- 前端:建空间对话框与空间设置加 KB 选择(可空=不绑);讲义 evidence 展示 kb 来源标识;
- TDD:绑定/改绑校验、检索缺省注入、digest/stats 含 KB 绑定不影响;真机:离线环境用「本地 KB 文档」验证 KB 命中出卡(需要 KB 可程序化建文档;若不可,记录复验方案)。

### M4-C 收口

## 2. 验收口径
- M4-A:审查清单逐项闭环(改完打勾)+ 单测回归绿 + 无新架构违规;
- M4-B:建绑/改绑 IPC+UI 可用;研究宿主 KB 检索注入生效(离线用 KB 文档或记录);证据纪律不放松;

## 3. 风险
- 审查结论量大:按严重度排序分批发;先 P0/P1 合并为若干“整改提交”;

- 收敛重复实现可能触碰其它包(如 ForceGraph 被长文用)——以既有 spec 回归为准。
