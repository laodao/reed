## 0. 为什么重做（需求还原）

用户反馈原"知识全景=一个对话框里的一张图"是错的，三点要害：

1. **承载**：全景是新开 Tab 页，不是弹窗；
2. **内容**：不只是一张概念图——要按**知识类型**体系化展示（概念/原理/论文/方法/规范…），且**不同类型领域侧重不同**（研究型看重论文/公理/定义/最新成果；金融/经济应用型看重法规/操作规范/案例）；
3. **交互**：每个知识点可点击 → 打开该知识点的**子图谱**（一阶邻居聚焦），可继续下钻；全景是领域知识体系的**提纲挈领**视图。

"研究型 vs 应用型"只是举例——**先建立完整的领域类型分类体系**（有哪些领域、各侧重什么知识、适合什么展示），Atlas 的展示配置以该体系为底座。

## 1. 领域知识类型学（核心交付）

### 1.1 三维框架

结合 [Biglan 学科分类（硬/软 × 纯/应用 × 生命/非生命）](https://itechdct.ntcu.edu.tw/ntcudct_courses/DigitalCommunication/resource/06_web//11016_web/NIT110111_%E4%B8%AD%E6%96%87/%E4%BB%A5%E6%8E%A2%E7%A9%B6%E7%A4%BE%E7%BE%A4%E7%90%86%E8%AB%96%E6%9E%B6%E6%A7%8B%E6%8E%A2%E8%A8%8E%E8%87%BA%E5%A4%A7MOOCs%E8%A8%8E%E8%AB%96%E5%8D%80%E8%87%A8%E5%A0%B4%E6%84%9F%E5%B1%95%E7%9A%84%E5%AD%B8%E7%A7%91%E5%B7%AE%E7%95%B0) 与知识维度框架（[Bloom/Marzano：事实-概念-程序-元认知](https://vle.upm.edu.ph/pluginfile.php/151922/mod_resource/content/1/Marzano%20and%20Kendall%20Taxonomy.pdf)），领域类型用三个轴描述：

| 轴 | 取值 | 含义 |
|---|---|---|
| 共识度 | 高共识 ↔ 低共识 | 范式是否统一、答案是否可判定（数学高、文学理论低） |
| 实践度 | 纯理论 ↔ 强实践 | 知识目的是解释世界还是改造/操作世界 |
| 对象 | 非生命 ↔ 生命/社会/人造 | 研究对象的性质（决定能否实验、是否含规范） |

### 1.2 领域大类清单（M1 覆盖的预设，用户可自定义扩展）

| # | 领域类型 | 典型例子 | 共识度 | 实践度 | 知识构成侧重（高权重类型） | 高频展示方式 |
|---|---|---|---|---|---|---|
| T1 | 形式科学/硬理论 | 数学、理论物理、理论CS、逻辑 | 高 | 低 | 定义/公理/定理/公式、概念、证明方法、开放问题 | 公式推导树、概念-定理分层图、大纲树 |
| T2 | 实证硬科学 | 物理、化学、生物、医学基础 | 高 | 中 | 概念、理论/模型、**实验方法**、数据/证据、**论文**、争议 | 概念网络图（方法/证据联结点）、时间线（发现史） |
| T3 | 软科学/人文社科理论 | 历史、哲学、社会学、经济学理论、文学批评 | 低 | 低 | 概念/术语、理论/学派、**人物/作品**、争议/流变 | 时间线（思想演进）、学派-概念地图、对比矩阵 |
| T4 | 工程技术/硬应用 | 软件工程、电子、机械、AI 系统、网络 | 中 | 高 | 概念、原理、**方法/架构/协议**、工具/框架、规范/标准、案例 | 系统架构分层图、技术栈依赖图、流程/状态图 |
| T5 | 专业实务/软应用 | 金融投资、法律、财会、医学临床、管理 | 中低 | 强 | 概念、**法规/监管/政策**、**操作规范/流程**、案例/判例、数据/指标、风险 | 法规-概念-操作三层结构、合规矩阵、流程状态图、案例库 |
| T6 | 技艺/创作 | 设计、音乐、写作、影视、游戏 | 低 | 强 | 概念/原则、**风格/作品**、方法/技法、练习/反馈 | 作品集/画廊、风格谱系图、作品-技法对照 |
| T7 | 前沿/交叉新兴 | 大模型、量子计算、区块链、生物信息 | 中 | 中 | 概念、论文/预印本、方法、基准/数据集、**最新成果**、开放问题 | 论文-方法时间线、成果更新流、概念网络（演进快，常刷新） |

设计含义：**M1 内置 5~7 个预设领域画像（profile）**，每个画像声明 `侧重知识类型集 + 默认视图集 + 排序`。建空间时用户选一个画像或自定义。画像决定：研究/提取时多收什么、Atlas 显示什么、默认先展示哪个视图。

### 1.3 知识单元类型（节点类型全集，跨领域统一枚举）

Atlas 的节点不只有"概念"。统一枚举（前端/数据层一致），领域画像 = 从中挑选并加权：

| 节点类型 | 说明 | 领域权重示例 |
|---|---|---|
| concept 概念/术语 | 领域基本单元（是什么） | 全部领域 ★ |
| fact 事实/数据 | 具体实例、数据集、指标、参数 | T2/T5/T7 ★★ |
| definition 定义/口径 | 形式化定义、术语口径 | T1/T3/T5 ★★（T5 需"法定口径"） |
| axiom 公理/定理/公式 | 可推导的形式陈述 | T1 ★★ |
| theory 理论/模型/框架 | 解释性结构（为什么） | T2/T3/T7 ★★ |
| method 方法/算法/流程 | 做法（怎么做） | T2/T4/T6 ★★ |
| artifact 工具/系统/实现 | 具体实现物 | T4/T6 ★ |
| paper 论文/文献/成果 | 知识一手载体 | T2/T3/T7 ★★、T4/T5 中 |
| standard 标准/协议 | 技术标准、接口规范 | T4 ★★ |
| regulation 法规/政策 | 约束性规则 | T5 ★★ |
| procedure 操作规范/作业流程 | 合规/操作要求 | T5 ★★、T4 中 |
| case 案例/判例/场景 | 情境化知识 | T5 ★★、T2/T4/T6 中 |
| person 人物/机构/学派 | 生产者与共同体 | T3 ★★、T2/T7 中 |
| controversy 争议/开放问题/前沿 | 未知区与未决点 | T1/T2/T3/T7 ★、研究型必标 |
| principle 原则/价值观 | 判断准则（偏 T5/T6） | T5/T6 ★ |

关系类型（边）也按节点类别分层：概念-概念（is-a/part-of/前置依赖/因果/对比）、概念-载体（定义出自 / 方法应用于 / 受……约束）、载体-载体（论文引用/标准兼容/规范更新）。

### 1.4 展示方式（表示选择逻辑）

依据"什么性质的知识配什么图式"（[知识可视化表示选择](https://eric.ed.gov/?ff1=pubJournal+Articles&q=stage&ff2=souEducation+and+Information+Technologies&id=EJ1402629)、[Knowledge scaffolding visualizations](https://kmel-journal.org/ojs/index.php/online-publication/article/view/278)）：

| 展示视图 | 擅长表达 | 适合节点类型 | 领域默认 |
|---|---|---|---|
| 概念网络图（力导/分层） | 关系、结构、邻接 | concept/theory/method/paper | 全部（默认主视图） |
| 分类树/大纲 | 层级、包含、总-分 | concept 体系、taxonomy | 全部（左栏常驻） |
| 时间线 | 演进、历史、成果序列、版本 | paper/person/争议(流变)、artifact 版本 | T2/T3/T7 默认增强 |
| 矩阵/对比表 | 维度对比、口径对照 | theory vs theory、regulation 条款对照 | T3/T5 增强 |
| 流程/状态图 | 步骤、状态机、合规路径 | method/procedure、case 流程 | T4/T5 增强 |
| 三层结构（法规-规范-概念） | 约束怎么落到操作 | regulation→procedure→concept | T5 专用视图 |
| 档案卡/详情 | 单点完整信息 | 任意节点 | 点击任何节点 |
| 架构分层图 | 系统分层/模块 | artifact/架构 | T4 增强 |

## 2. Atlas 概念设计（全景 Tab 页）

### 2.1 承载与路由

- **独立 Tab 页**（应用标签栏，非弹窗）：路由 `/domain-learning/:id/atlas`；从空间页头部"知识全景"进入（preloadTab 打开新标签），空间页 ↔ Atlas 可互跳。
- 复用既有标签机制：`useTabsStore().preloadTab(path, title)` + router.push（现成先例：长文项目打开编辑器 Tab）。

### 2.2 页面结构（提纲挈领）

```
┌ 顶栏：领域名 + 领域画像(类型/侧重标签) + 掌握度总览 + 视图切换器 + [回到讲义空间] ┐
├───────────────────────┬────────────────────────────────────────┬───────────────────┤
│ 左：结构索引(大纲树)     │ 主视图(可按画像切换)                     │ 右：选中节点档案     │
│ 按 画像侧重类型 分组     │ - 概念网络图(默认, 类型着色/可过滤)        │ - 定义+掌握度+来源   │
│ 可搜可过滤、显示掌握度   │ - 时间线(若画像开启)                      │ - 关系列表(按类型分组)│
│ 点击定位/高亮主视图       │ - 矩阵对比(若画像开启)                   │ - 关联内容: 论文/方法 │
│                        │ - 流程/三层结构(若画像开启)               │   /规范/案例/最新成果 │
│                        │ 点击节点→聚焦子图(一阶邻居,其余淡出)        │ - [去学] [打开子图谱] │
│                        │ 布局/图例/过滤控件                        │                     │
└───────────────────────┴────────────────────────────────────────┴───────────────────┘
```

### 2.3 交互（语义缩放三级跳）

1. **全局**：默认显示整个领域的关系网络（节点≤几百可全览；更多则按画像/分组自动分区）；
2. **聚焦**：单击节点 → 主视图平滑聚焦到该节点 + 一阶邻居（focus+context，非邻居淡化/隐藏），同时右栏出档案；
3. **子图谱下钻**：档案中"打开子图谱" → 主视图中心变为该节点（面包屑：全局 > 子方向 > 节点，可逐级回退），可继续点下一跳——即你说的"点击后打开这个知识点的图谱"。

视图切换器 + 左栏大纲树构成"图的盲区兜底"：文字树保证不读图也能提纲挈领；图保证关系可见。

### 2.4 档案侧栏（节点详情，含"关联的内容"）

选中任意类型节点，右侧档案按 **该节点类型模板** 渲染（统一结构，字段随类型）：
- 头部：名称/类型徽标/掌握度/来源
- 定义与解释（含 evidence 出处）
- 关系分区（"它是…的上位/它依赖…/它被论文X提出/它受法规Y约束"分组列出，可点击跳转）
- 关联内容区：论文列表、方法/原理、规范条款、案例、最新成果（按画像加权排序）
- 操作：[去学它]（跳空间页讲义）/[打开子图谱]（聚焦下钻）/[标记懂没懂]

## 4. 数据模型影响（设计标注，本期原型先 mock）

- dl_concept 扩为类型化节点：+`node_type`（§1.3 枚举）、`attrs(json: 定义/公式/链接/来源…)`；
- dl_relation 类型集扩到"概念-载体/载体-载体"；
- 新增"载体型节点"独立落表或并入节点表（本期：并入 dl_concept，node_type 区分）——规模仍是 SQLite 几百~几千节点，不引图数据库；
- dl_project 增 `profile`（§1.2 预设画像 id / 自定义 json）。
- 详情档案的"关联内容"由画像 + 节点类型派生查询（服务端聚合）。

## 5. 前端实现（原型/正式共用基础）

- **图谱技术：统一长文写作的自绘 SVG（用户要求，不引入 G6/vis-network）**。已核实 `components/longwriting/graph/GraphView.vue`：纯自绘 SVG、零图库依赖，自带——
  - 力导向布局（排斥 + 边吸引 + 中心引力 + 碰撞分离防重叠：`layout()`/`collidePass()`）；
  - viewBox 缩放/滚轮锚点缩放/拖拽平移/适应视图（`zoomAt`/`onWheel`/`onSvgMouse*`/`fitView`）；
  - 节点拖动；点击选中 → 高亮一阶邻居其余淡化（`highlightSet`/dim），点空白取消；
  - 右侧实体详情栏（基本信息/相关实体点击跳转/状态时间线/事件）。
  - Atlas 的 `AtlasGraph.vue` 复用同一套实现思路（力导向布局与视口交互与其同源），节点类型着色/形状、档案内容随领域画像变化。
  - **正式化时抽取公共力导向组件**（`components/common/ForceGraph.vue`），让长文 GraphView 与 Atlas 共用，避免两套漂移——本期原型先"同源实现"验证形态，抽取放 M2。
- 组件划分：
  - `DomainAtlas.vue`（Tab 页骨架：顶栏/左树/主视图/右档案/面包屑）
  - `AtlasGraph.vue`（自绘 SVG：力导向布局 + 视口 + 节点拖动 + 点击聚焦高亮 + 类型着色）
  - `AtlasTree.vue`（大纲树）
  - `AtlasTimeline.vue` / `AtlasMatrix.vue` / `AtlasProcess.vue`（增强视图，画像开启才挂载）
  - `NodeProfile.vue`（右栏档案）
  - mock：`atlas-data.ts` 按画像造两个示例（T5 金融合规、T7 前沿技术）供原型走查。
- 空间页知识全景按钮 → 改为跳 Atlas Tab；原弹窗移除或保留为"快速预览"。

## 6. 阶段拆分

- **M1（原型验证形态）**：Atlas Tab 页骨架 + 自绘 SVG 主图（类型着色/点击聚焦/子图下钻）+ 大纲树 + 节点档案 + 2 个画像示例 mock（T5 金融合规 / T7 前沿技术）→ GUI 走查"提纲挈领 + 下钻 + 类型差异"是否成立。原型阶段以构建+真机走查验证，不套 TDD（无后端逻辑）；后端 dl_* 本期不做。
- **M2**：时间线/矩阵/流程/三层结构视图按画像启用 + profile 可视化配置（建空间时选画像、调侧重）+ 抽取公共力导向组件供长文共用 + 与后端 dl_* 打通（届时上 TDD）。
- **M3**：跨领域节点复用、成果流自动更新（研究引擎接 Atlas）、导出（地图 PNG/PDF/交互页）。

## 7. 风险与边界

1. 图谱规模：>500 节点全览吃力 → 画像分组分区 + 大纲树兜底 + 懒展开（M1 示例控制规模）。
2. G6 体积/依赖：Electron 打包体积增加；需按需注册布局/交互，评估后定（备选 vis-network）。
3. "侧重"是软配置：画像默认值 + 用户可调，不把领域类型做成硬规则（避免误分类锁死展示）。
4. 法规/规范等时效内容：标注生效/版本/更新时间，与"研究更新流"（M3）联动。
5. mock 阶段不承诺后端字段即最终 schema，正式建模以 §4 为准再复核。
