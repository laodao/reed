### H1.（第 3 期）browser-render 渲染槽信号量死锁——独立脚本两种场景复现确认

- **位置**：`browser-render.ts:70-82`（acquire/release）+ `:176`（acquire 在节点超时定时器**之前** await）
- **实证**：场景 1（3 竞争者 + 2 槽）——A/B 均已 release 后 `activeRenders` 卡在 2，C **永久等待（硬死锁）**；场景 2（等待中 abort）——被 abort 唤醒的等待者消耗一次 release 却不取槽，**计数泄漏 1**（容量 2 降为 1）。
- **加重**：acquire 本身无超时且先于节点 300s 超时定时器——死锁时节点级保护无效，只有运行级看门狗（本批 toutiao 配 6h）能救；两个并发采集运行/并行分支即可触发。
- **修复（一行级）**：`releaseRenderSlot` 改 `activeRenders--; slotWaiters.shift()?.()`。

### H2.（第 2 期）Electron 端 net.fetch 不支持 `redirect:'manual'`——桌面端 30x 全挂且无降级（实验证实）

- **位置**：`http-fetch.ts:107-137`
- **实证**（仓库自带 Electron 44.5.1 + 本地 302 服务）：`net.fetch(url, {redirect:'manual'})` 抛 `Redirect was cancelled`，被统一 catch 吞成失败——**桌面端任何重定向 URL 的抓取/下载硬失败**；单测 stub 的是 undici 语义测不到。SSRF 侧 fail-closed 无绕过，但闸门在桌面端形同虚设。
- **修复**：manual 抛错时降级（net.request 逐跳过闸，或 follow+事后校验最终 URL）+ Electron 环境集成测试。

### H3.（第 2 期）tree 形态提示词-解析器错位——父子边永远不生成（新证据坐实）
