## 二、高危（8 项）

### H1. AI Hub：非 admin 用户可经 `aihub:login` 劫持全站 AI 出口（Web 多租户形态）

- **提交**：1a893515 / 66f0b4a0
- **位置**：`src/core/platform/aihub/aihub-auth.service.ts:174-199` + `ipc-router.ts:30-72`
- **问题**：ipc-router 已把 `provider-config:create/update` 收口 admin（防劫持全体用户 AI 流量），但非 admin 可调的 `aihub:login/register` 内部 `ensureAihubConfig` 会在**共享表**（useRawRepo，全局唯一一条）创建 ai-hub 行，`baseUrl = 调用者提供的 gatewayUrl + '/v1'`，`materializeJwt` 覆写 apiKey。攻击链：总开关开启后，任意注册用户抢先登录并把 gatewayUrl 指向自控伪网关 → 后续真实用户的 JWT 被物化进这条 config → 所有 LLM/图像/视频请求以 Bearer 头把 JWT 发往攻击者网关（**凭据收割 + prompt 全量泄露**）。且已存在 config 不更新 baseUrl，真实地址无法纠正。
- **建议**：`aihub:login/register/logout/token-expired` 在 Web 形态收口 admin，或 aihub 通道整体仅 Electron 启用。

### H2. AI Hub：任意登录用户可跨租户登出他人会话；多用户 JWT 互相覆盖（计费错乱）

- **位置**：`aihub.handler.ts:66-73,116-123` + `aihub-auth.service.ts:208-224,193-199`
- **问题**：`aihub:logout`/`aihub:token-expired` 对所有登录用户开放，执行全局 `disableAihubConfig`——用户 A 登出即破坏 B 正在使用的凭据（跨租户 DoS）。会话按 userId 隔离、物化 config 却全局唯一：多用户先后登录 JWT 互相覆盖，A 的调用以 B 的账号计费。根因同 H1：模块按 Electron 单用户设计，被通用透传到多租户。
