## 一、高危（4 项）

### H1. ZIP 素材包导出：打包侧源路径无 dataPath 收口——Web 多租户任意文件读取

- **提交**：98baf5e4（T10b）
- **位置**：`episode-zip-exporter.service.ts:166`（`sink.addFile(resolveAssetPath(entry.sourcePath!))`）、`:232-235`（frameJson 回退）
- **攻击链（静态逐环核实）**：① `ep:update-storyboard` 接受任意 `Partial<Storyboard>`，repository 将 `frameImage.filePath`/`videoPath` **原样落库**（simple-json 无路径白名单）；`ep:update-scene` 轻量路径同样可写 `narrationAudioPath` 等；② `resolveAssetPath` 对绝对路径/盘符/http(s) URL **原样返回**（存量兼容设计），相对路径可含 `../../`；③ export-zip 把该路径字节流打进 ZIP 返回，Web 端 `/assets/*` 路由恰好服务导出目录——**任一认证租户可读取服务器进程可读的任意文件**（`.env`、其他租户 data 目录、`/etc/passwd`）。比 MP4 通道（ffmpeg 重编码、非媒体必失败）是质变的原始字节外泄面。
- **建议**：打包侧强制收口——resolve 后校验 `path.resolve` 结果（含 `fs.realpath` 防 symlink）必须位于 `getDataPath()` 内，越界/URL 记 null 缺失；写侧对 frameImage.filePath 等做同样收口。

### H2. ArchiverZipSink 未监听 archiver 'error'——素材缺失/URL 回退时 Web 进程崩溃

- **提交**：98baf5e4
- **位置**：`episode-zip-exporter.service.ts:60-64`（只挂 warning）、`:68`
- **实证**（/tmp 独立探针复刻 sink 模式）：缺失文件 → `[uncaughtException] ENOENT`；`frameImage.url` 为 http URL 时同样 ENOENT（协议 URL 被当"绝对路径"放行后当本地文件打开）。图/视频源**无存在性预检**（音频有过滤）——存量数据中"frameImage 只有 url"即可触发。Web server 无 process 级兜底 → **整个服务进程崩溃（DoS）**；Electron 侧 IPC 永不返回、任务卡 running、半成品 zip 残留。
- **建议**：`archive.on('error')` 接住并让 finalize() reject + abort 清理；addFile 前对非 dataPath/URL 源跳过。

### H3. ep.keyframe 任务重试完全失效——payload 键名两套口径（实证）

- **提交**：2de97efc/98997250（T11 分派）× 4e6b9c63（T07 埋点）
- **位置**：`gen-task-dispatchers.ts:127-145`（要求 snake_case `session_id/storyboard_id`）vs `keyframe.handler.ts:498-504`（主入口**无 session_id**）vs `refine-session.service.ts:408-415`（camelCase 两键都对不上）
- **实证**：两种真实 payload 喂 `resubmitKeyframe` 均抛"payload 缺 session_id/storyboard_id"——**任何 failed 的关键帧任务在抽屉点重试必产生一条新 failed**；主入口的正确重试语义（重跑主链路）根本没实现。四个 resubmit 函数**零测试覆盖**（测试自身还用 camelCase payload）。
- **建议**：统一 payload 契约（refine 落 snake_case），主入口另注册独立提交器；补真实 payload 形状的表驱动单测。

### H4. EP 渲染域裸 Repository 越权面继续扩大（系统性既有模式 × T07/T08 新通道）

- **位置**：`refine-session.service.ts:174-179`、`scene-blocking.service.ts:168-170,221,235`（裸查 + **裸 update 写 camera_meta_json**）、`stage-compositor.service.ts:288-296`
- **问题**：租户隔离的真实载体是 BaseRepository.scoped，而 T07/T08 新服务对 storyboard/scene/project 链路全用裸 `ds.getRepository()`——Web 多租户下认证用户 A 可经 `ep:refine:open` **读用户 B 的分镜文案/资产卡/关键帧图路径**、经 `ep:director:save-camera` **裸 update 他人分镜的 camera_meta**。写回最终落库是 scoped 的，但读路径与 camera_meta 写路径没有。这是 keyframe-generation/storyboard 的既有模式（我的历期清单 ep 46 文件家族），非本批首创，但**每个新通道都在扩大暴露面**。对照正面样板：T09 narration.handler 是 scoped getById + 事务内显式 userId 的正确写法。
- **建议**：专项整改——EP 渲染域 storyboard/scene 查询改 scoped 或 handler 层补归属校验，至少 refine/director 新通道先补。
