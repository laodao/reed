## 高危

### H1.（新暴露）图像生成三通道 userId 客户端可控 + 正常调用落全租户共享行——租户隔离对本表实际失效

- **提交**：bf3f4006（M3 修复不彻底暴露）
- **位置**：`asset-image.handler.ts:200,309,386` + `main-image-generator.service.ts:60,286,508,620,743`
- **问题**：M3 修复只剥离了 `ep:asset:image:add` 一个入口。同服务的 `generate-main` / `add-main` / `character:generate-three-views` 三个通道仍把客户端 `userId` 原样透传到 `imageRepo.create({userId: input.userId ?? null})` 直写（不走 addImage 的 getCurrentUserId() 回退）：
  - 显式传他人 ID → 冒名写他人租户；
  - 不传或传 null（**Web 端正常调用即是如此**）→ 写 user_id=NULL 的全租户共享行（visibilityWhere 使所有租户可见）——比 add 通道更糟，`generate-main` 的正常 Web 调用也会落共享行，租户隔离在这些链路上实际失效。
  - 三通道均不在 ADMIN_CHANNELS，Web 通用透传直接可达；`generate-three-views` 的 handler 类型甚至没写 userId 字段，但运行时多余属性照样透传。
- **建议**：三个 handler 入口同样剥离 userId；服务侧四处 `input.userId ?? null` 改为 `getCurrentUserId()` 回退；补 Web 端三通道回归测试。**这是本轮最高优先级**。

### H2.（遗留未修，第二轮报告 H1）`ep:update-scene-dialogue` 仍无租户归属校验

- **提交**：1982b298 引入（rebase 后新哈希），本轮区间未修
- **位置**：`src/core/platform/episode-production/narrative/scene-dialogues.ts:21-42`
- **问题**：已人工复核确认——文件中仍无任何 userId/getById/scoped 逻辑，裸 `ds.query` 按 id 直查直改 `scene_dialogues`（该表有 user_id 列、`db.sceneDialogues` 作用域仓储现成可用）。Web 端任何登录用户可改写任意租户台词。
- **建议**：改用 `db.sceneDialogues.getById()`（scoped）做存在性+归属检查后再 UPDATE，handler 层加 text 长度上限。
