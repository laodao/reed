### 安全 / 多租户（191a6f38）

**M1. 限流可被路径变体绕过** — `src/web/server/auth/rate-limit.ts:42-43`
桶 key 为 `` `${ip}:${req.path}` ``，而 `req.path` 是原始路径。Express 大小写不敏感 + 非严格模式下 `/login`、`/login/`、`/Login`、`/%6Cogin` 均命中同一路由却各自成桶，每个变体 20 次/15 分钟，登录/注册限流实质被击穿。建议改用 `req.route?.path`（路由模板）或纯按 IP 限流。

**M2. 反代部署下限流失效或自我 DoS** — `src/web/server/index.ts`（全文无 `trust proxy` 设置）+ `rate-limit.ts:42`
未设 `app.set('trust proxy', ...)`：nginx 等反代后 `req.ip` 恒为代理 IP，全体用户共享 10 注册/小时、20 登录/15 分钟的桶——单 IP 即可打满造成全员无法登录/注册（自我 DoS）。建议按部署形态配置并文档化；多实例部署换 Redis。

**M3. `addImage` 可冒名写入他人租户** — `src/core/platform/episode-production/assets/services/asset-image.service.ts:103`（入口 `asset-image.handler.ts:120-129`）
`userId: input.userId !== undefined ? input.userId : (getCurrentUserId() ?? null)` 只做默认值不做白名单：Web 客户端显式传他人 ID → 写入他人租户（数据污染）；传 `null` → 写入对全体租户可见的共享行（跨租户内容注入，他人资产选图器会看到种植的图）。提交宣称「预置图 userId:null 共享语义保留」，但该语义对普通客户端同样放行。建议 HTTP 通道入口剥离 `userId` 字段，预置 seed 场景走内部标记。

**M4. 附件上传零类型校验 → 存储型 XSS** — `src/core/packs/diary/services/diary-attachment.service.ts:52-118`（伺服侧 `src/web/server/api/assets-router.ts:42`）
