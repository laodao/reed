## 0. 通用工程约定（所有任务共同遵守）

### 0.1 迁移纪律

- 新表/新列一律在 `src/core/database/migrations/` 新增独立迁移文件（文件名 `add-<对象>.ts`，参照 `add-storyboard-background-ref.ts`、`add-asset-image-variant-category-and-migrate.ts` 模式），纳入现有自动执行机制。
- 迁移必须 SQLite/PostgreSQL 双方言可跑；参照 `tests/unit/migrations/expand-episode-status.spec.ts` 写迁移单测。
- 新表必带 `user_id varchar null` 多租户隔离列（Web 端必填、PC 端可空），仓储查询遵循 `asset-image.service.ts` 的读规则（读 = 自己的行 OR user_id IS NULL 的共享行）。

### 0.2 IPC 与分层纪律

- EP 后端入口：`src/core/packs/episode-production/handlers/` 下新增或扩展 handler 文件，在 `handlers/index.ts` 的 `registerEpisodeProductionHandlers()` 中注册；channel 一律 `ep:` 前缀（包 manifest 已声明 `ipcChannelPrefixes: ['ep:']`）。
- 业务逻辑放平台层 `src/core/platform/episode-production/` 对应子域（assets / narrative / render / compose / workflow / services），handler 只做参数校验与转发——遵循现有五层管道。
- Web 端同构：新增 channel 前缀需确认 `src/web/server/api/register-channels.ts` 的包激活覆盖（`ep:` 前缀已整包覆盖，通常无需改动；上传类走 `upload-router.ts`）。

### 0.3 前端约定

- 组件放 `src/renderer/src/components/episode-production/<子域>/`；跨 stage 共享的放 `shared/`。
- 状态放 `src/renderer/src/stores/episode-production/` 对应 store；弹窗类功能无需新路由。
- PC/Web 双端：涉及 WebGL 的组件参照 `PanoramaViewer.vue` 的 `preserveDrawingBuffer` 先例；涉及文件落盘的走 IPC 由主进程写（Web 端经 web server）。

### 0.4 测试设施

| 层级 | 设施 | 参照 |
|---|---|---|
| 单元/迁移 | `npm run test:unit`（vitest，sqlite/pg 双跑） | `tests/unit/migrations/*.spec.ts` |
| 服务集成 | `tests/integration/episode-production/` | `hyp3-few-shot-test.ts` |
| E2E（Web） | playwright `npm run test:e2e:web` | `tests/e2e/web/10-episode-production.spec.ts`、`16-episode-production-mp4-e2e.spec.ts` |
| 真机全链路 | `scripts/e2e-real-episode-video*.cjs` | 现有真机脚本 |
| 质量度量 | `quality-check.service.ts` 四指标 | 关键帧 refs 覆盖率/字幕↔对白/时长偏差/VLM 相似度 |

### 0.5 验收总纲（每个任务的 AC 之外共同保证）

1. 现有 E2E（`10-episode-production.spec.ts`、`16-episode-production-mp4-e2e.spec.ts`）不回归。

3. 涉及生成质量的改动（任务 5/6/7/8）需在真机脚本跑通至少一个完整单集链路。

## 任务 5：风格模板库（Q-A3，第二批，6–9 人日，较原估下修）

> 下修原因（2026-10-13 核查）：`platform/episode-production/prompts/style-resolver.ts` 已实现风格单一来源（提示词优化 §4.4）——`resolveStyle(ctx)` 统一产出 `prefix / suffix / projectStyle / negative`，消费点已收口，**无需再改造三处注入点**，只需扩展 preset 来源与项目应用层。

### 5.1 目标

用户可创建/保存/应用自定义风格模板（风格指令 + 质量后缀 + **避免指令** + 风格 Tag），支持上传参考图让 VLM 反推风格参数；应用后全链路（资产图/关键帧/缩略图）风格统一。

### 5.2 功能设计

**数据模型**：新表 `ep_style_template`：

```
id PK / user_id / name / description
style_prefix text      -- 主体风格前缀（管形象）
quality_suffix text    -- 质量后缀（管质感）
negative_prompt text   -- 避免指令
style_tags json        -- 标签数组
ref_image_path text?   -- 创建时的参考图（仅溯源展示）
created_at / updated_at
```

内置 20 风格锚点（`style-presets.ts`）与 `PRESET_STYLES`（`keyframe-prompt-builder.ts:64`，即 `StyleConfig` 同形）保持代码态不动；用户模板入库。

**核心机制——接入 style-resolver 单一来源**：
- `resolveStyle(ctx)` 的 preset 查找扩展为「内置 PRESET_STYLES + 用户模板」合并：`PromptContext` 增加可选 `styleTemplateId`，resolver 经注入的仓储查模板（查不到回退内置，保证健壮）。
- **应用到项目** = 把模板三字段**快照**写入 `config.stylePrompt`（projectStyle 通道，已有）+ `config.styleNegative`（新键）+ `config.styleTemplateId`（溯源）。选快照而非仅存 ID：模板删除不影响已应用项目。resolver 的 `negative` 段合并优先级保持：风格预设 negative + 时代档案 negativeExtra + **config.styleNegative**。
- **参考图反推**：新 prompt 文件 `prompts/style-inference-prompt.ts`——输入参考图，VLM 输出 `{stylePrefix, qualitySuffix, negativePrompt, styleTags}` 纯 JSON（遵循 `episode-production-system-prompts.md` 的提示词规范：正向表述、明确模板、3 个 few-shot）。复用现有 VLM 通道。

**UI**：项目设置新增"风格"分区——左侧模板列表（内置只读组 + 我的模板组），右侧编辑器（名称/三个文本域/标签/参考图缩略）；操作：新建（手动填写 或 上传参考图→反推预填→人工确认）、编辑、删除、**应用到项目**。应用后项目设置显示当前风格快照。

| 新增 | `database/migrations/add-ep-style-template.ts` | 建表 |

### 5.4 测试与验收

## 任务 6：阶段检查清单产品化（Q-A4，第二批，5–8 人日）

### 6.1 目标

把"每阶段检查项 + 通过标准"做成显式 UI：分镜/制作阶段每卡质检徽标，stage 出口检查清单卡，不合格项一键跳转修复（重生/挑图）。

### 6.2 功能设计

**后端**：`quality-check.service.ts` 扩展 `checkStoryboard(storyboardId)`：

```
items: [{
  key: 'keyframe_exists' | 'keyframe_refs_covered' | 'subtitle_dialogue_match'
     | 'video_ready' | 'duration_deviation' | 'face_consistency' | 'text_artifact',
  label: string, pass: boolean, detail?: string, severity: 'error'|'warn'
}]
```

其中前五项直接复用现有四指标实现（拆到单分镜粒度）；`face_consistency` 复用 VLM 相似度（关键帧 vs 角色主图/身份图，阈值可配置，默认 0.75）；`text_artifact` 用 VLM 问"画面是否含文字/水印"（可选开关，控制成本——仅对"拟入选合成"的分镜跑）。
新增 IPC：`ep:quality:check-storyboard`、`ep:quality:check-episode {episodeId}`（批量，返回通过率）。

**前端**：

## 任务 7：关键镜头精修工作台 MVP（Q-A5，第三批，8–12 人日）

### 7.1 目标

单镜头深度精修：载入分镜完整上下文 → 同参考并行生成多候选 → 并排比较 → 明确写回。候选不污染正式资产（"候选—写回"安全边界，与任务 8 共用该组件）。

### 7.2 功能设计

**入口**：制作 stage 关键帧面板与分镜卡新增"🎨 精修"按钮 → 打开全屏弹窗 `RefineWorkbenchDialog.vue`。

**三栏布局**：
- 左栏·上下文：分镜文案（台词/画面描述，只读可复制）、出场角色/场景/道具卡（点击经 `AssetGalleryPicker` 增删参考）、当前正式关键帧与挑图 override 展示。

**生成**：并行调用关键帧生成服务，`parallelism` 受既有 provider 限流约束；参考图编排 = 用户在左栏选定的资产参考（主图/派生图）+ 风格快照，经 `keyframe-prompt-builder` 组装（与正式链路同一 prompt 通道，保证"精修所见即正式所得"）。

**MVP 范围裁剪**：不含局部重绘/遮罩（图像 provider 无 mask 能力，二期经 ComfyUI inpaint 补）；不含视频候选（仅关键帧）。

## 任务 8：导演工作台 L1 MVP（Q-S1，第三批，15–20 人日，质量主线主攻）

### 8.1 目标

可取景的代理片场：在场景空间内拖拽摆放人物/道具/占位 → 调机位 → 导出"导演控制图"→ 写回分镜背景参考 → 关键帧生成继承构图 → 图生视频继承首帧。附带摆位数据自动生成构图描述（文字+控制图双通道约束）。

### 8.2 功能设计

**数据模型**：

```
新表 ep_scene_blockings（迁移 add-ep-scene-blockings）：
  id PK / user_id / location_binding_id
  layout_json: [{ kind: 'character'|'item'|'placeholder',
                  assetId?, refImageId?,        // character/item 必填
                  x: number, y: number,          // 米，地面平面坐标，原点=场景中心
                  rotationDeg: number, scale: number, label?: string }]
  camera_defaults_json: { fovDeg: number, heightM: number, pitchDeg: number,
                          focalPreset?: string,  // 对齐 lens-presets 命名
                          yawDeg: number }
  updated_at
（一地点一套摆位；机位微调 per-shot，放分镜侧）
```

`storyboards` 表加列 `camera_meta_json`（迁移 `add-storyboard-camera-meta`）：单分镜机位覆写 + 控制图生成参数快照。控制图本体落文件后以 `image_asset`（category=`context`，label=`director_control`）登记，`backgroundRefImageId` 指向它——写回槽位复用任务已验证的 `storyboard.service.setBackgroundRefImageId`。

**three.js 场景**（`DirectorStageDialog.vue`，全屏弹窗）：
- 场景构成：背景卡（场景主图作为远处竖立平面）、地面网格（1m 网格 + floor_plan 叠加开关——俯视图与平面布局图对齐）、实体卡：character 用其视角派生图（front/three-quarter-left/right/side）作为贴图的竖立平面卡（billboard，按"实体朝向 vs 相机方位角"自动选最近视角贴图），item 用参考图卡，placeholder 用半透明人形剪影贴图；`three-spritetext` 名称标签。
- 双视图：同一 Scene 双相机——俯视 OrthographicCamera（摆位编辑主视图，可叠 floor_plan）+ 透视 PerspectiveCamera（取景预览，参数即导出机位）；分屏或页签切换。
- 交互：俯视图 pointer 拖拽移动（raycast 地面）、旋转滑杆、缩放、删除；透视视图拖拽调 yaw/pitch、滚轮/滑杆调 FOV 与高度。
- 导出：固定 1280×720 渲染目标，`preserveDrawingBuffer: true`（PanoramaViewer 同款），`captureCanvas()` 出 base64。

**写回与消费链路**（价值兑现的关键，附录 A5）：
1. 新 handler `ep:director:export-control-image { storyboardId, imageBase64 }`：落文件 → 登记 `image_asset(category=context)` → `setBackgroundRefImageId` → 返回 { imageId, path }。
2. **分槽注入**（控制图≠风格参考）：关键帧参考板组装处，`backgroundRefImageId` 对应图进入独立"背景/构图"槽；`keyframe-prompt-builder` 对该槽固定插入引导语"以下为构图与站位参考（layout control image），仅约束构图/站位/景别，忽略其渲染风格与质感"——与风格通道（任务 5 的 resolveStyle）物理分离。
3. **构图提示词生成器** `prompts/director-composition-prompt.ts`：`layout_json + camera_meta` → 中文构图描述（"中景：女主位于画面左侧背对镜头，男主右侧面向镜头；镜头俯角约15°，焦段约35mm"）。景别由"主体高度/画面高度比"映射（远景/全景/中景/近景/特写五档），左右由 x 坐标符号映射，朝向由 rotation−yaw 差映射（面向/背对/侧对镜头）。注入点：关键帧画面描述为空或用户勾选"辅助构图描述"时，追加到画面描述尾部（不覆盖用户文案）。

**入口**：分镜卡与关键帧面板"🎬 导演取景"按钮；地点资产卡"编辑摆位"入口（先摆位后取景两段式，摆位属地点、机位属分镜）。

### 11.3 功能设计

**接口契约（任务 7/8 开工前冻结）** `src/core/platform/services/gen-task-registry.service.ts`：

```ts
export interface GenTaskRecord {
  id: string
  userId: string | null
  taskType: string            // 'ep.keyframe' | 'ep.video' | 'ep.tts' | 'ep.compose' | 'chat.image' | ...
  entityType: string          // 'storyboard' | 'episode' | ...
  entityId: string
  projectId?: string
  episodeId?: string
  status: 'running' | 'succeeded' | 'failed' | 'canceled'
  progress?: number           // 0-1
  message?: string
  error?: string
  payloadJson?: string        // 重试所需参数快照
  resultRef?: string          // 产物定位（如 videoPath/imageId）
  createdAt: Date
  updatedAt: Date
}
// 服务方法：create / update(id, patch) / succeed(id, resultRef) / fail(id, error)
// cancel(id) —— 语义：尽力取消（按 taskType 分派到域内取消实现；不可取消的返回 unsupported）
// list(query) / retry(id)（按 payloadJson 重新入队到对应域 handler）
// 事件：emit('gen-task-updated', record) → IPC 推送 `gen-task:updated`
```

**数据**：新表 `gen_tasks`（迁移 `add-gen-tasks`，平台级非 ep 前缀；索引 user_id+status、entity）。

**接入方式**：域内生成入口（关键帧、视频 `video.handler.ts:317` 后台任务、TTS、合成）在起任务处 `registry.create`，进度/终态处 update/succeed/fail；**失败必带可读 message 与 payloadJson**。取消按钮按 taskType 分派：comfyui 走中断、云视频 API 有 cancel 则调、无则仅标记并提示"供应商侧将继续扣费，请知悉"。

**前端**：
- 新全局 store `src/renderer/src/stores/gen-tasks.ts`（订阅 `gen-task:updated`，内存 + 拉取分页）。
- 新全局组件 `TaskDrawer.vue`（顶栏图标入口，与通知铃铛并列）：运行中任务显示进度条与当前步骤；终态可展开错误；每条带"跳转"（按 entityType 路由到 `/:projectId/studio/:episodeId` 对应 tab）与"重试"（failed）；底部"清除已完成"。
- 终态推送通知中心（成功低打扰可折叠、失败高优先）。

**EP 前置接入（接口先行的落地）**：任务 7/8 实现时，精修批量生成与导演台控制图导出按本契约埋点（此时 registry 可先以内存实现跑通接口，任务中心立项时切换持久化实现——**接口不变，实现可换**，这是后置不返工的保证）。
