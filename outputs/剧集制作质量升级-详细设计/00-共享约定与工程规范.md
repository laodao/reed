# 00 · 共享约定与工程规范

> 所有任务 subagent 的必读文档。本文约定跨任务的工程纪律、测试设施与验收基线；各任务文档只写本任务特有内容。

---

## 1. 迁移纪律

- 新表/新列一律在 `src/core/database/migrations/` 新增独立迁移文件（命名 `add-<对象>.ts`，参照 `add-storyboard-background-ref.ts`、`add-asset-image-variant-category-and-migrate.ts`），纳入现有自动执行机制。
- 迁移必须 SQLite/PostgreSQL 双方言可跑；参照 `tests/unit/migrations/expand-episode-status.spec.ts` 写迁移单测。
- 新表必带 `user_id varchar null` 多租户隔离列（Web 端必填、PC 端可空）；仓储查询遵循 `asset-image.service.ts` 读规则：读 = 自己的行 OR `user_id IS NULL` 的共享行。

## 2. IPC 与分层纪律

- EP 后端入口：`src/core/packs/episode-production/handlers/` 新增/扩展 handler，在 `handlers/index.ts` 的 `registerEpisodeProductionHandlers()` 注册；channel 一律 `ep:` 前缀（包 manifest 已声明 `ipcChannelPrefixes: ['ep:']`）。
- 业务逻辑放平台层 `src/core/platform/episode-production/` 对应子域（assets / narrative / render / compose / workflow / services / prompts），handler 只做参数校验与转发。
- Web 端同构：`ep:` 前缀已被 `src/web/server/api/register-channels.ts` 整包覆盖，通常无需改动；上传类走 `upload-router.ts`。**平台级新前缀**（如任务 11 的 `gen-task:`）必须同步 register-channels。

## 3. 前端约定

- 组件放 `src/renderer/src/components/episode-production/<子域>/`，跨 stage 共享放 `shared/`；状态放 `src/renderer/src/stores/episode-production/`；弹窗类功能无需新路由。
- WebGL 组件参照 `shared/PanoramaViewer.vue`（`preserveDrawingBuffer: true` + `captureCanvas()` 先例）。
- 文件落盘一律经 IPC 由主进程完成（Web 端经 web server），渲染进程不直接写盘。

## 7. 质量主线 A/B 度量（任务 5/6/7/8 合并后的专项验收，W5 执行）

| 度量 | 方法 | 通过标准 |
|---|---|---|
| 控制图对构图的提升 | 同组分镜开/关导演台控制图各生成 1 组 | `quality-check` VLM 相似度组间提升；人工站位/左右/景别一致率记录基线对比 |
| 风格一致性 | 应用自定义风格模板前后各 1 集 | 跨镜头 VLM 风格相似度方差下降 |
| 坏帧拦截 | 检查清单上线前后各 1 集真机全流程 | 合成阶段才发现的坏镜数下降 |
| 资产防回归 | 主图替换影响范围提示 | 误覆盖事故 0（提示弹出率 100%） |

度量报告写入 `docs/` 并回填 README 状态表。

## 8. 提示词工程规范（涉及新 prompt 的任务适用：T02/T05/T07/T08/T09）

遵循 `docs/episode-production-system-prompts.md`：结构分离（指令与输入分区）、关键约束置首尾、输出给明确模板 + 3 个 few-shot、正向表述（不说"不要 X"说"要做 Y"）、量化约束（不说"简短"说"18–28 字"）、枚举值与既有 prompt 对齐、binding ID 强约束。新 prompt 文件放 `platform/episode-production/prompts/`，并回填 `docs/episode-production-system-prompts.md` 索引。
