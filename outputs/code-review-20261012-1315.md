## 二、高危（3 项新增 + 2 项上期挂起确认）

### H1. tree 形态提示词-解析器错位——层级隶属边永不生成

- **提交**：8524f02c
- **位置**：`prompts/index.ts:846`（提示模型"用 **attrs.parent** 标注直接上级"）vs `system-aggregate.service.ts:363,369`（parser 只读元素**顶层** `parent`）；示例 JSON 两处都不展示
- **问题**：模型按提示词把 parent 写进 attrs 时 parser 读不到 → **tree 形态的 sublevel-of 隶属边全跳过**，退化为 catalog；attrs.parent 仅作普通属性行。`system-aggregate.spec` 全文无一处 parent/tree 用例——四形态之一零守卫。
- **建议**：parser 取 `el.parent ?? el.attrs.parent`（数据可得），示例补顶层 parent，补 tree 用例。一行级修复。

### H2. 向量回填窗口饥饿——大库老论断永远补不到

- **提交**：81c71a78
- **位置**：`digest-orchestrator.service.ts:1434-1436`（listWorking = findByKb `limit` 2000）+ `kb-atom.repository.ts:170`（createdAt DESC）
- **问题**：回填每轮只看**最新 2000 条**；missing > 2000 的库（正是本修复要救的 7847 条真机场景）补完窗口内就 `missing.length === 0` 直接 return——**窗口外的老论断永远不进回填视野**。叠加 24h 周期 + Electron-only 装配（Web 租户零回填），"自愈"承诺只对最浅一层成立。
- **建议**：listWorking 按 createdAt ASC 扫描或游标推进，或向量侧反查缺失集。

### H3.（实证回归）net.fetch 不支持 `redirect:'manual'`——桌面端重定向抓取全失败，逐跳 SSRF 闸门沦为死代码

- **提交**：eced0157
- **位置**：`http-fetch.ts:115-121`、`http-politeness.ts:125`
- **问题**（用仓库自带 Electron 44.5.1 + 本地 302 服务实证）：`net.fetch(url, {redirect:'manual'})` 直接 **throw "Redirect was cancelled"**——桌面主进程里 manual 逐跳循环对任何 30x 目标抛错 → http-request 下载、web-extract 正文抓取、agent http_get、配图下载（CDN 防盗链图链常见 30x）全部失败且被 skip 静默吞掉。**单测全绿是因为 spec 用 stubGlobal 模拟 fetch（undici 语义）——测试与生产走两套语义**。SSRF 侧 fail-closed 无绕过，但闸门在桌面端等于不存在（请求先死了）。
- **建议**：桌面端 manual 改 `net.request` 自管逐跳；或探测 manual 支持降级 follow 并声明逐跳校验失效；补 Electron 环境集成测试堵住环境分裂。
