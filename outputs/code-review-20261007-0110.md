## 高危（4 项，全部为功能死链/承诺落空类）

### H1.（严重）自动化链路的跨书归并永远不合并——embeddingConfig 硬编码 null 致嵌入恒失败

- **提交**：fe11439b
- **位置**：`src/core/platform/services/kb-brain/automation.service.ts:166` + `smelt-common.ts:defaultBrainEmbed` + `knowledge-base.service.ts:934`
- **问题**：automation 的 corpus 步骤默认实现写死 `new KbCorpusMergeService({ modelOverride }).run(kbId, null)`——第二参 embeddingConfig 硬编码 `null`。`defaultBrainEmbed` 收到 null 走 `{}` → `getEmbeddingVectors` 因无 providerConfigId 直接 throw → catch 成 null → corpus-merge 按「嵌入不可用不盲并」跳过。**即使 KB 行配置了 embeddingConfig，自动化路径也拿不到**——P3 核心功能在唯一的生产触发路径上是死链（对比：smelt-pipeline 的 `lookupKbForSmelt` 正确取 kb 行）。测试全部注入 embed，掩盖了此问题。
- **建议**：corpus 默认实现仿照 `lookupKbForSmelt` 取 `kb.embeddingConfig` 传入，或让 `run` 只收 kbId 自查。

### H2. 质量门「自动恢复」路径失效——published 优先取样使待审卡饿死

- **提交**：fe11439b
- **位置**：`src/core/platform/services/kb-brain/qa-sampler.service.ts:93-97`
- **问题**：抽检取样是 `[...pub.rows, ...prop.rows].filter(smelt).slice(0, 5)`——published 恒排前。而降级到 review 的前提恰是已有 ≥3-5 张已发布差卡：① 此后新卡只进 proposed，published 第一页（createdAt DESC）被老差卡占住；② 每轮反复给**同一批老差卡**记 0 分；③ 待审好卡几乎进不了样本。净效果：滚动均分被老差卡钉死在阈值下，「恢复 ≥1.0 自动回直发」实际不可达，且每轮冶炼白烧 5 次 judge 重复评判同批卡。测试恰好只造 4 张 published（<5 席）让第 5 席留给待审卡，通过但掩盖了饥饿。
- **建议**：按 noteId 去重取样（只抽未评过或评分最旧的卡），或 proposed/published 固定配额，或对已评分卡设冷却。

### H3. 成卡门槛与簇容量上限数学冲突——大库（>1500 事件/桶）套路产线静默停产

- **提交**：fe11439b
- **位置**：`src/core/platform/services/kb-brain/pattern-induct.service.ts:103-111` + `smelt-common.ts:24-29,45`
- **问题**：`cardThreshold = max(8, ceil(bucket × 2%))`，而聚类 `maxPerCluster = 30`。某场面桶事件数 >1500 时 threshold ≥31 > 30，**任何簇都不可能达到成卡门槛** → 全部跳过，零 LLM 调用零产出，只留一行日志。事件取材上限 5000（threshold 可达 100），多书库常见场面很容易超 1500。讽刺的是嵌入失败降级「整桶一簇」反而能过门——聚类越成功越产不出卡，恰是冶炼层目标场景（大库）静默失效。
- **建议**：`maxPerCluster` 取 `max(SMELT_CLUSTER_MAX, threshold)` 或对 threshold 封顶；补 >1500 桶回归测试。

### H4. 「空包回退平铺」未真正生效——新库拿到只有标题头的"知识包"

- **提交**：fe11439b
- **位置**：`src/core/platform/services/kb-brain/brain-pack.service.ts:153-155, 327-343` + `kb-brain-tools.ts:59-64` + `writing-brain-tool.ts:132-137`
- **问题**：`renderPack` 恒以 `[header]` 起始，永不返回空串 → `buildPack` 在 ok:true 时 pack 恒非空（至少一行标题头）。后果：`kb-brain-tools.ts:62` 的 `if (packed.ok && !packed.pack)` 是**死代码**，「大脑里还没有成品知识」提示永不触发；新库无冶炼产物时（提交明示的回退场景）两个工具主路返回只有标题头的知识包，**平铺检索回退不执行**，模型拿到无信息文本。即便死分支触发，也只返回「试试平铺检索」文案而非真正执行。已用最小复现脚本验证。
- **建议**：`buildPack` 对 sections 全空返回 `ok:false`（或空 pack+标记），让既有回退路径接管；或 `renderPack` 空段返回 `''`。
